# Reactor Web 客户端 部署说明（V1.0.0）

> 适用目标：**内网 Linux 服务器**（x86_64 / amd64），Docker 环境。
> 交付内容：1 个 Docker 镜像 + 编排配置 + 本说明。
> 用途：让 **Win7 电脑通过浏览器**使用 Reactor；Win10 及以上仍推荐桌面客户端（功能更全）。

---

## 0. 这个镜像是什么、不是什么

**包含**：Web 前端静态产物（已按 Chromium 109 降级，兼容 Win7 浏览器）、HTTP/WS 服务端、
Agent 运行时（zcode.cjs，由容器内 Node 24 执行）。

**不包含**：身份服务与模型网关。登录、账号、模型能力仍需既有的
`Reactor 服务端` 部署（`reactor-desktop-server` 镜像）。本镜像只提供 Web 入口。

**服务端渲染与文件操作的落点是容器内的 `/data/workspace`**，不是用户本机。

---

## 1. 环境要求

| 项 | 要求 |
| --- | --- |
| 操作系统 | Linux x86_64 |
| Docker | 20.10+（Compose v2） |
| 内存 | 建议 ≥ 4 GB，并按并发会话追加（每个会话一个 agent 进程） |
| 磁盘 | 镜像约 480 MB，工作区按使用量增长 |
| 端口 | 3030（浏览器访问） |
| 客户端浏览器 | **Chrome/Edge 109 及以上**（Win7 上限即 109） |

> Chrome 109 是最后一个支持 Win7 的版本。企业内网需提前准备离线安装包并纳入软件分发。

## 2. 部署步骤

### 2.1 导入镜像

```bash
gunzip -c images/reactor-web-v1.0.8.tar.gz | docker load
docker images | grep reactor-web      # 应看到 reactor-web  v1.0.8
```

### 2.2 配置令牌

```bash
cd config
cp .env.example .env
# 生成令牌并填入 .env 的 REACTOR_WEB_TOKEN
openssl rand -hex 24
```

> ⚠ **不设令牌时服务端不校验任何身份**：任何能访问 3030 端口的人都会获得
> `/data/workspace` 的读写与容器内 shell 权限。生产环境必须设置。

### 2.3 启动

```bash
docker compose up -d
docker compose ps                 # 状态应为 healthy
docker compose logs -f --tail=20
```

### 2.4 验证

```bash
curl -s http://127.0.0.1:3030/api/server-info     # 应返回 JSON，含 workspaces
```

浏览器打开（首次带令牌换 cookie）：

```
http://<服务器IP>:3030/?token=<REACTOR_WEB_TOKEN>
```

登录页出现即部署成功。之后可直接用 `http://<服务器IP>:3030/` 访问（cookie 已写入）。

### 2.4.1 HTTPS 同源反代（正式部署推荐）

直接暴露 3030 有三个问题：登录走 CORS 白名单、identity 需要可达、浏览器高级能力
（大文件、通知、PWA）要求安全上下文。用 nginx 同源反代一次解决：

```bash
cd config
bash gen-self-signed.sh <服务器IP>        # 生成自签证书（正式环境替换企业 CA 证书）
docker compose -f compose.yml -f compose.https.yml up -d
# 注意 compose.https.yml 是 override：nginx 占 80/443，reactor-web 的 3030 对外映射收回
```

访问 `https://<服务器IP>/`（自签证书首次会提示不受信任，内网试点可继续；
要消除提示需导入根证书或换企业 CA 证书）。

反代路由：`/auth/ /me/ /depts/ /users /v1/ /desktop/ /download /api/v1/` → identity:8791；
`/ws`（WebSocket）、`/api/`、`/` → reactor-web:3030。管理台 8792 不经此代理。

> 启用 HTTPS 后，`REACTOR_ALLOWED_ORIGINS` 可保持原值（同源请求不再触发 CORS），
> 但若仍有客户端直连 3030 的 http 源，保留原配置即可。
> ⚠ dev 编排（server/packages/server/docker）的服务名是 `web`，启用时需把
> compose.https.yml 里的 `reactor-web` 改成 `web`。

### 2.4.2 模型地址与容器网络（上线前必查）

Web 端的 agent 跑在容器里，**它看到的 `127.0.0.1` 是容器自己**。管理台里给模型供应商配的
「直连地址」（`ai_providers.direct_base_url`）如果写成 `http://127.0.0.1:xxxx`，容器内必然
连不上，表现为：

- 页面停在「工作中 … / 重新连接中 N/10」，没有任何回复；
- agent 日志（容器内 `/root/.reactor/cli/log/zcode-*.jsonl`）反复出现
  `model.request.failed`，`baseURL` 是 `http://127.0.0.1:xxxx/v1`。

正确做法（任选其一）：

1. **清空 `direct_base_url`**，让模型走网关（推荐，网关是容器网络内的服务名，天然可达）；
2. 改成容器可达的地址：
   - 同 compose 网络内的服务名，如 `http://model-proxy:8080/v1`；
   - 宿主上的服务，用 `http://host.docker.internal:3425/v1`。**Linux 需额外给容器加**
     `extra_hosts: ["host.docker.internal:host-gateway"]`（Docker Desktop 自带该映射，
     Linux 默认没有）。交付 compose 已预留该字段，按需取消注释。

验证命令（在 web 容器内执行）：

```bash
docker exec reactor-desktop-web node -e "fetch('http://host.docker.internal:3425/v1/models')
  .then(r=>console.log('可达', r.status)).catch(e=>console.log('不可达', e.cause?.code))"
```


### 2.4.3 `REACTOR_IDENTITY_URL` 必须是「web 容器可达」的地址（2026-10-31 实测勘误）

登录请求的真实链路是：浏览器经 `/ws` RPC 调到 **web 容器里的服务端**，由它
（Node/undici）向 `REACTOR_IDENTITY_URL` 转发 `/auth/login`。`identityUrl` 虽然也会
经 `/api/server-info` 下发给浏览器（登录页据此锁定并隐藏地址框），但那只是展示，
**真正发请求的是容器**。所以这一项必须填容器可达的地址：

```yaml
REACTOR_IDENTITY_URL: http://identity:8791     # ✓ 与 identity 同一 compose 网络（默认值，推荐）
REACTOR_IDENTITY_URL: http://192.168.1.10:8791 # ✓ 宿主机/远端 IP（容器可达即可）
REACTOR_IDENTITY_URL: http://127.0.0.1:8791    # ✗ 容器里的 127.0.0.1 是它自己！
```

填 `127.0.0.1:8791` 的表现：登录页停在「fetch failed」，浏览器网络面板里**没有任何
请求**（请求根本不是浏览器发的）；报错文案 `fetch failed` 是 Node undici 的错误，
不是浏览器原生的 "Failed to fetch" —— 看到小写 f 就该想到是服务端转发失败。

这个设计的好处：浏览器所在机器**不需要能访问 identity**，identity 也不必对外暴露端口；
`REACTOR_ALLOWED_ORIGINS` 的 CORS 放行对登录这条链不是必需的（OAuth 直连流程才用得上）。

> 历史坑（2026-10-31）：排障时误把该值当成「浏览器可达地址」改成 `127.0.0.1:8791`
> 并锁死隐藏了地址框，导致所有登录必挂。排查入口：页面里 `fetch()` 探测 identity 通畅、
> 但点登录抓不到任何浏览器请求 → 请求在服务端，查容器到 identity 的连通性：
>
> ```bash
> docker exec reactor-desktop-web node -e \
>   "fetch('http://identity:8791/api/health').then(r=>console.log('可达',r.status)).catch(e=>console.log('不可达',e.cause?.code??e))"
> ```

### 2.5 并入服务器部署（推荐）

若服务器上已有 `Reactor 服务端` 的 compose 栈（identity / gateway / portal / pg / ldap），
应当把 web 作为**同一栈内的一个服务**，而不是单独 `docker run`。好处：同网络、
同项目、同一次 `docker compose up -d` 起停，且 agent 可以用服务名访问网关。

在既有的 `compose.yml` 里加：

```yaml
  web:
    image: reactor-web:v1.0.8
    container_name: reactor-desktop-web
    environment:
      ZCODE_SERVER_AUTH_TOKEN: ${REACTOR_WEB_TOKEN:-}
      ZCODE_SERVER_WORKSPACE: /data/workspace
      ZCODE_DATA_BASE_DIR: /data
    ports:
      - "3030:3030"
    volumes:
      - web-data:/data
    depends_on:
      - identity
    restart: unless-stopped
```

并在 `volumes:` 下补 `web-data:`（普通卷，与 pg/ldap 完全独立）。

> ⚠ agent 在 web 容器内运行，访问模型网关必须用**服务名** `gateway:8790`，
> 填 `127.0.0.1:8790` 会打到容器自己身上。

仓库内的开发编排已按此方式接入：`server/packages/server/docker/compose.yml`。

## 3. 已知限制（当前版本）

| 限制 | 影响 | 说明 |
| --- | --- | --- |
| **所有 Web 用户共用同一个工作区** | 用户之间可见彼此文件 | 当前为单工作区模型，仅适合小范围试点；多人正式使用前必须完成每用户隔离 |
| **附件上传不可用** | 不能拖拽/选择本地文件进对话 | 依赖 `getPathForFile`，Web 端尚无上传通道 |
| 无内嵌浏览器 / 电脑操作（CUA） | 浏览器自动化类任务不可用 | 需要服务端图形会话，不在 Web 方案内 |
| 无法打开本机编辑器/文件管理器 | 只能在线查看 | 浏览器沙箱限制 |
| 远程工作区（SSH/Docker）未接通 | Web 端不能连其他机器 | 后端接口已具备，前端未接线 |

## 4. 兼容性说明

Web 产物已针对 **Chromium 109** 验证：

- `oklch()` / `color-mix()` 在构建期降级为 sRGB 静态值，并保留 `@supports` 增强分支，
  现代浏览器仍获得广色域表现（**不是整体降级**）。
- `Array.prototype.toSorted`（Chrome 110+）由入口垫片补齐，仅 Web 产物包含。
- 真机验证：Chromium 109.0.5414.46 下零报错、界面完整；与 Chromium 155 相比像素差异
  1.49%，全部来自字形抗锯齿与色域差异，无元素缺失。

低于 Chromium 109 的浏览器不在支持范围。

## 5. 常用运维

```bash
docker compose logs -f --tail=100          # 查看日志
docker compose restart                     # 重启
docker compose down                        # 停止（数据卷保留）
docker compose down -v                     # 停止并删除工作区数据（谨慎）
```

工作区与运行数据都在卷 `web-data`（挂载到容器 `/data`）内。备份该卷即可备份全部数据。

## 6. 重建镜像

镜像源码位于仓库 `deploy/web/`：

```bash
docker build \
  --build-arg BASE_IMAGE=docker.1ms.run/library/node:24-bookworm-slim \
  --build-arg NPM_REGISTRY=https://registry.npmmirror.com \
  -t reactor-web:v1.0.8 <构建上下文>
```

构建上下文需包含：`Dockerfile`、`runtime-package.json`、`server-dist/`（`packages/server/dist`）、
`web-dist/`（`packages/web/dist`）、`agent/zcode.cjs`（`apps/zcode-cli/packages/cli/dist/zcode.cjs`）。

> 基础镜像必须是 Debian/glibc 系。Alpine(musl) 下 node-pty 预编译产物无法加载，
> 终端能力会失效。
