# Reactor 运维台（reactor-ops）部署说明

运维台是一个**独立于主 Web 的特权容器**：平台管理员登录后，agent 以宿主机 root 视角
运行，用来改 Docker 配置、清理磁盘垃圾、管理服务器。

> ⚠ 这是整个交付包里权限最高的组件。普通用户无法登录（服务端校验
> `platform_admin`），但一旦 admin 会话泄露，等同于宿主机 root 泄露。不要把
> 3040 端口暴露到公网；不用时直接停掉。

## 1. 权限面（刻意开到最大）

| 配置 | 作用 |
| --- | --- |
| `privileged: true` | 宿主内核能力 |
| `pid: host` | 能看/管宿主机进程与服务 |
| `network_mode: host` | 宿主网络（端口直接是宿主机端口） |
| `- /:/host:rw` | 宿主根文件系统，agent 工作区默认 `/host` |
| `- /var/run/docker.sock` | 容器内 `docker` CLI 直连宿主 Docker |
| `ZCODE_WEB_USER_SANDBOX=0` | worker 子进程不做系统沙箱 |
| `REACTOR_WEB_PRIVILEGED=1` | worker 以容器 root 运行、不 setpriv 降权，工作区 = `/host` |
| `REACTOR_WEB_ADMIN_ONLY=1` | 只允许 `platform_admin` 登录 |

镜像内额外装了 `docker.io`（CLI）、`procps`、`iproute2`、`lsof`、`less`、`nano`；
基础能力（git/curl/7z/jq/python/pandas 等）继承自主 Web 镜像。

## 2. 部署

前提：主 Web 已部署（`web/load-and-up.sh` 跑过），identity / gateway 在运行。

```bash
cd ops
sh load-and-up.sh
```

脚本会：检查/导入 `reactor-web:v1.1.1` → 构建 `reactor-ops:v1.1.1` →
用独立项目 `reactor-ops` 启动容器（不复用主 Web 的项目名与数据卷）。

访问：`http://<服务器IP>:3040/`，用平台管理员账号登录。

> 身份地址默认 `http://127.0.0.1:8791`（host 网络下即宿主机 identity），
> 可用 `REACTOR_IDENTITY_URL` / `REACTOR_GATEWAY_URL` 覆盖。

## 3. 典型运维操作

在运维台对话里直接说需求即可，agent 等价于在宿主机上执行：

```bash
# 磁盘诊断
df -h
du -sh /host/var/lib/docker/* | sort -h | tail -20
docker system df

# 安全清理（只删悬空镜像/构建缓存/旧日志）
docker image prune -f
docker builder prune -f
journalctl --vacuum-size=200M

# 改 Docker 配置（宿主路径是 /host 前缀）
vi /host/etc/docker/daemon.json
systemctl restart docker        # pid:host + privileged 下可用

# 管容器
docker ps -a
docker logs --tail 100 reactor-web
```

### 清理红线（建议在提示词/操作习惯里固定）

- **不要** `docker system prune -a` / `docker system prune --volumes` /
  `docker volume prune`——会删掉交付镜像或 `web-data`、`pg-data`、`ldap-data` 数据卷；
- 现场无外网，交付镜像删了只能重新传 tar；
- 先 `docker system df` + `du` 看占用，再按需清理。

## 4. 安全边界

- 只有 `platform_admin` 能登录；`dept_head` / `user` 会被 403 拒绝；
- 与主 Web 容器、用户数据卷完全隔离（独立项目 `reactor-ops`、独立 `ops-data` 卷）；
- agent 的会话与凭据在 `ops-data`，不与其他用户混用；
- 建议只在内网管理网段开放 3040，或通过跳板机访问；
- 不用时：`docker compose -p reactor-ops down`（不会删 `ops-data`）。

## 5. 升级

主 Web 镜像升级后：

```bash
docker load -i ../web/images/reactor-web-v<新版本>.tar.gz
cd ops
# 改 compose.yml / Dockerfile 里的版本号后重跑
sh load-and-up.sh
```

## 6. 常见问题

| 现象 | 原因/处理 |
| --- | --- |
| 登录提示「仅平台管理员可登录运维台」 | 账号不是 `platform_admin`；换 admin 账号 |
| 登录 502 | 运维容器连不到 identity；确认网络/`REACTOR_IDENTITY_URL` |
| `docker: command not found` | 镜像没基于 reactor-ops 构建；确认 `docker build` 用的是 `deploy/ops` |
| 容器内看不到宿主机文件 | 检查 `- /:/host:rw` 挂载与 agent 的 cwd（应为 `/host`） |
