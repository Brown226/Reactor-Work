# 全文一致性

## 核心：找"同一件事在两处说得不一样"

一致性问题的价值全在**对照**上，所以每条问题必须同时给出**两处（或多处）原文**，并标明各自位置。
只报"某处有问题"而不指出与谁矛盾，等于没报。

## 必须交叉核对的六类

| 类别 | 典型矛盾 |
| --- | --- |
| 数值 | 正文写 DN200、材料表写 DN150；说明写 2 台、表里 3 台 |
| 名称 | 标题写「循环水处理系统」、正文写「循环水系统」；设备名与型号不符 |
| 编号 | 图册编号/文件编码/DOC.NO 在封面、页眉、目录、正文中不一致 |
| 单位与量纲 | 一处 `m³/h`、一处 `t/h`；压力和扬程混用 |
| 时序 | 版次/日期前后颠倒；"施工完成后"出现在"施工前"章节 |
| 范围 | 目录列了某章节但正文缺失；正文有某表但目录未列 |

## 步骤

1. 抽取所有"可对照实体"：编号、名称、数值+单位、日期、版次、表格行数与条目。
2. 按实体聚合，找出取值集合大小 > 1 的实体 → 每个上报一条，给出全部取值与位置。
3. 对**表格与正文**单独再对一遍（材料表与设计说明的矛盾是最高发的）。
4. 区分"同一实体不同写法"（`warning`）与"数值冲突"（`error`）。

## 不要做

- 不要把"同一实体的不同粒度"误报成矛盾（如"给水系统"与"给水系统管道"层级不同）。
- 不要在无法判断哪个值正确时替用户选一个——报出全部取值让人定。

## 输出要求（所有审查类型一致）

先用对话消息给出整体判断（结论、问题条数、按严重度分组的一句话摘要），再由**结构化结果**承载明细。

每条问题必须包含：

| 字段 | 要求 |
| --- | --- |
| `severity` | `error`（必须修改）/ `warning`（建议修改）/ `info`（提示） |
| `ruleCode` | 本条依据的规则标识（如 `TYPO-001`、`STD-ABOLISHED`），不适用时写类型名 |
| `originalText` | **原文片段**——一字不改地抄回，用于定位与复核；缺失这一项的问题条视为无效 |
| `suggestion` | 建议改成什么；无法给出时写明"需人工确认" |
| `description` | 一句话说明为什么是问题（引规则/标准/条款） |
| `location` | 行号或章节号；有字符偏移时一并给出（`startOffset`/`endOffset`） |
| `anchor` | 供「点击问题 → 原文高亮」使用的定位（文件名 + 上述偏移；无偏移时给 `quote`） |

严重度口径（**不要全报 error**）：

- `error`：事实错误、引用已废止标准、违反强制性条文、数据矛盾——不改会出事。
- `warning`：规范/习惯问题、表述不严谨、可能引起歧义的措辞。
- `info`：可读性建议、可选优化。

**禁止**：把"未发现问题"写成结论却省略检查范围；把猜测写成结论；报出问题却不给原文片段。
