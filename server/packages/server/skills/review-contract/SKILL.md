# 合同风险审查

## 立场与边界（先声明）

- 默认站在**委托方（我方）**立场审；不确定时先问。
- 本文只做**风险提示**：指出条款缺失、不明确、对我方不利之处。**不是法律意见**，重大风险应提示咨询法务。
- 不要虚构法条编号。引法条必须准确；不确定就只说"依据合同法律规定"这类泛述或直接不引。

## 六个必查面

1. **主体与标的**：主体资格、名称一致性、标的范围是否明确（含附件清单是否齐全）。
2. **价格与付款**：总价/单价、税率与发票、付款节点与比例、预付款担保、逾期利息。
3. **进度与验收**：交付时间与顺延条件、验收标准与期限、验收不通过的处理、默示验收条款。
4. **变更与索赔**：变更程序、计价方式、索赔时限（**时限过短是常见陷阱**）、不可抗力范围。
5. **违约与责任**：违约金比例是否对等、责任上限、间接损失是否排除、解除条件。
6. **知识产权、保密与争议解决**：成果归属、保密期限、争议解决方式与管辖地（管辖地是否对我方不利）。

## 输出

按上面六面逐面给结论（"无风险 / 有风险见第 N 条 / 本文件未涉及"），风险条目按严重度排序。
每条给出**条款原文片段**、风险点、建议表述。缺条款的写"建议补充"并说明补什么。

## 输出要求（所有审查类型一致）

先用对话消息给出整体判断（结论、问题条数、按严重度分组的一句话摘要），再由**结构化结果**承载明细。

每条问题必须包含：

| 字段 | 要求 |
| --- | --- |
| `severity` | `error`（必须修改）/ `warning`（建议修改）/ `info`（提示） |
| `ruleCode` | 本条依据的规则标识（如 `TYPO-001`、`STD-ABOLISHED`），不适用时写类型名 |
| `originalText` | **原文片段**——一字不改地抄回，用于定位与复核；缺失这一项的问题条视为无效 |
| `suggestion` | 建议改成什么；无法给出时写明"需人工确认" |
| `description` | 一句话说明为什么是问题（引规则/标准/条款） |
| `location` | 行号或章节号；有字符偏移时一并给出（`startOffset`/`endOffset`） |
| `anchor` | 供「点击问题 → 原文高亮」使用的定位（文件名 + 上述偏移；无偏移时给 `quote`） |

严重度口径（**不要全报 error**）：

- `error`：事实错误、引用已废止标准、违反强制性条文、数据矛盾——不改会出事。
- `warning`：规范/习惯问题、表述不严谨、可能引起歧义的措辞。
- `info`：可读性建议、可选优化。

**禁止**：把"未发现问题"写成结论却省略检查范围；把猜测写成结论；报出问题却不给原文片段。
