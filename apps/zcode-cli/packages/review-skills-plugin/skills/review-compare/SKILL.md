# 以文审文

## 与「全文一致性」的区别

一致性是**一份文件内部**自洽；以文审文是**两份文件之间**对齐。所以必须明确谁是基准（权威方），
结论才有方向：应以基准为准，报出目标文件的偏差。

## 步骤

1. **先确认基准**：问清楚或让用户指定哪一份是权威依据（上游设计文件 > 规格书 > 上一版）。
   基准不明确的，先问再查，不要自己假设。
2. 抽取可比对字段：参数（压力/温度/流量/规格/材质）、数量、编号、单位、条款要求。
3. 逐字段对照，按方向分类：
   - `error` **实质性偏差**：数量、规格、材质、压力等级与基准不符。
   - `warning` **表述偏差**：同一要求两种说法，可能引起歧义。
   - `info` 基准有而目标未提及（可能是合理省略，需确认）。
4. 每条给出**双方的原文片段**与位置（基准侧 + 目标侧）。
5. 结尾给"偏差清单"：共 N 项，其中实质性 M 项。

## 不要做

- 不要在目标文件里"补写"基准内容——你只报偏差，改动由设计人决定。
- 不要把基准本身的错误当成目标文件的错误（基准也要核，但要单独说明）。

## 输出要求（所有审查类型一致）

先用对话消息给出整体判断（结论、问题条数、按严重度分组的一句话摘要），再由**结构化结果**承载明细。

每条问题必须包含：

| 字段 | 要求 |
| --- | --- |
| `severity` | `error`（必须修改）/ `warning`（建议修改）/ `info`（提示） |
| `ruleCode` | 本条依据的规则标识（如 `TYPO-001`、`STD-ABOLISHED`），不适用时写类型名 |
| `originalText` | **原文片段**——一字不改地抄回，用于定位与复核；缺失这一项的问题条视为无效 |
| `suggestion` | 建议改成什么；无法给出时写明"需人工确认" |
| `description` | 一句话说明为什么是问题（引规则/标准/条款） |
| `location` | 行号或章节号；有字符偏移时一并给出（`startOffset`/`endOffset`） |
| `anchor` | 供「点击问题 → 原文高亮」使用的定位（文件名 + 上述偏移；无偏移时给 `quote`） |

严重度口径（**不要全报 error**）：

- `error`：事实错误、引用已废止标准、违反强制性条文、数据矛盾——不改会出事。
- `warning`：规范/习惯问题、表述不严谨、可能引起歧义的措辞。
- `info`：可读性建议、可选优化。

**禁止**：把"未发现问题"写成结论却省略检查范围；把猜测写成结论；报出问题却不给原文片段。
