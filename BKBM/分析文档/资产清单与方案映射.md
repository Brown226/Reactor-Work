## 二、此前遗漏的三处（本次复核修正）

### 遗漏 1：`mcp_ptc` 模块（8 个 pyd / 80 签名）

**这是"MCP 工具 → Python 函数"的转换器**，是技能文档里那句
「MCP 将 PKPM 提供的所有工具函数**映射为原生 Python 函数**」的实现。

核心接口：

```python
class MCPToPTC:
    asetup(self) -> None                                    # 异步初始化
    _setup_server(self, server_name, config) -> None        # 连接一个 MCP 服务
    _register_ptc_tools(self, server_name, session) -> None # 注册工具
    _register_tool_related_classes(self, server_name, tools) # 注册数据结构
    inject_tools_to_namespace(self, globals_dict=None) -> List[str]   # ★ 注入函数
    inject_classes_to_namespace(self, globals_dict=None) -> List[str] # ★ 注入类
    get_classes_description(self, server_name=None) -> str
    ais_connected(self, server_name=None, ping_timeout=5.0) -> Union[bool, Dict[str, bool]]

class SchemaToModel:
    create_model_from_schema(self, name, schema) -> Type[BaseModel]      # JSON Schema → pydantic
    create_models_from_defs(self, all_defs, extra_schemas=None) -> Dict
    convert_dict_to_model(data, model_class) -> BaseModel
```

**为什么重要**：这是整套"函数注入"机制的引擎。**没有它，MCP 工具就只能一个个当工具调用，不能写脚本批量操作。**

**对移植的影响**：这块必须自己实现（约 2 周），核心是：
1. 从 MCP `tools/list` 拿工具定义
2. 把 JSON Schema 转成 Python 函数签名
3. 注入到执行器全局命名空间

## 五、三条关键结论

**① 最重要的资产不是代码，是 PKPM-Link.md 的 200 行工程知识**

那里面有交叉打断、端点 z 语义、两套入口、荷载符号——**每一条都是踩坑记录**。代码可以重写，这些坑要重新踩。

**② 此前漏掉的 `mcp_ptc` 是架构的关键一环**

没有它，MCP 工具只能一个个当工具调用，**不能写脚本**。而"写脚本批量操作"正是这套方案的威力所在（一个脚本建 700 根斜杆）。
