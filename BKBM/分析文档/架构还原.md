## 二、Agent 是什么（LangGraph 图）

```python
graphs = {"agent": "PKPMAgent.agent:PKPMAgent"}
```

**`agent.pyd` 只有 2 条签名**（其余全被编译进图定义）。但从中间件可反推完整结构：

```
PKPMAgent（StateGraph）
  state: PKPMAgentState
  checkpointer: get_sqlite_checkpointer()   ← 每 superstep 提交

  节点: agent（模型调用 + 工具执行循环）
  中间件链（before_model → wrap_model_call → after_model）:

  ┌─ skills             系统提示注入可用技能清单
  ├─ skill_activation   处理 /skill 斜杠命令，合成消息对
  ├─ mcp_manager        把 MCP 连接状态写进系统提示
  ├─ knowledge_middleware  注入知识快照
  ├─ context_usage      计算 token 占用，触发压缩判定
  ├─ context_compaction 超阈值时压缩历史
  ├─ image_limit        图片数量/大小限制，超限转占位符
  ├─ view_image         工具产出的图片重新注入模型
  ├─ dangling_tool_call 修补未闭合的 tool_call
  ├─ permission         三级权限 Ask/Auto/Full，拦截高危工具
  ├─ ask_user_question  向用户提问并等待
  ├─ stop_request       用户中断
  ├─ steer_input        运行中插入新消息（转向）
  ├─ task_lifecycle     发布 started/completed/failed 事件
  ├─ title              生成会话标题
  ├─ model_selection    动态选模型
  └─ web_access         联网
```

**这是核心设计**：不在一个巨大的 prompt 里堆功能，而是**每个关注点一个中间件**，各自 hook 模型调用前后。

## 三、关键机制逐个拆解

### 3.1 上下文压缩（middleware/context_compaction + _context_compaction_support）

最复杂的设计，70+ 函数。逻辑：

```
1. context_usage 每次模型调用后测量 token
2. 超过阈值 → _auto_compact_request() 触发
3. _find_safe_cutoff_point(messages, cutoff_index)  找安全切点
     ↑ 不能切断 tool_call / tool_result 配对
4. 把待压缩区切成「原子组」_atomic_groups()
     ↑ 一条 assistant + 它的全部 tool 消息是一组
5. 按 token 预算分批 _batch_assignments()
6. 每批生成摘要 _generate_assignments()
     - _generate_giant_turn() 处理超长单轮
     - _reduce_tool_content() 截断工具输出
7. 分级摘要 _age_to_budget()：老内容摘要更狠
8. _update_overall() 维护跨压缩的整体摘要
9. 落盘 history.md，消息里留指针 _reference_block()
```

**可移植点**：
- `tpc`（tokens-per-char）动态校准
- `_pinned_use_skill_read_messages` —— 被技能读过的内容不压缩
- 压缩后依然可 `browse` 原文（history.md）

### 3.2 执行器（execworker/manager）

```python
submit(key, code|file_path, args, timeout, workspace_dir) -> dict
  _acquire(key)          # 按 key 取 worker，没有则新建
  _await_ready(handle)   # 等 worker 就绪
  _run_on(handle, ...)   # 投递任务
  _submit_inner()        # 内部排队
  as_result()            # 返回 dict

interrupt_async / interrupt_blocking  # 两套中断
run_editor(code, file_path)           # 编辑器直接跑
```

**关键**：worker 按 `key` 复用（`_session_handles`），所以 Tekla 那种需要常驻 .NET 运行时的能持续工作。

### 3.3 技能系统（skill_kit）

```

  skills_roots()              → [内置, SKILLS_EXTRA_PATHS, 用户目录]
  collect_skill_metas(dirs)   → 扫描所有 SKILL.md 读 frontmatter
  _fs_fingerprint(mds)        → 文件指纹缓存，避免重复扫描

```

### 3.4 MCP 连接层（mcp_link/registry）——最值得抄的部分

```python
# 统一注册表
add_mcp_server(name, config)
connect_to_server(name, work_dir, cmd_args) -> bool | str
get_active_link(name) -> BaseMCPLink
is_server_connected(name) -> bool
set_mcp_server_enabled(name, enabled)

# BaseMCPLink 抽象
Connect(work_dir, cmd_args, timeout=30) -> bool | str
  _start_mcp_server()   # 子类实现：怎么启动软件
  _connect_mcp()        # 通用：连 httpx streamable_http
  _wait_mcp_service()   # 通用：等端口就绪
Disconnect()
IsConnected()
```

**子类只需实现 `_start_mcp_server`**，其他通用。这是很干净的设计。

各子类做法：

| 子类 | 启动方式 |
|---|---|
| pkpm | `_find_pkpmmain_exe()` → `_attach_to_process()` → 版本校验 |
| plants | 注册表四路发现 → `_copy_template_project()` → Popen |
| sausage | `_find_installed_exe(product)` → `_is_project_dir()` 校验 |
| revit | `_is_server_running()` → `_kill_port_process()` → `_start_revit_mcp_process()` |
| pkpm_module | `_is_module_process()` 识别 → `_manual_start_hint()` 兜底 |

**公共工具**（common_tools）：
```python
is_local_port_opened(port) -> bool
pid_to_mcp_port(pid) -> int        # 从 PID 反查端口
wait_local_mcp_ready(port, timeout=100)
```

### 3.5 连接简报（briefing）——很妙的 UX 设计

```python
build_briefing(server_name) -> str
connect_briefing_hook(result)        # 连接成功后自动挂 hook
format_categories(server_name)       # 可用函数类别
format_classes(server_name)          # 可用数据结构
_sample_type(server_name)
```

连接成功后自动往返回结果里附一份「你能用什么」，模型不用猜。

## 五、移植到 Reactor 的映射建议

Reactor 是 TypeScript/Node + Electron 技术栈（`packages/desktop` 已用 electron-builder）。对应关系：

| PKPM Agent | Reactor 现状 | 移植方式 |
|---|---|---|
| Electron 壳 | ✅ 已有 `packages/desktop` | 直接复用 |
| Next.js 前端 | ✅ `packages/web` | 直接复用 |
| FastAPI 后端 | ❌ 无 | 用 Node（`packages/server`）重写，或独立 Python 服务 |
| LangGraph 图 | ⚠️ 有 provider 抽象 | `packages/services` 里加 agent 编排层 |
| 中间件链 | ✅ 有 plugin/extension 机制 | 用现有 hook 系统实现 |
| MCP 连接层 | ⚠️ 有 `@modelcontextprotocol` 依赖 | **新增 `mcp_link` 模块，照抄 registry 模式** |
| 技能系统 | ⚠️ 有 skill 相关 | 参考 `skill_kit` 三件套 |
| 执行器 | ⚠️ 有 node-pty | 扩展为 Python 执行器 |
| 知识库 | ⚠️ EvoFlow 知识库（已有授权） | **直接对接现有** |

### 最该抄的三个点

**① MCP 注册表模式**
```
registry.py: add/connect/disconnect/get_active_link/is_connected
BaseMCPLink: 只要求子类实现 _start_mcp_server
```
这比 Reactor 现在散落各处的工具接入方式干净得多。

**② 能自动降级的启动发现**
```
四路候选（卸载表 / 自身配置键 / 文件关联 / 环境变量）
→ 每个都过 _is_valid_plants_root()
→ 显式路径 > 环境变量 > 上次成功 > 自动发现
```

**③ 连接简报**
连上就告诉模型"你能用这些"，省掉一轮摸索。

## 六、照猫画虎的最小实现路径
