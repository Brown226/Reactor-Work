## 0. 一句话目标

企业登录后：**走公司网关的模型调用被记账并上报，管理台能看用量；公司下发的策略在端上形成权限天花板；开发者模式旁路调用有意不记账。**

## 1. 已拍板决策（不再讨论）

| #   | 决策                                                                                          | 理由                                                                                                        |
| --- | --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| D1  | **只上报企业 provider 的 `model_call`**（`providerId === reactor:providerId` 的哨兵企业条目） | 对齐 R6 与模型治理契约：旁路「没有审计与用量上报」是产品既定口径，不是缺口                                  |
| D2  | **策略模式词表用 ZCode 四档**：`plan` / `build` / `edit` / `yolo`                             | 与端上 `zcodeTaskMode` / `permission/service.ts` 同一词表；旧词 `readonly/balanced/trust/strict` 不进客户端 |
| D3  | **采集在 Host，令牌只在 Host**                                                                | 与 P1 凭据边界一致；Renderer 不直接 POST                                                                    |
| D4  | **outbox + `eventId` 幂等补传**，不新建 sidecar 式 RPC                                        | 语义继承原项目；实现独立；崩溃不丢不重                                                                      |
| D5  | **额度 v1 只告警不阻断**；旁路可绕开计量是**有意边界**                                        | 与模型治理信任模型一致；硬限流将来放网关                                                                    |
| D6  | **服务端仍不写网关审计**；管理台用量数据来自端侧 `/desktop/audit/batch`                       | R6 原文；「归属可追溯」≠「网关已落库」                                                                      |
| D7  | 开发者模式**只**影响模型可见性，**不**放开策略强制点                                          | 禁止写 `if (devMode) skip policy`                                                                           |

### D2 模式天花板映射（语义）

组织 `defaultApprovalMode` 表示「用户最高能开到哪一档」，用户会话 mode 与天花板取**更严**交集：

| 天花板（组织） | 用户可选                  | 效果                             |
| -------------- | ------------------------- | -------------------------------- |
| `plan`         | 仅 `plan`                 | 只读规划                         |
| `edit`         | `plan` / `edit`           | 可改文件，不可乱跑命令           |
| `build`        | `plan` / `edit` / `build` | 常规开发                         |
| `yolo`         | 四档皆可                  | 不额外收紧（默认若服务端未配置） |

用户侧显示「受组织策略限制」，不允许开到天花板之上。

**服务端改动（D2 连带）**：`DesktopPolicy.defaultApprovalMode` 枚举改为 `plan|build|edit|yolo`；管理台策略页选项同步；库内若有旧值按 `readonly→plan · strict→edit · balanced→build · trust→yolo` 读时映射（写入只写新值）。冒烟脚本断言同步改。

## 2. 产品规则（用户/管理员看得见的行为）

| #   | 规则                                                                                            | 备注                                |
| --- | ----------------------------------------------------------------------------------------------- | ----------------------------------- |
| R1  | 企业登录后，**企业网关模型**每次调用记一条 `model_call`（含 token 分项），批量上报服务端        | 未登录：不报、不拉策略              |
| R2  | 离线/服务端不可达：事件留在本地 outbox，恢复后补传；**不丢不重**                                | `eventId` 幂等                      |
| R3  | 开发者模式旁路（本地 provider）**不入 outbox、不上报**                                          | 显式旁路；报表口径=「企业网关用量」 |
| R4  | 登录后拉取 `GET /desktop/policy`，形成：模式天花板、命令黑名单、出网白名单、额度告警线          | 拉取失败保留旧策略                  |
| R5  | 设置页「企业服务端」展示：本月用量进度（告警阈值）、策略摘要（是否限制）                        | 不新增顶级设置分区                  |
| R6  | 超额度**不中断**模型调用，只提示；命令/出网违规 → 拒绝执行并可上报 `policy_block`（见阶段划分） | 硬阻断不在 v1                       |
| R7  | 管理台「用量 / 审计」能看到上报的 `model_call`；归属 uid 由服务端按令牌写入                     | 请求体禁止携带 uid/deptId           |

**非目标（本阶段不做）**

- `tool_call` / `approval` / `session` 全量审计（留 P4.3，契约已支持，端上不接）
- 用量硬阻断 / 网关侧计量
- 旁路调用的任何上报
- 正文、路径列表、args/result 进入事件
- 改登录、改模型目录同步、改开发者模式手势

## 4. 架构与数据流

```
zcode-cli                    Host (services)                      server/
─────────                    ───────────────                      ───────
model_usage / stream    →    ReactorUsageReporter
task_token_usage_delta       ├─ 过滤：企业 provider 才入队
                             ├─ outbox.jsonl（append / ack）
                             └─ flush：≤500/批  ──────────────►  POST /desktop/audit/batch
                                                                  GET /desktop/policy
                             ReactorPolicyCache  ◄────────────────┘
                             ├─ desktop-policy.json
                             └─ 只读供给：permission 天花板
                                            命令黑名单闸
                                            HttpClient 出网白名单
                                            设置页额度展示
```

### 4.1 用量事件映射（`model_call` only）

| 审计事件字段               | 取值来源                                                                                                                                                   | 红线                         |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| `eventId`                  | 流式 `task_token_usage_delta.eventId ?? eventKey`                                                                                                          | 稳定、可重传                 |
| `ts`                       | 事件时间 ISO8601                                                                                                                                           | 不得大幅超前                 |
| `sessionId`                | 任务/会话 id                                                                                                                                               |                              |
| `action`                   | 恒定 `"model_call"`                                                                                                                                        |                              |
| `outcome`                  | 由 status 推导：完成 `ok`，错误 `error`，取消 `cancelled`                                                                                                  |                              |
| `usage.inputTokens` 等     | `ZCodeUsage`：input/output/total；`cachedInputTokens→cacheReadTokens`，`cachedWriteInputTokens→cacheWriteTokens`；`reasoningTokens` 不进服务端四段价则忽略 | 字段名按 `AuditUsage`        |
| `usage.model` / `provider` | `modelId` / `providerId`                                                                                                                                   |                              |
| `usage.cost`               | 端侧不填（服务端按价目核算）                                                                                                                               |                              |
| `summary`                  | 可空或短标签（如 `modelId`），**≤200 字**                                                                                                                  | **禁止正文**                 |
| `uid` / `deptId`           | **禁止填写**                                                                                                                                               | 服务端按令牌写入；带了会 400 |

入队过滤（必须同时满足）：

1. 已登录企业服务端；
2. 本次 `providerId` 为 `reactor:providerId` 指向的企业条目；
3. `usage.totalTokens > 0` 或分项有有效数字；
4. `querySource` 为 v1 不区分（主轮/compact/标题若走同一流事件则一并计；**若实测标题/compact 不经过该流，记入「已知缺口」而不是放宽过滤去报旁路**）。

### 4.2 上报器语义（继承原项目，实现独立）

- `peek` 读一批不删 → `POST` → 全批 `ack`（accepted/duplicates/rejected 都算已处理；rejected 是脏数据重试无意义）。
- 未登录 / 无 `baseUrl`：不发起网络，outbox 保留。
- 单批 ≤ `MAX_AUDIT_BATCH`（500）；一次 flush 最多 N 批（默认 10）防饿死。
- outbox 上限 5000，超出丢最旧并 `logger.warn`。
- 触发：登录成功、模型回合结束（30s 合并窗口）、退出前 best-effort、定时兜底（如 5min）。
- HTTP 走既有 `ApiClient` / `reactorServerClient`，Bearer **access token**（不是网关令牌）。

### 4.3 策略语义

| 情况                                          | 行为                                                            |
| --------------------------------------------- | --------------------------------------------------------------- |
| 未登录                                        | 不同步、不强制；`source=unknown` 视为**不限制**但设置页如实显示 |
| 拉取失败 / 超时 / 形状不对                    | **保留**上次策略，`source=cache` + `stale`，记 warn             |
| `commandBlacklist` / `egressAllowlist` 空数组 | **不限制**（不是全禁）；UI 显示「当前未限制」                   |
| 策略缺失字段                                  | 按默认策略合并（`DEFAULT_POLICY` 语义），不把缺失当清空         |

强制点（P4.2 起）：

| 字段                  | 落点                                         | 行为                                   |
| --------------------- | -------------------------------------------- | -------------------------------------- |
| `defaultApprovalMode` | 会话 mode 解析 / `setMode` / 会话默认 mode   | 取天花板交集；拒绝时提示来源=组织策略  |
| `commandBlacklist`    | bash 等执行类工具审批闸                      | 命中 → 拒绝 + 可选 `policy_block` 事件 |
| `egressAllowlist`     | 与 `public-egress-policy` 同一 HTTP 边界扩展 | 域名后缀匹配；`*` 逃生阀；解析失败拒绝 |
| `quota`               | Reporter 累计 + 设置页                       | 阈值提示；**不拦**                     |

域名匹配规则（与原项目对齐，避免两义）：空=不限制；`example.com` 含子域；`*.example.com` 仅子域不含裸域；端口不参与匹配。

## 5. 阶段划分（每阶段可独立验收）

### P4.1 用量上报（model_call）— 优先

**做**

1. `packages/services/src/reactor-server/`（或旁路新目录 `usage-report/`）实现 Reporter + outbox。
2. 挂接 Host 会话流 `task_token_usage_delta`（`zcodeTaskServiceAdapter` 既有事件），按 §4.1 入队。
3. `IReactorServerService` 或同模块扩展 `reportAuditEvents` / 内部 flush；登录/退出/回合结束触发。
4. 设置页「企业服务端」：本月累计 token 简报（可先读本地 outbox+内存或 `v4/usage/stats` 企业 provider 过滤，与上报同源优先）。
5. 服务端**零改动**（D2 枚举改放 P4.2 亦可，互不阻塞）。

**验收**

- [ ] 企业模型对话一次 → outbox 有条目 → flush → 服务端 `GET /desktop/audit?action=model_call` 能查到，`uid` 为登录用户。
- [ ] 断网对话 → 事件保留 → 恢复网络补传，重放同一批 → `duplicates` 增加，库内不双计。
- [ ] 开发者模式 + 本地模型对话 → outbox **无**新条目。
- [ ] 未登录 → 不出网、outbox 不新增。
- [ ] 事件体无 uid/deptId、无正文字段。
- [ ] 真机：与 P1 相同 CDP/独立数据目录方式跑通一条对话。

### P4.2 策略下发与天花板 + 额度展示

**做**

1. 服务端：`defaultApprovalMode` 枚举改为 ZCode 四档 + 旧值读映射 + 冒烟更新（D2）。
2. 端上：`GET /desktop/policy` → PolicyCache；设置页展示策略摘要与额度进度/告警。
3. 模式天花板：接入 mode 解析（`permission` / 会话 mode 变更）。
4. 管理台策略页选项与文案（若未做 D2 则此项阻塞）。

**验收**

- [ ] 管理台设 `defaultApprovalMode=edit` → 端上刷新策略后无法保持在 `yolo`/`build`，并提示组织限制。
- [ ] 拉取失败时策略不清空；设置页状态为「缓存/陈旧」。
- [ ] 月度限额 80% / 100% 阈值在设置页出现提示；调用不被拦断。
- [ ] 旧策略值 `balanced` 等读入后行为等于映射档。

### P4.3 强制点补全（命令 / 出网）+ 可选 tool_call

**做**

1. `commandBlacklist` 进执行类工具审批闸；拒绝可报 `policy_block`。
2. `egressAllowlist` 进 HTTP 边界；WebFetch / 统一 HttpClient 走同一判定。
3. （可选）`tool_call`：`tool_usage` 终态或流事件映射，`tool_start` 不上行。
4. （可选）`approval`：PermissionRequested → `ask`；Resolved → allow/deny。

**验收**

- [ ] 黑名单命令被拒绝，模型能收到可理解的拒绝原因；其它命令不受影响。
- [ ] 白名单外域名出网被拒；白名单内/空名单行为正确。
- [ ] 与 `public-egress-policy`（私网 IP）**双重判定**不互相破坏。

## 7. 已知缺口与有意边界（写进实现注释与本文件，不当 bug 修）

1. **旁路不计量**：开发者模式 + 本地模型可绕开额度与审计（与模型治理一致）。
2. **客户端强制可被改码绕过**：策略是治理不是内核级安全；硬保证应将来放网关。
3. **流式采集可能漏 `querySource ≠ main_turn`** 的模型调用（标题/compact）。P4.1 先接受并在报表口径写「以事件流为准」；若必须全量，P4.1b 再在 `recordModelUsageFact` 同点入队（仍禁止报旁路）。
4. **额度跨机不汇总端上缓存**：端上进度仅本机视角或短缓存服务端总数；权威以管理台为准。
5. **多窗口**：Reporter/PolicyCache 在 Host 单例；不走 Renderer localStorage 信道。

### 17.5 本轮修掉的一处测试自身竞态（洞② 用例）

首次批量跑洞② 单测时 3 次里挂 1 次，失败固定在同一处：`reactorAuditWiring.test.ts`「行为事实（洞②）」断言 `pendingEvents === 3` 实测为 2。

- **不是产品缺陷，是测试的等待方式错了**。入队走 `auditOutbox` 的写串行链，每次 `append` 都是 `mkdir + writeFile + rename` 真实文件 I/O；原用例用 `settle(6)`（固定等 6 轮 `setTimeout(0)`）等三笔落盘 —— **定时器与 I/O 完成无关**，机器负载高时 6 轮可能在第三笔写完前就跑完。
- **修法**：加 `waitUntil(predicate, timeoutMs=5000)` 轮询等条件本身（5ms 间隔），把「等 3 条入队」从"等固定轮数"改成"等条件成立"。
- **验证**：单文件连跑 **8 次全绿**，四文件批次连跑 **5 次全绿**（修前 3 次里挂 1 次）。
- **教训**：断言"异步副作用已完成"必须等条件，不能等固定轮数的宏任务 —— `settle(n)` 只适合"等到某个 fire-and-forget 至少被调度过"，不适合"等到 N 笔 I/O 全部落盘"。
