# 技能与 Agent 下发

企业登录之后，服务端可以把**技能**与**数字人（Agent，界面上叫「企业专家」）**下发到你的客户端。本页说明两者各自的状态所有者、同步时序、发现层优先级、同名冲突处理与失败语义。

两件事都属于**已实现**能力：技能下发为 P2，Agent 下发为 P3。契约正本见 `docs/已完成/已完成-server-skill-sync.md`、`docs/已完成/已完成-server-skill-delivery-plan.md`（P2）与 `docs/已完成/已完成-服务端接线-P3-Agent下发.md`（P3，字段映射与发现层）；决策正本见 `docs/未完成-服务端接线-方案-v1.md` §4.3 / §4.4。

## 1. 落地状态

| 能力 | 状态 | 阶段标注 |
| --- | --- | --- |
| 技能下发（独立目录、作用域标记、全量对齐、启停 / 更新 / 卸载护栏、手动同步、登录后后台同步一次） | 已实现 | P2 |
| 技能市场（目录 / 精选 / 分类 / 收藏 / 安装） | 已实现 | 后续增量（P2.5 / 市场方案） |
| Agent（企业专家）下发（server 作用域物化、字段映射、发现层与优先级、只读护栏、安装 / 启停 / 卸载 / 手动同步、登出清空） | 已实现 | P3 |
| 技能注入集过滤（用服务端的注入集参与会话注入决策） | 未实现 | P2 有意后置，见 §6 |
| 专家「以此专家开会话」薄封装、专家使用量上报 | 未实现 | P3 非目标，使用量属 P4 口径 |

## 2. 一句话规则

| # | 规则 |
| --- | --- |
| R1 | 只有企业登录后才同步；未登录不发请求、不动本地文件 |
| R2 | 服务端是**安装关系**的唯一真相；本地只负责「物化文件」 |
| R3 | 服务端下发的资源与**你自己的**技能 / Agent 物理隔离，可共存 |
| R4 | 下发的资源在列表里**可辨识来源**，且不能被误删成「用户自建」 |
| R5 | 服务端不可达 / 未登录 / 请求失败 → **不删除**任何本地文件 |
| R6 | 卸载必须同时解除服务端安装关系，**不能只删本地** |

## 3. 落盘位置

两者都是**用户级**目录，与工作区级目录 `.zcode` 无关：

| 资源 | 落盘位置 | 目录所有者 |
| --- | --- | --- |
| 服务端技能 | `~/.reactor/server-skills/<技能名>/`（含 `SKILL.md` 与附属文件） | 技能同步器（唯一写者） |
| 企业专家 | `~/.reactor/server-agents/<专家名>.md` | 专家同步器（唯一写者） |

设计上刻意**不混进**你的自建目录（`~/.reactor/skills/`、`~/.reactor/agents/`）：

- 混进去后「用户自建」与「服务端下发」无法区分，R4 无法满足；
- 卸载 / 更新 / 冲突处理时容易误删你自己的文件。

服务端技能目录**没有**额外的来源标记文件：来源由所在目录决定（作用域 = `server`）。

## 4. 状态所有者

原则是「一处状态一个写入者」：

| 状态 | 唯一写者 | 落盘 / 存放 |
| --- | --- | --- |
| 服务端技能文件树 | 服务端技能同步器 | `~/.reactor/server-skills/` |
| 技能的启停 | 既有技能服务的启停接口（写按路径的启用表） | `~/.reactor/cli/config.json` |
| 技能的安装 / 卸载关系 | 服务端（客户端经安装接口调用） | 服务端数据库 |
| 专家文件树 | 服务端专家同步器 | `~/.reactor/server-agents/` |
| 专家的安装 / 启停 / 收藏关系 | 服务端 | 服务端数据库 |
| 专家市场卡片字段（热度 / 标签 / 图标等） | 同步器的内存投影 | 不进 markdown；重启未同步前可缺失，界面降级只显示名字 |
| 企业登录令牌 / 地址 / 企业 provider 标识 | 企业服务端接入服务 | 凭据库 + 供应商配置 |

**禁止**：界面直接写这两个目录；同步器去写自建目录；为服务端资源再造一份启用状态文件。

> **提示**：技能与专家的「启停」语义**不一样**。技能启停是本地启用表，不删文件；专家启停等于「是否物化」——停用即删除本地文件，因为专家没有「留文件但不生效」的中间态，其可见性就等于「下发了没有」。

## 5. 同步时序

### 5.1 技能：全量对齐

```text
界面 / 登录钩子        技能同步器              服务端身份进程         磁盘
    │ ① 触发同步           │                        │                  │
    ├────────────────────►│ ② 取落盘集             │                  │
    │                     ├───────────────────────►│                  │
    │                     │ ◄── 技能清单 + 附件清单 │                  │
    │                     │   （失败 → 离线，本地一字不动）             │
    │                     │ ③ 逐个技能：内容不等才写 ├──────────────► server-skills/
    │                     │    附件哈希不符才拉取   │                  │
    │                     │ ④ 删除不在清单里的目录  ├──────────────► 只动本目录
    │                     │ ⑤ 取注入集（只读投影，用于「已下架」徽标） │
    │ ◄── 结果：变更 / 移除 / 离线 / 鉴权过期 / 单项错误              │
```

**幂等**：服务端没有变更时重复同步不改变磁盘内容与修改时间（正文按字符串比对，附件按哈希短路）。

**并发**：同步器内部是串行队列，同一时刻只跑一次，避免「全量对齐删目录」与「单技能卸载删目录」交叉执行把状态写撕裂。

### 5.2 技能：单技能动作

| 动作 | 步骤 |
| --- | --- |
| 卸载 | 先调服务端卸载接口（服务端写「不再自动装回」的记录），成功后才删本地目录；失败则**不删本地**（否则会出现「服务端仍安装、本地已空」）；服务端返回「本就不存在」时视为已卸载，仍清理本地残留 |
| 更新 | 重新拉取该技能并把变更文件落盘，成功后调用归位接口消除「有更新」标记 |
| 启停 | 走既有技能启停接口，写启用表；**不**调服务端启停接口 |
| 安装 | 经市场安装接口，成功后重新全量拉取再对齐（不靠本地推算） |

### 5.3 专家：写后重新全量拉取

专家的同步纪律与技能同构，但多一条硬规定：

1. **触发**：登录成功、启动时已登录、手动刷新、安装 / 启停动作成功之后。
2. **目标集** = 服务端目录里「已安装 **且** 已启用」的条目，这是唯一的物化判据。
3. **对齐**：内容不等则整文件重写，不在目标集则删除；增 / 改 / 删**只动**专家目录。
4. **写后重新全量拉取**：任何写操作成功后都重新拉一次目录再对齐，**不本地推算**安装数、热度等聚合字段——旧项目的教训就在这里。
5. **登出**：清空整个专家目录；再次登录由触发器恢复。
6. **失败**：未登录 / 请求失败 / 服务端不可达 → 不删除任何本地文件，保留上次结果。

### 5.4 触发时机一览

| 时机 | 技能 | 专家 |
| --- | --- | --- |
| 企业登录成功 | 后台同步一次（失败只记日志，**不回滚登录**） | 后台同步一次（同样不阻断登录） |
| 启动且已登录 | 后台同步一次 | 后台同步一次 |
| 手工操作 | 手动同步 / 安装 / 更新 / 卸载后 | 手动同步 / 安装 / 启停 / 卸载后 |
| 未登录 / 登出 | 不发起同步，**不清空**技能目录（保留离线可用副本） | 清空专家目录 |
| 周期轮询 | 无 | 无 |

> **提示**：登出对两者的处理**不一致**，且都是有意设计。技能保留本地副本以便离线可用（契约里写明：若要改成「登出即回收」，属于独立决策，需先改契约语义）；专家则清空，因为专家目录本身就是「服务端关系的投影」。

## 6. 发现层与优先级

下发下来的文件要能被现有加载链路发现——两个同步器都**复用既有发现逻辑**，不新建第二套加载器：

| 层 | 技能 | 专家 |
| --- | --- | --- |
| 界面侧 | 技能发现增加用户级 `server-skills` 根，作用域标记为 `server` | 专家发现增加 `server-agents` 根；分组额外走「企业专家」组 |
| 命令行侧 | 技能发现根加入 `server-skills` 根，来源标记为远端 | 专家 bootstrap 增加第三根，来源标记为 `server` |
| 只读护栏 | 对 `server` 作用域调用删除会被**明确拒绝**，必须走卸载 | 删除 / 改名路径对服务端文件**拒绝**（代码断言），界面不提供入口 |

两条链路的**数量必须一致**（同一数据根双根加载，不分叉），否则会出现「界面看得到、命令行看不到」的问题。

### 6.1 同名解析（技能）

同名技能跨来源并存时：

- **列表**：两者都显示，并标注来源 / 冲突。
- **解析**（`$` 提及注入、命令行按名加载）：优先级为

```text
server > workspace > plugin > user
```

也就是说**企业下发优先**。理由与既有方向一致（企业下发的指令应压过本地同名版本），且实现上无需改动既有的用户级 / 项目级根顺序。

细节两条：服务端同名技能被你在本地停用时，解析会回落到下一优先级来源；命令行列表仍按路径保留全部同名（既有语义不变，只有「按名解析」取第一位）。

> **待核实**：若产品希望「项目本地版本覆盖企业下发」，需同时改解析顺序、发现根插入位置与界面折叠映射三处，属独立决策，本页按当前实现描述。

### 6.2 同名解析（专家）

同名专家并存时，设置页两组各显示并标注来源。运行时裸名解析的优先级为：

```text
plugin > server > workspace > user > built-in
```

即：企业专家会遮蔽同名的用户级 / 项目级专家，但会被插件专家遮蔽。此外，服务端专家的名字会占用「裸名」，避免插件专家抢注与企业专家同名的别名。

> **待核实**：命令行侧按名加载同名专家时不做同名折叠（会全部加载），其解析结果与界面侧优先级是否完全一致，属方案文档中登记的未决项，需按实际版本验收。

## 7. 同名冲突与「已下架」

| 情形 | 行为 |
| --- | --- |
| 服务端技能与你自建技能同名 | 列表两者都显示并标冲突；按名解析取服务端版（§6.1） |
| 服务端专家与你自建专家同名 | 设置页两组各显示并标来源；裸名解析按 §6.2 |
| 管理端把**已安装**技能标记为停用（软下架） | **文件保留**（仍在落盘集），界面用「已下架」徽标标出（落盘集与注入集的差集）；技能注入在 P2 阶段**不因此变化** |
| 管理端把「自动安装」技能设为停用 | 不在落盘集 → 同步后删除本地目录（服务端口径） |
| 管理端收回授权（不再可见 / 不在落盘集） | 同步后删除本地目录 |
| 管理端下架专家 / 收回授权 | 服务端目录里不再包含该条目 → 对齐时删除本地文件（专家无中间态） |

技能软下架与专家下架的语义**相反**，是有意边界，不当缺陷处理。

## 8. 失败语义

| 情况 | 行为 |
| --- | --- |
| 网络错误 / 服务端错误 / 未登录 | 结果标记为「离线」，**零删除零写盘**，本地保留上一份可用副本 |
| 令牌失效或授权变化（未授权类错误） | 同样零删除零写盘，结果标记为「登录已失效」，界面提示重新登录 |
| 单个附件取不到或哈希不符 | 跳过该文件并记入错误清单，不写半套；技能其它文件继续 |
| 技能正文写盘失败 | 跳过该技能，继续其余 |
| 名字非法 / 路径越界 | 拒绝该项，不落盘 |
| 目录被占用导致删除失败 | 记入错误清单，下次同步重试 |
| 并发同步 | 串行队列，一次只跑一个 |
| 专家写盘失败 | 记入错误清单，不阻塞其它专家 |

「离线」与「登录已失效」必须区分：都提示「同步失败」会让用户看不出真正原因（到底是网断了还是得重新登录）。

## 9. 验收场景

技能侧：

1. 登录成功后，`~/.reactor/server-skills/` 出现落盘集目录，列表来源标记为「服务端」。
2. 附件哈希与服务端清单一致时不重拉；服务端改文件后仅重拉变化的附件（二进制按解码后字节校验）。
3. 断网同步 → 本地数量与内容不变，标记为离线。
4. 软下架已安装技能 → 文件仍在并标「已下架」；自动安装技能被停用 → 目录被删除；收回授权 → 目录被删除，你的同名自建目录不受影响。
5. 卸载 → 服务端关系与本地目录一并解除，再同步不会被装回。
6. 同名共存 → 两条路径的按名解析都取服务端版，列表两者都显示。
7. 对服务端技能调用本地删除 → 明确拒绝；自建技能仍可删。
8. 未登录 → 不触发同步，登录前已有的下发目录不被清空。

专家侧：

1. 登录 → 出现「企业专家」分组与来源徽标；未登录则完全没有。
2. 安装并启用一个专家 → 本地出现对应 markdown，字段映射正确；用它发起子任务时系统提示词、模型与技能白名单生效。
3. 停用 → 本地文件删除、列表与选择器立即消失；再启用 → 恢复物化。
4. 卸载 → 服务端关系与本地文件一并删除，再同步不会回灌；管理端下架同理。
5. 断网 / 服务端错误 → 同步报错但本地文件完整保留。
6. 登出 → 专家目录清空；你的 `agents/` 与 `.zcode/agents/` 字节不变；再登录恢复一致。
7. 同名专家并存 → 两组各显示并标来源；对服务端专家无删除入口，直接传服务端路径调用删除 / 更新会被拒绝。
8. 命令行与界面列出的服务端专家数量一致。

## 10. 字段映射：服务端专家 → 本地 markdown

服务端下发的专家会物化成与自建专家同格式的 markdown，字段映射如下（未列出的市场字段不进 markdown，只做界面徽标）：

| 服务端字段 | 本地落点 | 处理 |
| --- | --- | --- |
| 名字 / 描述 | 同名元信息 | 服务端已限制名字字符集，文件名安全 |
| `persona` | 正文（即系统提示词） | 直通 |
| 模型 + 供应商 | 元信息里的模型选择，写成「本地企业 provider 标识 / 模型 id」 | 服务端的供应商是网关逻辑名，**禁止**字面写入；本地企业 provider 标识缺席时**不写模型**，跟随主会话 |
| 思考档位 | 元信息里的推理档位 | 有则写；无模型时丢弃（不为此另开一条写入路径） |
| 权限模式 | 元信息里的权限模式 | **降级映射**：只读 / 严格 → 计划档；均衡 / 信任 → 自动档。子智能体的权限词表只有两档，与会话的四档是两回事，因此该映射是**有损**的（无法从落盘结果反推出原值） |
| 技能白名单 | 元信息里的技能列表 | 直通；本机没装的技能运行时自然不注入 |
| 已安装且已启用 | 是否物化 + 发现过滤 | 目标集唯一判据 |
| 标题 / 图标 / 标签 / 官方标记 / 热度 / 收藏 | 不进 markdown | 同步器内存投影供界面徽标；重启未同步前降级只显示名字 |

## 与上游 ZCode 的差异

| 关注点 | 上游 ZCode 官方文档 | 本说明书（本仓） | 原因 |
| --- | --- | --- | --- |
| 分发来源 | 官方托管服务与官方插件市场 CDN | 内网自建服务端下发，按登录身份可见 | 内网隔离，不能依赖公网 CDN 与账号 |
| 技能来源标记 | 无「服务端下发」这一来源 | 新增 `server` 作用域与来源，独立目录 `~/.reactor/server-skills/` | 来源必须可辨识，且不能与你自建技能混淆 |
| 专家（数字人） | 无「服务端下发专家」概念 | 服务端下发的专家物化为 `~/.reactor/server-agents/`，在「企业专家」分组可用 | 组织级专家需要统一发布与回收 |
| 同名冲突 | 无该场景 | 技能按名解析企业下发优先；专家裸名解析企业下发位于项目之上、插件之下 | 明确一处优先级，避免同名双注入 |
| 卸载语义 | 本地删除即可 | 必须走服务端卸载接口解除安装关系，否则会被自动装回 | 安装关系的唯一真相在服务端 |
| 离线行为 | 未特别约束 | 服务端不可达时零删除零写盘，保留上一份可用副本 | 网络抖动不该让本地能力消失 |
| 启停语义 | 未区分 | 技能启停不删文件；专家启停等于删除本地文件 | 专家没有「留文件不生效」的中间态 |
