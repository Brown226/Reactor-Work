# 内网办公四件套

「办公四件套」指 Word 文档（docx）、电子表格（xlsx）、演示文稿（pptx）与 PDF 四条创作能力。在 Reactor 里它们是**随安装包内置的官方插件**，装完即可用，**不访问任何外部插件市场**。这一页说明它们从哪来、怎么分发、离线边界在哪，以及 Reactor 自己生成文档时遵循的排版规范。

依据：`docs/已完成/已完成-内网办公四件套-fork-spec.md`、`docs/已完成/已完成-文档产出-规范-v1.md`、`docs/已完成/已完成-Markdown导出-方案-v2.md`、`docs/已完成/已完成-文件解析OCR-CAD-集成方案.md`、`docs/已完成/已完成-OCR栈轻量化方案.md`、`docs/已完成/已完成-办公公式与字体管线-借入方案.md`、`docs/未完成-PDF阅读器-论文模式-spec-v1.md`。

## 四件套是什么

| 插件 | 技能 | 视觉验收 Agent | 用途 |
| --- | --- | --- | --- |
| `documents` | `docx` | `visual-judge` | Word 文档创建、编辑、排版、审阅与批注 |
| `pdf` | `pdf` | `visual-judge` | PDF 报告 / 简历 / 海报 / 封面的排版与渲染输出 |
| `presentations` | `pptx` | `visual-judge` | 演示文稿制作 |
| `spreadsheets` | `xlsx` | `visual-judge` | 电子表格制作 |

每个插件各带 1 个 `visual-judge` Agent：**渲染产出必须经逐页视觉验收判定通过才算交付**，这是四件套自带的质量门禁。

## 为什么 fork 进仓库（不再访问上游 CDN）

部署环境是内外网隔离的公司内网。四件套此前以官方市场插件形式下发，市场目录走 `cdn-zcode.z.ai`，断网时会退化为不可用。

现在的做法：

- 四件套内容 **fork 进仓库**（`apps/zcode-cli/packages/{documents,pdf,presentations,spreadsheets}-plugin/`），形态为**纯内容型**插件（无 `package.json`、不进 pnpm workspace）。
- 构建期登记进发布资产清单，启动时 seed 到本地插件缓存，**随安装包分发**。
- **官方市场的 CDN 目录分片默认禁用**：商店只显示随安装包内置的官方插件，不访问 `cdn-zcode.z.ai`。仅当显式设置 `ZCODE_OFFICIAL_PLUGIN_MARKETPLACE=on|1|cdn` 时才恢复 CDN 目录（供公网开发/联调）。
- 插件卡片图标为字母头像回退（不再引用 CDN 图片地址）。
- 已安装的历史 CDN 插件不自动卸载，商店不再显示，可在设置里手动移除。

> **提示**：四件套的加载**不经过市场**——它是本地资产 seed 到本地插件清单，因此与 CDN 开关无关，断网也不受影响。

### 版本一致性（内部约束）

同一插件的版本号在三处必须一致，任一处漂移会导致加载到旧缓存或校验失败。当前四件套均为 `0.1.7`。这一条对使用者不可见，但排查「为什么加载的是旧版」时要先看它。

## 三层能力与分层规则

| 层 | 组成 | 形态 |
| --- | --- | --- |
| 创作层 | 四件套技能 + 视觉验收 Agent | 仓库内置插件，默认启用 |
| 操作层 | 文档解析（`parse_document`）、docx 最小改动手术刀（`docx_patch`）、OCR（`ocr_scan`）、DWG（`dwg_*`）、PDF 研读（`pdf_*`） | 确定性 MCP 工具 |
| 核心层 | 原生工具（读 / 写 / 执行命令 / 子智能体 / 计划 / 工作流） | 不变 |

三条产品规则：

1. **读 vs 创作**：从既有文件抽取文本/Markdown 属**操作层**（单次工具调用、确定性、无脚本依赖）；从无到有产出文档属**创作层**。
2. **docx 写入路径二分**：`docx_patch` 是「确定性小修」的唯一 owner（手术式改字、格式不动）；docx 技能的编辑路线是「结构性大改」的唯一 owner。两者不互相替代，审查的一键修改走 `docx_patch`。
3. **OCR 与 CAD 归操作层**：四件套不得重复建设 OCR / 图纸解析。

## 离线边界（Phase 2）

内网办公环境**全员预装 Office 与 WPS**，系统为中文 Windows（自带宋体/黑体/雅黑）。据此确定的最小依赖策略：

| 依赖 | 处置 | 安装包增量 |
| --- | --- | --- |
| LibreOffice | **不打包**。解析顺序：系统 PATH 的 soffice → 环境变量 `ZCODE_LIBREOFFICE_PATH` / `ZCODE_SKILL_ENGINE_ROOT` 指向的受管引擎 → 报缺失走内网流程 | 0 |
| Python + wheels | 打包便携 Python + 依赖闭包（docx / xlsx / pdf 三线导入全集） | 约 90MB |
| 中日韩字体 | 不打包，用系统字体 | 0 |

### 与上游不同的离线语义

上游的依赖检查策略是「缺失就去公网镜像下载、禁止 WPS 替代」。本仓改为：

- soffice 缺失时的处理顺序：已装但不在 PATH 的先注册 → 由 IT 经内网镜像/基镜像提供，或配置环境变量指向受管引擎 → **不得静默跳过 PDF 导出或视觉检查**。
- 渲染保真度不再由「必须装 LibreOffice」保证，改由**视觉验收 Agent 逐页判定**兜底。
- 依赖检查的提示文案已重写，**公网镜像地址全部移除**。
- 依赖缺失时必须给出**可读的缺失报告**，不得静默降级产出残缺交付物。

### 环境变量契约

| 变量 | 语义 |
| --- | --- |
| `ZCODE_SKILL_ENGINE_ROOT` | 受管引擎根目录（含字体、Python 等） |
| `ZCODE_LIBREOFFICE_PATH` | 指定 soffice 可执行文件 |
| `ZCODE_PYTHON_PATH` | 指定便携 Python |
| `ZCODE_FONT_DIR` | 指定字体目录 |

解析顺序为「显式 env > 受管根布局 > 系统 PATH」。环境检查脚本只认这组契约。

### 已知未完全离线化的部分

- 三平台「干净环境全功能可用」尚未做实机安装验证（只有产物层资产核验）。
- LibreOffice 相关路由（xlsx 重算、docx 转 PDF）需要真实桌面环境或 IT 决策才能完整验收。
- 视觉验收 Agent 的真实逐页调用尚未在桌面端完整跑通。

## 办公公式与字体管线

创作链路的两个排版质量短板已有对应方案并已实施：

- **公式**：主路线改为 **LaTeX → OMML**，产出 Word/PPT **原生可编辑公式**；转换失败时降级为图片或纯文本，并在产出质检里记一条可读告警，**不得静默丢公式**。
- **字体**：字体解析收口为**单一实现**。解析顺序为「受管字体目录 → 显式字体目录 → 系统中日韩字体扫描 → 结构化告警」。明确**不回退到不被支持的字体格式**，也不静默换成默认字体。

> **提示**：内网构建**禁止字体自动下载**。字体只走受管目录或系统字体。

## 文档产出规范：排版令牌的唯一来源

Reactor 自己生成 `.docx` / `.xlsx` 时（审查报告、Markdown 导出），排版只有一处来源：**共享的排版令牌 + 各包内的样式表适配器**。

这条规范解决一个具体问题：报告「丑」往往不是审美问题，而是**排版被交给了读者本机的 Word**——生成时不写样式，同一份报告在不同机器上字体不同、表格列宽由 Word 自动分配决定，长表的窄列被压成竖排。

### 适用范围

| 输出 | 样式表来源 |
| --- | --- |
| 审查报告 `.docx`（横向 A4、七列长表） | 报告侧样式适配器 |
| 审查报告 `.xlsx`（问题清单 + 摘要） | 同上报，列定义同源 |
| Markdown 导出 `.docx`（纵向 A4、流式长文） | 导出侧样式适配器 |

**不在适用范围**：用户提供的文件本身。`docx_patch` 的设计前提就是**保留原文档格式**，只改文本节点；给别人的文件套我们的样式是 bug 而不是功能。

### 令牌内容

排版令牌是纯数据，单位是人的单位（磅 / 毫米 / 倍行距 / 十六进制色），到 OOXML 单位的换算只有一份实现。

- **字体**：标题微软雅黑（西文 Arial）、正文宋体（西文 Times New Roman）、等宽 Consolas；中西文两组都写。
- **字号**：报告标题 18pt、一级标题 14pt、二级标题 12pt、正文 10.5pt（五号）、表格 9pt（小五）、页脚 9pt。
- **颜色**：正文黑、次要信息灰、表头底纹浅灰；严重度用红/橙/灰三档，建议用绿色。
- **表格**：外框 1pt、内线 0.5pt，单元格内边距上下 3pt / 左右 5.4pt。
- **页面**：A4，上下左右留白由令牌给出。

### 样式表结构（生成器只准挑样式名）

1. **文档默认样式**：正文体、10.5pt、1.3 倍行距、段后 6pt。这是地基——不写它，字体字号就由读者本机 Word 决定。
2. **内置样式覆盖**：标题必须覆盖颜色，因为库给内置标题默认带蓝色，中文工程文件里是错的。
3. **自定义样式**：元信息键值、表格三档、注释块、页眉页脚、代码块与引用块；字符样式用于严重度、建议、等宽。

### 验收不变量

文档写一百遍不如一条断言。以下每条都有测试钉住，**绕过样式表就会失败**：

1. 正文、页眉、页脚里每个字符属性**只准**引用样式名；出现直接写死字体/字号/颜色即判定绕过样式表（报告侧连粗体斜体一起禁，Markdown 导出允许粗斜体，因为那是内容语义）。
2. 内置标题不得保留库自带的蓝色，且必须加粗、指定中文字体。
3. 表格固定布局 + 每条列宽与样式表算出的列宽一致 + **列宽之和等于版心宽度**（对不上时 Word 会把表格拉出正文区，这正是窄列竖排的成因）。
4. 表头行有底纹、跨页重复；行不跨页拆分。
5. 页面尺寸与页边距来自令牌；页脚是页码域。
6. 文档属性必须有标题与创建者。
7. **docx 与 xlsx 信息口径一致**：结论状态、核对引用数、库快照、覆盖缺口，两种格式都要有——收报告的人可能只看其中一种。

### 布局规则

- **列数决定纸张方向**：审查报告问题表是 7 列且三列是大段中文，必须横向 A4；Markdown 导出是流式长文，纵向。
- **列宽配比**固定：序号 / 严重度 / 类别 / 位置 / 原文片段 / 问题说明 / 建议，合计 100；xlsx 按同一份配比摊开。
- **元信息排成两列小表**，不排成一串等权正文：眼睛要能直接落到「结论状态」那一行。
- **注释块不提升为标题**：数据边界、免责话术用浅底 + 左竖线的注释块，用标题会让人误以为是章节。
- **颜色只表达「这条要干什么」**：严重度列按值着色、建议列绿色、编号列等宽灰。

### 怎么验收「真的变好看了」

解包看 XML 只能证明属性写对了，证明不了 Word 打开后的样子。视觉验收要真渲染：

```bash
# 1. 生成样张（字段用真实的，不要占位值）
# 2. 逐页渲染成 PNG（同时打印每页尺寸与列宽，作为可复核的证据）
pnpm render:docx <样张.docx> .tmp-render
# 3. 逐页看图判定
```

判定标准（按你能否接受，不看代码）：

- 每个单元格都放得下自己的内容，没有被压成竖排或从词中间断开；
- 表头与表体一眼可分，表头在跨页处重复；
- 标题层级、表格文字、注释块三类信息的字号与灰度分明；
- 颜色只在有语义处出现；
- 正文里不出现 Markdown 记号（报告没有渲染器，会原样印出来）。

## Markdown 导出（Word / PDF / PNG）

预览 Markdown 文件时，工具栏「更多」菜单内有「导出」子菜单，可导出三种格式：

| 格式 | 行为 |
| --- | --- |
| PNG 长图 | 单张 PNG，宽度等于预览正文宽度，**固定浅色白底**；正文过长时提前提示「不建议导出」但不阻止 |
| Word（.docx） | **固定浅色白底**；标题/列表/表格/图片/代码块保留结构；公式与代码块按纯文本降级 |
| PDF | 页面尺寸由导出 HTML 的页面规则决定；固定浅色 |

- **不重新解析 Markdown**：直接用预览区已渲染的 DOM + 运行时样式快照拼装，保证导出与预览像素级一致。
- **本地图片内联**：导出前把本地图片转成内联数据；缺图则报错并中止，**不产出残缺文件**。
- **导出互斥**：同一文件同时只允许一个导出任务，进行中菜单项禁用。
- **失败语义**：任何一步失败都显示明确原因，**不伪造成功**，不留下半成品文件。
- **字体**：只声明中文字体栈，不打包字体；无中文字体的机器上导出可能乱码（已知边缘场景）。

## PDF 阅读器 · 论文模式

打开 PDF 预览时有「论文模式」开关（**默认关**），面向阅读论文 / 标准 / 说明书：

- 侧栏页签：大纲 · 引文；点击跳转页码。
- 选区菜单：复制 / 引用 / 解释 / 翻译；「引用进会话」把页码 + 原文片段写入输入框草稿。
- 抽取与跳转**完全离线**；「总结/翻译」走企业模型出口，模型不可用时给出可读错误而非静默空。

分期与状态：

| 阶段 | 内容 | 状态 |
| --- | --- | --- |
| P0a | 五件离线结构/引文/正文/区域/公式候选 API + 单测 | **已落地** |
| P0b | 阅读器 + 侧栏 + 引用进会话 | **已落地**（「论文模式」开关，与审查定位**互斥**，默认普通预览） |
| P1 | 框选区域翻译/提问增强、图注对齐、摘要卡 | **尚未落地** |
| P2 | 与审查定位互通（同一坐标协议） | **尚未落地** |

> **提示**：公式候选是**启发式**（公式行/图片区），**不是** LaTeX 识别；置信度低时界面标「候选」。

## 验收场景

1. **断网启动**：四个插件加载成功，4 个技能、4 个视觉验收 Agent 可见，无网络报错。
2. **市场降级**：商店只显示内置官方插件，不发起对上游 CDN 的目录请求；显式打开开关后才恢复 CDN 目录。
3. **版本一致**：四件套在插件清单、内置定义、发布资产三处版本一致。
4. **依赖缺失**：干净账户 + 断网下，依赖检查对缺失项给出可读报告而非伪造成功；缺 soffice 时报内网指引而非公网地址。
5. **创作链路**：docx / xlsx / pdf 三条创作链路产出真实文件 → 各自视觉验收判定通过。
6. **排版令牌**：绕过样式表直接写字体字号时，不变量测试失败；列宽之和等于版心宽度。
7. **Markdown 导出**：含本地图片 + 公式 + 代码块 + 表格的 Markdown，PNG/PDF/Word 三种导出均正常；图片被删除时报错并不产出文件；导出进行中再次点击，菜单项禁用。
8. **论文模式**：打开含书签的论文 PDF，大纲层级与页码正确、点击跳转误差 ≤1 页；断网下上述能力全绿。
9. **边界**：加密 PDF、纯扫描件给出明确错误/提示走 OCR，不崩界面。

## 与上游 ZCode 的差异

| 项 | 上游 ZCode | 本说明书 / 本仓 |
| --- | --- | --- |
| 四件套来源 | 官方市场插件，目录走 `cdn-zcode.z.ai` | **fork 进仓库**，随安装包分发，默认禁用 CDN 目录，断网可用 |
| 依赖获取 | 缺失即去公网镜像下载，禁止 WPS 替代 | 走系统已装 / 内网镜像 / 受管引擎；**不得静默降级** |
| 渲染保真 | 由「必须 LibreOffice」保证 | 由**视觉验收 Agent 逐页判定**兜底 |
| 文档产出排版 | — | 排版令牌唯一来源 + 不变量测试；报告横版 A4 七列表 |
| PDF 论文模式 | — | 离线结构/引文抽取 + 侧栏 + 引用进会话 |

**本仓为什么需要它**：内网与公网隔离，任何依赖公网 CDN 或公网镜像的链路都不可用；同时内网用户交付的是**工程文档**，排版一致性与「不能被读者本机字体决定」是硬要求，因此把四件套 fork 进仓库并把排版收口到一份令牌。

> **待核实**：`visual-judge` 逐页判决在真实桌面端的完整端到端调用（含 LibreOffice 路由）尚未执行，当前只有产物层与环境检查层证据。
