# 闲时任务

不是所有任务都需要马上开始。整理一份代码库分析、批量补一轮注释、跑一遍文档同步检查——这类工作晚几个小时拿到结果并不影响什么。

**闲时任务** 就是为这种场景准备的：你提交任务后它进入全局队列，等到算力富余时段自动执行。执行由内网服务端统一调度，客户端不指定时间，也不承诺开始时刻。

和 [定时任务](automations.md) 的区别很清楚：定时任务由你指定时间、可以反复执行；闲时任务不排时间表、只跑一次，什么时候开始由队列决定。

> **提示**：闲时任务入口是否显示、能否创建，由内网服务端下发的配置与资格判定共同决定。如果你的客户端里暂时看不到相关入口，说明该能力尚未对你所在环境下发，不需要做任何操作。

## 使用前提

闲时任务需要满足两个条件，缺一即不可创建：

1. **服务端已下发闲时任务配置**。客户端启动或打开自动化页面时会向服务端拉取一次配置快照，未下发时入口整体不渲染。
2. **资格校验通过**。打开页面时客户端会向服务端查询当前账号的创建资格与取号名额；查询完成前创建按钮保持禁用，查询失败时同样禁入。

界面上的提示与对应处理方式：

| 提示 | 含义 | 处理 |
| --- | --- | --- |
| 暂时无法确认创建资格，请刷新后重试 | 资格查询仍在进行或暂时失败 | 刷新页面或稍后再试，**不代表没有资格** |
| 闲时任务名额已用完，可在 {时间} 后再次创建 | 服务端对取号频率做了限制 | 等提示的时间过去后自动放开 |
| 闲时任务服务暂时不可用，请稍后重试 | 与内网服务端通信失败 | 检查网络与服务端可用性后重试 |
| 闲时任务仅向具备资格的用户开放 | 当前账号不在放行范围内 | 联系管理员确认放行配置 |

> **提示**：客户端会把资格与名额做一次 fail-closed 判定——查询进行中、失败或结果不完整时都不会放行创建，避免依赖异常被吞掉后才在真实提交时报错。真正是否放行以服务端取号结果为准。

## 创建闲时任务

在左侧边栏点击 **自动化**，切到 **闲时任务** 标签，点击 **创建闲时任务**。也可以在自动化首页使用闲时任务模板，点击后会预填好指令带你进入创建页。

表单需要填写：

| 字段 | 说明 |
| --- | --- |
| **任务标题** | 默认为「未命名」，建议改成能一眼认出的名字 |
| **指令** | 任务的全部内容。因为是无人值守执行，指令要尽量完整、自足 |
| **项目** | 只能选当前窗口已打开的本地项目，**创建后不可修改** |
| **权限** | 和会话一样的四档执行模式，默认「变更前确认」 |
| **模型 / 推理强度** | 从闲时任务可用的模型列表中选择，需与当前服务端下发的模型清单一致 |

指令写得越完整，无人值守时跑出来的结果越接近预期——把要分析什么、输出成什么格式、怎么验证都交代清楚。

因为任务在你不盯着的时候执行，**建议先提交一次 Git commit** 再创建任务，这样对结果不满意时可以干净地回退。

> **注意**：闲时执行时无人值守，需要确认的操作会暂停任务直到你响应。界面会提示「建议权限切换为完全访问，以减少任务失败率」，这只是非阻塞建议，不会阻止创建。

## 排队与执行

提交后任务进入 **全局队列**，按创建时间先来先到排，任务卡片上会显示当前排到第几位（如「排队第 3 位」）。

排队期间不用干等：点开任务能核对刚才填的配置，发现写漏了直接改；列表下方的模板也一直可用，随手再排一个进去。

轮到你的任务时它自动开始执行，状态变为「运行中」。整个过程有几个特点：

- 无需你在场：任务在后台跑，你可以继续做别的事，甚至关掉这个项目的会话。
- 长任务接着跑：单次执行有时长上限，到点后任务会回到队列，下次 **接着原来的会话继续**，不会从头再来。应用重启也不会丢。
- 不承诺具体时间：队列取决于整体算力余量，界面不会给出「预计几点开始」这类估算。任务会一直等下去，直到轮到它——如果不想再等，取消即可。

执行期间如果 Agent 遇到需要确认的操作，会像普通会话一样在会话里等你响应，任务状态保持「运行中」。

> **提示**：只查看进度不会产生任何影响，直接点开会话查看即可。确实需要改要求时，把新要求写成一个新的闲时任务重新排队，往往比打断当前任务更划算。

## 管理任务

任务有六种状态：**排队中、已暂停、运行中、已完成、失败、已取消**。

卡片右上角的菜单随状态变化：

| 当前状态 | 可用操作 |
| --- | --- |
| 排队中 | 暂停、删除 |
| 已暂停 | 继续、删除 |
| 运行中 | 取消任务 |
| 已完成 / 失败 / 已取消 | 删除 |

暂停会保留任务但停止派发。需要注意：**暂停时长超过队列等待时限的任务，会被放回队列重新排队**，位次可能因此往后。

「继续」在两个前提下行为不同：票仍有效时只是恢复派发；票已失效时会把任务重新排到队尾，消耗一次新的取号。

任务失败后不会自动重试，你可以检查指令和配置后重新提交一个新任务。已经完成的文件修改在任何情况下都不会自动回滚。取消任务时已修改的文件同样会保留。

### 在侧栏查看

已经开始执行过的闲时任务，会在左侧边栏的 **闲时任务** 分组里出现一行，行尾带月亮标识。点击可以进入对应会话查看 Agent 做了什么。

还在排队和已暂停的任务不会出现在侧栏，它们只在自动化页面管理。

### 运行历史

任务详情页可以在 **设置 / 历史** 之间切换。因为闲时任务只跑一次，历史里最多一条记录，显示指令、触发时间、状态与耗时，并支持跳转到对应会话或删除这条历史记录。

历史记录只是一行可见性标记：删除历史不会删除任务与会话，也不清空执行结果。

## 需要注意的限制

**电脑需要保持运行。** 与定时任务一样，闲时任务在你的电脑上执行。机器睡眠期间不会推进，但也不会因此丢失——恢复后继续排队。如果希望它在夜间跑完，请打开自动化页面的 **保持电脑运行** 开关（也可在「设置 → 保持电脑运行」中修改）。

**创建频率受服务端限制。** 取号名额用完后创建按钮会置灰，鼠标悬停能看到多久之后恢复，到点自动放开。

**只支持本地项目。** 当前版本不支持远程工作区，手机端远程控制界面也不显示自动化相关内容。

> **待核实**：单次执行的时长上限、队列等待时限对应的具体数值未在本说明书中给出；以上游口径描述语义，具体数值由内网服务端下发策略决定。
