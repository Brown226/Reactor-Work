## 4. 用量上报：只报「模型调用」

### 4.1 数据流

```text
Agent 运行时                   客户端 Host                       服务端
────────────                   ───────────                       ──────
用量增量事件  ──►  上报器
                   ├─ 过滤：只有企业 provider 才入队
                   ├─ 队列落盘（追加 / 确认）
                   └─ 冲刷：每批 ≤ 500 条 ─────────────────►  批量上报接口
                      策略缓存  ◄───────────────────────────  策略读取接口
```

### 4.2 事件字段

| 字段 | 来源 | 约束 |
| --- | --- | --- |
| 幂等键 | 流事件的稳定标识（无则退到事件键） | 稳定、可重传；没有幂等键则**不上报** |
| 时间 | 事件时间（ISO8601） | 不得大幅超前 |
| 会话标识 | 任务 / 会话 id | — |
| 动作 | 恒定「模型调用」 | 其他动作类别留给 P4.3 |
| 结果 | 由状态推导：完成 / 错误 / 取消 | — |
| 用量分项 | 输入 / 输出 / 总量；命中缓存的输入 → 缓存读，写入缓存 → 缓存写 | 字段名按服务端用量契约；**推理 token 不进事件**（服务端四段价已含在输出里） |
| 模型 / 供应商 | 模型 id / provider 标识 | — |
| 费用 | **端侧不填** | 服务端按自己的价目表核算 |
| 摘要 | 可空或短标签（如模型 id） | **≤ 200 字**，禁止正文 |
| 归属（用户 / 部门） | **禁止填写** | 服务端按令牌写入；请求体带了直接拒绝 |

### 4.3 入队过滤

必须**同时**满足：

1. 已登录企业服务端；
2. 本次调用命中的 provider 是企业托管条目；
3. 用量分项里至少有一个有效数字（全零的调用不计账，服务端也会当脏数据拒掉）。

**开发者模式旁路不在其中**：解锁开发者模式后直连本地模型的调用不入队、不上报。这是产品既定的口径（报表口径就是「企业网关用量」），不是缺口。

### 4.4 队列与冲刷语义

- **读一批不删 → 上报 → 全批确认**。上报成功但确认前崩溃，重发由服务端的幂等键判重兜住。
- 单批上限 500 条；一次冲刷最多若干批（默认 10 批），避免长时间占住。
- 上报失败**不动队列**，下次重试；队列有上限（默认 5000 条），超出丢最旧并记日志（磁盘有界优先）。
- 触发时机：登录成功、模型回合结束（合并窗口默认 30 秒）、退出前尽力一次、定时兜底（默认 5 分钟）。并发触发会合并成同一次冲刷。
- 网络出口是既有的服务端 HTTP 客户端，用的是**登录令牌**（不是网关令牌）。

> **待核实**：用量增量在客户端的具体取材位置（会话流事件结构）在计划文档里被登记为待确认项，实施时需按实际事件结构对齐——本页只描述已确定的事件形状与过滤条件。

### 4.5 阶段验收（P4.1，端侧接通后逐条走）

- [ ] 企业模型对话一次 → 队列里有条目 → 冲刷 → 服务端能查到该条用量，归属为当前登录用户。
- [ ] 断网对话 → 事件保留 → 恢复网络补传；重放同一批 → 判重数增加，库内不双计。
- [ ] 开发者模式 + 本地模型对话 → 队列**无**新条目。
- [ ] 未登录 → 不出网、队列不新增。
- [ ] 事件体内没有用户 / 部门字段，没有正文字段。

## 5. 桌面策略天花板

### 5.1 模式天花板映射

组织的默认访问模式表示「用户最高能开到哪一档」，用户的会话模式与天花板取**更严**的交集：

| 天花板（组织） | 用户可选 | 效果 |
| --- | --- | --- |
| 仅规划 | 仅「仅规划」 | 只读规划 |
| 可改文件 | 「仅规划」/「可改文件」 | 可改文件，不可随意执行命令 |
| 常规开发 | 「仅规划」/「可改文件」/「常规开发」 | 常规开发 |
| 不限制 | 四档皆可 | 不额外收紧（服务端未配置时的默认） |

命中限制时界面显示「受组织策略限制」，不允许开到天花板之上。

> **提示**：天花板用的是**会话模式四档词表**。旧版本服务端曾使用另一套词表（只读 / 均衡 / 信任 / 严格），P4.2a 已完成切换：写入只写新词，读取时对库内旧值做映射（旧「严格」→ 可改文件、旧「均衡」→ 常规开发、旧「信任」→ 不限制、旧「只读」→ 仅规划）。

### 5.2 策略字段与强制点

| 字段 | 落点 | 行为 | 状态 |
| --- | --- | --- | --- |
| 默认访问模式 | 会话模式解析 / 模式切换 / 会话默认模式 | 取天花板交集；拒绝时提示来源为组织策略 | 未实现 |
| 命令黑名单 | 命令执行类工具的审批闸 | 命中 → 拒绝执行，可选报一条策略拦截事件 | 未实现 |
| 出网白名单 | 与既有出网边界同一处扩展 | 域名后缀匹配；解析失败即拒绝 | 未实现 |
| 额度 | 上报器累计 + 设置页 | 阈值提示；**不拦截**调用 | 未实现 |

域名匹配规则（避免两义）：空名单 = 不限制；写 `example.com` 含子域；写 `*.example.com` 只含子域不含裸域；端口不参与匹配。

### 5.3 策略失败语义（P4.2b 的设计口径）

| 情况 | 行为 |
| --- | --- |
| 未登录 | 不同步、不强制；来源标记为「未知」，视为不限制但界面如实显示 |
| 拉取失败 / 超时 / 形状不对 | **保留**上次策略，标记为「缓存且陈旧」，记警告 |
| 黑名单 / 白名单为空数组 | **不限制**（不是全禁），界面显示「当前未限制」 |
| 策略缺字段 | 按默认策略合并，**不把缺失当清空** |

**禁止**：拉取失败就清空限制；用开发者模式放行策略。

### 5.4 阶段验收（P4.2）

- [ ] 管理台把默认访问模式设为「可改文件」→ 端上刷新策略后无法保持在不限制 / 常规开发，并提示组织限制。
- [ ] 拉取失败时策略不清空，设置页状态显示为「缓存 / 陈旧」。
- [ ] 月度限额达到 80% / 100% 阈值时设置页出现提示，调用**不被拦断**。
- [ ] 库内残留旧词表值时，读入后的行为等于映射档。

### 5.5 强制点补全（P4.3，未实现）

- [ ] 黑名单命令被拒绝，模型能收到可理解的拒绝原因；其它命令不受影响。
- [ ] 白名单外的域名出网被拒；白名单内与空名单行为正确。
- [ ] 与既有的私网 IP 出网限制**双重判定**、互不破坏。

## 6. 已知缺口与有意边界

这些是**有意保留**的边界，写进契约与实现注释，不当缺陷修：

1. **旁路不计量**：开发者模式 + 本地模型可以绕开额度与审计（与模型治理口径一致）。
2. **端上强制可被改码绕过**：策略是治理不是内核级安全；硬保证将来放网关。
3. **流式采集可能漏掉非主回合的模型调用**（如标题生成、压缩）。P4.1 先接受，并在报表口径写「以事件流为准」；若必须全量，后续再在同一事实写入点补采集（**仍禁止上报旁路**）。
4. **额度跨机不汇总端上缓存**：端上进度只是本机视角，权威以管理台为准。
5. **多窗口**：上报器与策略缓存在客户端 Host 内是单例，不走界面层存储通道。

> **待核实**：额度告警的呈现位置（是设置页内的企业服务端分区，还是独立的用量统计分区）在契约里写为「不新增顶级设置分区」，具体落点需按 P4.2b 实现确认。

## 与上游 ZCode 的差异

| 关注点 | 上游 ZCode 官方文档 | 本说明书（本仓） | 原因 |
| --- | --- | --- | --- |
| 计费与额度 | 官方 Coding Plan：周额度、额度重置卡、套餐权益 | 不适用；内网服务端自行计量，额度只告警不阻断 | 内网隔离部署没有公网计费链路 |
| 用量数据来源 | 官方服务端按账号汇总 | **端侧上报**：服务端网关不写审计，管理台用量来自端侧批量上报 | 归属要可追溯，但不把网关变成审计系统 |
| 用量上报范围 | 官方全量计费 | v1 **只报模型调用**；工具调用与审批属后续阶段 | 工具链路的钩子尚未接入，先报最关键的计量项 |
| 隐私边界 | 未特别约束 | 事件只含结构化元数据与用量计数，**正文不落服务端**，摘要 ≤ 200 字短标签 | 服务端红线，也让报表可审计而不可反查会话内容 |
| 旁路口径 | 本地模型直连等同普通用法 | 开发者模式旁路的调用**有意不计量、不上报** | 与模型治理的信任模型一致，是产品既定边界 |
| 策略下发 | 官方无组织级策略天花板 | 组织可下发访问模式天花板、命令黑名单、出网白名单与额度告警线（P4.2b/P4.3 待做） | 企业管理需要统一的权限上限 |
| 策略词表 | 不适用 | 与客户端会话模式**同一四档词表**，不用上游 / 旧项目的另一套词表 | 两端词表不一致会导致天花板无法表达 |
| 落地状态 | 官方能力即产品形态 | 用量采集已实现、策略天花板与强制点**尚未实现** | 本说明书如实标注阶段，不把计划写成现成功能 |
