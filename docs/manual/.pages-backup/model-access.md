# 接入模型

Reactor（数智堆脑）的模型访问统一走**内网模型网关**：由自建服务端（`server/`）提供身份登录与模型出口，客户端不直接连公网模型服务。

本页说明配置入口、企业目录即白名单的语义、本地模型配置的可见性，以及「一键拉取模型」的作用范围。全部结论都可在源码或 `docs/` 契约中核实。

## 接入方式总览

| 方式 | 适用场景 | 配置入口 | 登录态 |
| --- | --- | --- | --- |
| 企业服务端 | 内网标准用法：模型清单由服务端下发，调用走网关并按人归属 | 首启登录页或 **设置 → 企业服务端** | 需要企业账号 |
| 本地模型配置 | 未登录 / 未配置企业服务端时的自建通道，或解锁开发者模式后的旁路 | **设置 → 模型设置** | 不需要 |

企业服务端地址是**身份服务的地址**（例如 `http://192.168.1.10:8791`），网关地址由它推导：同主机、端口换为网关端口、路径为 `/v1`。客户端界面里的「服务端地址」只填身份地址即可。

## 配置入口

### 方式一：首次启动登录页

全新安装首次启动时，登录页就是产品唯一的登录入口，只需三项：

1. 企业账号
2. 密码
3. 服务端地址

登录成功后进入工作区，企业模型清单已自动写入，无需再手工添加。

### 方式二：设置 → 企业服务端

已启动过应用后，从**设置 → 企业服务端**进入同一份表单（登录页与设置页共用同一个组件，字段顺序与地址预填一致）。未登录时显示账号 / 密码 / 服务端地址；已登录时显示当前账号与角色、网关地址、企业模型清单，以及「刷新模型」「退出登录」两个动作。

### 方式三：模型选择器

点击对话框中的模型名称打开模型选择器，在列表底部进入模型设置面板，可管理当前可用的模型通道。**未解锁开发者模式时，「模型设置」不在设置导航中出现**（原因见下节）。

## 企业目录即白名单

企业会话激活（已登录企业服务端）后：

- 聊天里可选的模型 = 该会话从网关目录同步到的**企业模型**；本地其它 provider 的模型不参与选择。
- 模型请求由企业网关统一鉴权与计量（每次请求现场签发令牌），调用可按人归属到账号。
- 只有 chat 板块的模型进入可选清单：embedding / rerank 不是会话模型，混进下拉会让用户选到一发就报错的条目。

| 情况 | 行为 |
| --- | --- |
| 未登录企业服务端 | 不限制模型，本地 provider 正常可用 |
| 已登录但目录为空（同步中 / 失败） | 不限制，也不因目录为空把可选模型清空；面板显示原有状态，可点「刷新模型」重试 |
| 目录同步后被裁掉的模型 | 由既有同步逻辑处理；聊天里选不到即视为不可用 |
| 退出企业登录 | 模型清单清空、provider 条目保留，选择器恢复列出本地 provider 模型 |

> **提示**：模型清单由客户端按网关目录做增量对齐（缺的加、多的删），而不是把清单整体覆写到 provider 配置里。因此手动在本地配置里塞进去的企业模型，会在下一次同步时被对齐掉。

## 本地模型配置与开发者模式

「模型设置」是**本地模型配置界面**，也是一条绕过目录治理的旁路：企业会话下模型清单本该由服务端目录决定，本地那份配置一敞开，白名单就失去意义。因此它的可见性由开发者模式控制。

| 项 | 规则 |
| --- | --- |
| 默认状态 | 隐藏。「企业服务端」分区始终可见，它是被认可的模型来源 |
| 解锁方式 | 在任意一处版本号**连续点击 7 下**（相邻两次间隔超过 1.5 秒即重新计数） |
| 入口数量 | 两个入口各自计数，混点不解锁；必须「在同一处连续点满 7 下」 |
| 当前入口 | 设置 → 外观的「应用信息」行，以及侧栏底部的版本号 |
| 途中反馈 | 连点途中不给进度提示，只在解锁 / 反锁那一刻给结果提示 |
| 反锁收尾 | 正停在「模型设置」页时被反锁或换账号，自动退回「常规」页 |
| 配置留存 | 只隐藏界面，不删除磁盘上的本地 provider 配置 |

解锁后本地 provider 重新可用，但要注意：**这是一条绕过治理的旁路**，不经网关的模型调用没有白名单校验，也没有审计与用量上报。企业模型的鉴权仍走网关，所以审计与用量在网关侧依然成立——本策略约束的是「能选到哪些模型」，不是「调用能否被审计」。

详细的策略与验收场景见[模型治理与开发者模式](model-governance.md)。

## 手工添加内网 provider

未登录企业服务端，或已解锁开发者模式时，可以在**设置 → 模型设置**里手工添加一个兼容 OpenAI / Anthropic 协议的供应商，指向内网模型服务：

1. 进入模型设置面板。
2. 在左侧供应商列表底部点击「添加供应商」。
3. 自定义供应商名称（例如内网网关的别名）。
4. 按协议类型填写接口地址：OpenAI 兼容协议填到 `/v1` 一级，Anthropic 兼容协议填站点根（聊天路径由客户端拼 `/v1/messages`）。
5. 填入 API Key；部分内网网关允许匿名读目录，可以留空后试拉取。
6. 点击「添加模型」手工填写模型 ID，或使用下节的「一键拉取模型」。
7. 开启启用开关后即可在聊天中选择该模型。

## 一键拉取模型

模型设置里的「一键拉取模型」（位于「添加模型」左侧）从供应商的 `/models` 目录一次拉取、多选批量添加。

```text
点击「一键拉取模型」
        │
        ├─ 在后台进程发起请求（不受浏览器同源策略限制）
        │
        ├─ 请求 <base>/models 或 <base>/v1/models（按协议形态选择，404 才换下一个候选）
        │
        └─ 弹出目录窗口 → 勾选 → 逐个添加（走既有的单模型添加路径）
```

语义要点：

| 项 | 说明 |
| --- | --- |
| 请求位置 | 由**持有该供应商配置的那台机器**发出（本地 host 或远程工作区所在机器），不在界面进程里直接发 |
| 参数 | 使用表单里正在编辑的 Base URL、API Key 与协议类型 |
| 鉴权头 | Anthropic 协议用 `x-api-key`；其余用 `Authorization: Bearer`。密钥为空时两个头都不带（便于匿名读内网目录） |
| 候选地址 | 按协议形态选择第一条；**只有 404 才降级到下一条**，鉴权失败直接报错，不换地址 |
| 默认勾选 | 目录中尚未添加的全部模型；已存在的行标「已存在」并禁用勾选 |
| 写入方式 | 逐个 `await` 添加，每次添加都会触发一次配置保存与视图刷新；失败项保持勾选可直接重试 |
| 只读性 | 拉取本身是只读操作，不写配置、不改模型顺序 |

> **提示**：拉取弹窗失败时，已成功添加的模型会保留，弹窗停留在错误态，不会自动关闭。

失败语义：

| 情况 | 表现 |
| --- | --- |
| 未填 Base URL | 直接提示未配置 Base URL，无法拉取模型目录 |
| 401 / 403 | 透出 HTTP 状态码与响应片段，不换候选地址 |
| 两条候选都 404 | 报错 |
| 超时 / 网络错误 | 按钮回到可点状态并给出错误，不会永久停在加载中 |
| 目录为空 | 提示该供应商返回的模型目录为空 |
| 目录全部已添加 | 提示无需重复添加，确认按钮禁用 |

## 单个模型的高级参数

在模型设置里点开某个模型、展开「高级」，可以为这一个模型单独设置**最大输出 Token**（单次回复的长度上限）。默认留空，跟随模型自己支持的上限。

> **提示**：输出空间与历史对话共用同一个上下文，输出上限调得越高，能带上的历史对话就越少，自动压缩也会来得更早。

同一个面板里也能看到模型的**上下文窗口**。企业下发的模型其窗口由服务端统一下发，本地修改会在下一次同步时恢复；名称以 `[1m]` 结尾的模型固定按 1M 上下文处理。

会话的自动上下文压缩会在接近窗口上限前提前触发（系统为模型输出预留空间并保留安全缓冲）。该策略没有界面开关或阈值设置项。压缩口径与兜底值见[常见问题](qa.md)。

## 验证配置

1. 进入**设置 → 企业服务端**，确认显示已登录、账号与网关地址正确，企业模型数量非 0。
2. 回到对话框，在模型选择器中确认能选到企业模型。
3. 发送一句简单指令，确认有正常响应。

若模型清单为空，先点「刷新模型」；仍为空时检查服务端网关是否可达、账号是否被分配了模型可见范围。

## 与上游 ZCode 的差异

- 上游写法：围绕 GLM Coding Plan 讲接入，推荐「连接 Z.ai / 连接 BigModel 账号」或填 API Key。→ 本说明书写法：改为登录**内网自建服务端**，模型统一走企业网关。→ 原因：内网隔离部署，无公网账号与套餐链路。
- 上游写法：给出 BigModel 与 Z.ai 的 Coding 专用端点、通用端点对比，以及 Anthropic 接口的计费限制说明。→ 本说明书写法：全部删除，不写任何公网端点。→ 原因：这些端点与计费规则在本仓不适用。
- 上游写法：免费体验额度、每日 Token 额度表、在应用内订购套餐、团队套餐席位。→ 本说明书写法：全部删除，改为说明企业目录即白名单与目录同步语义。→ 原因：本仓的模型可用范围由服务端目录决定，不由套餐决定。
- 上游写法：「添加供应商」时列举 Anthropic、OpenRouter、Moonshot、OpenAI、MiniMax、小米 MiMo 等公网服务的填法。→ 本说明书写法：只写「添加兼容 OpenAI / Anthropic 协议的内网供应商」通用步骤，不列举公网服务端点。→ 原因：内网场景下供应商由管理员统一维护，公网地址不可达也无意义。
- 上游写法：本地模型配置始终可见。→ 本说明书写法：说明「模型设置」默认隐藏、连点版本号 7 下解锁开发者模式、解锁后进入的是绕过治理的旁路。→ 原因：本仓把本地模型配置视为一条需要显式动作才能进入的旁路。
- 上游写法：用户级路径 `~/.zcode/v2/config.json`。→ 本说明书写法：`~/.reactor/v2/config.json`。→ 原因：用户级目录已收口为 `.reactor`，`ZCODE_*` 环境变量名保持不变。

> **待核实**：内网网关对具体模型（上下文窗口、思考档位、图片支持）的实际能力由服务端目录与供应商配置决定，本页未逐一列举，请以管理台下发的模型清单为准。
