# 项目记忆

有些信息只值得告诉 Agent 一次：你习惯的 commit message 写法、项目用的包管理器、团队的评审约定。**项目记忆**（界面上的「工作区记忆」）为 Reactor Agent 提供项目级的长期记忆，让这类信息延续到后续会话，而不需要每次对话开头都重复交代。

开启后，Reactor 会在每轮对话成功结束后于后台回顾最近的交流，判断是否有值得长期保留的内容——你的偏好、你对 Agent 工作方式的纠正、项目目标与约束、你提供过的外部资料。保存下来的记忆会在同一项目的后续会话中自动带入上下文。

你也可以在对话中直接管理记忆：说「记住，我们从 staging 分支发布」即可立刻保存；说「忘掉刚才说的发布分支」即可删除对应记忆。

> **项目记忆默认关闭**，需要你在设置里主动打开。

## 与 `AGENTS.md` 的区别

项目记忆和项目指令文件 `AGENTS.md` 解决的是同一类需求（让 Agent 记住背景），但分工完全不同。上游文档在同一主题下没有把这两者摆在一起对照，这里补一张表说清楚：

| 对比项 | `AGENTS.md` | 项目记忆 |
| --- | --- | --- |
| **谁来写** | 你手写，或由团队维护后提交 | Agent 自动提炼，你不需要动手 |
| **存在哪** | 项目仓库里，跟着代码走，进 Git | 只存在你本机用户数据目录，不进 Git |
| **适合什么** | 团队约定、编码规范这类需要评审和共享的规则 | 协作过程中积累的零散事实与个人偏好 |
| **作用范围** | 读取用户全局与当前 Workspace 两级 | 按项目隔离，一个工作区学到的不会带到另一个 |
| **生效方式** | 任务启动时读取并注入 | 开关只对新会话生效 |
| **典型例子** | 「提交前必须跑 `pnpm typecheck`」 | 「这个项目习惯用 pnpm」 |

简单判断：**需要团队评审、需要跟代码一起走的内容写进 `AGENTS.md`；只是让 Agent 记住的零散偏好交给项目记忆。** 两者可以同时开启，互不替代。

> **提示**：`AGENTS.md` 的读取规则与路径见 [Reactor Agent](agent.md) 的「项目指令文件」一节。

## 开启项目记忆

打开 **设置 → 记忆**，找到 **工作区记忆** 开关并打开。

关于这个开关有四点需要了解：

- 默认关闭：需要你主动启用，不会在安装后悄悄记录。
- 只对新会话生效：修改设置影响新建会话和应用重启后恢复的会话；进行中的对话保持原有设定。
- 可能增加 Token 用量：开启后，系统会发起额外的模型请求来提取和召回长期记忆。
- 关掉即停用：关闭开关后不再提取与召回，但已经写在磁盘上的文件不会被自动删除。

## 会记住什么

项目记忆聚焦四类信息：

| 类型 | 覆盖内容 | 示例 |
| --- | --- | --- |
| **user** | 你的身份、专长和偏好 | 「习惯用 pnpm 和 Conventional Commits」 |
| **feedback** | 对 Agent 工作方式的纠正或确认 | 「不要顺手修改无关文件里的 lint 报错」 |
| **project** | 项目目标、约束与进展 | 「站点需要保持兼容 Node 20」 |
| **reference** | 你提供过的外部资源 | 「设计规范在团队 Wiki 的某个链接」 |

同样重要的是项目记忆刻意**不记**的内容：代码结构和 Git 历史（Agent 随时可以重新读取）、`AGENTS.md` 里已有的内容，以及只在当前对话内有效的临时信息。

## 工作机制

一轮对话成功结束后，后台流程会回顾最近的交流。如果发现值得保留的信息，就把它写成一个小的 Markdown 事实文件，并更新 `MEMORY.md` 索引；没有则什么都不保存。整个过程发生在你的回合结束之后，不会拖慢对话本身。

需要判断是否值得提取时，会先在后台扫描已有的记忆清单，把现有条目一并交给提取流程，避免重复创建同一条记忆。

每条记忆是一个 Markdown 文件，带 frontmatter 描述名称、一句话摘要和类型；正文写事实本身，可以用 `[[名称]]` 互相链接。`MEMORY.md` 只是索引，每行一条，不放正文。

在同一项目的后续会话里，索引会自动加载进 Agent 的上下文，无需任何手动操作。记忆按**项目隔离**：在一个工作区学到的内容不会带到另一个工作区。

## 记忆存在哪里

记忆是保存在你本机的普通 Markdown 文件，位于用户级数据目录下的 CLI 存储区：

```text
~/.reactor/cli/memories/projects/<项目标识>/memory/
├── MEMORY.md   # 索引，一行一条
└── *.md        # 每条事实一个文件
```

其中 `<项目标识>` 由项目名短横线化和一段哈希组成，用来区分同名项目。目录基址可被 `ZCODE_HOME`、`ZCODE_DATA_BASE_DIR` 或 CLI 配置里的 `storage.dir` 覆盖。

项目记忆**只对本地工作区生效**：远程工作区不参与提取。存储目录为普通文件，你可以随时手动打开、编辑或删除；删除某个项目的记忆目录即可完全重置该项目的记忆。

## 在设置里查看与清理

Reactor 提供 **设置 → 记忆** 下的记忆查看器，可以按工作区浏览已经保存的记忆文件：

| 能力 | 说明 |
| --- | --- |
| **按工作区筛选** | 左侧选择工作区，右侧列出该项目保存的全部记忆文件 |
| **查看内容** | 选中文件即可看到正文；索引文件 `MEMORY.md` 未生成时会标注 |
| **搜索** | 可按记忆文件名搜索，也可按工作区名搜索 |
| **用外部编辑器打开** | 每条记忆右侧提供「用编辑器打开」入口，便于直接改文件 |
| **刷新** | 手动重新读取目录，拿到最新的文件列表 |

两点限制值得先知道：

- **仅本地桌面端可用**。Web 端设置页不提供查看器，会提示「记忆详情仅支持在本地桌面端查看」。
- **单个文件预览有大小上限**。超过 5 MiB 的记忆文件不提供预览，需要直接用编辑器打开。

## 限制与说明

- **默认关闭**：需要按项目的工作流在设置中主动开启。
- **只对新会话生效**：进行中的对话不会中途改变行为。
- **远程工作区不参与**：当前仅对本地工作区执行记忆提取与召回。
- **索引加载有大小上限**：索引过长时会被截断，并在加载内容里给出提示。简短的条目效果最好——自动提取本身也会保持条目精炼。
- **子智能体不读写项目记忆**：它只在主对话里生效。
- **与 MCP memory server 不是一回事**：项目记忆是 Reactor 内置能力，无需任何 MCP 配置即可使用；如果你已在用记忆类 MCP 工具，两者相互独立。

## 与上游 ZCode 的差异

| 项 | 上游写法 | 本说明书写法 | 原因 |
| --- | --- | --- | --- |
| 产品名与用户级路径 | ZCode、`~/.zcode/cli/memories/...` | Reactor（数智堆脑）、`~/.reactor/cli/memories/...` | 用户级数据目录已改为 `.reactor` |
| 与 `AGENTS.md` 的对照 | 只在 Agent 页顺带提一句，Memory 页没有对照表 | 新增「与 `AGENTS.md` 的区别」小节与对照表 | 这两者最容易被混淆，按上游的处理方式读者仍会问「到底写哪个」，本页专门说清楚 |
| 开关位置与名称 | 设置 → 常规 → Memory | 设置 → 记忆 → 工作区记忆 | 本仓设置页分组与词条名称为「记忆 / 工作区记忆」 |
| 能否查看或清除记忆 | 明确写「目前还不能查看或清除记忆」 | 改写为「设置里有记忆查看器，可按工作区浏览、搜索、用编辑器打开；单文件预览上限 5 MiB」 | 本仓已提供记忆查看器，上游结论在本仓不成立 |
| 记忆类型名 | 用中文字段名描述四类 | 同时给出 `user` / `feedback` / `project` / `reference` 枚举值与中文说明 | 便于与磁盘上的 frontmatter 对齐 |
| 版本要求 | 写「需要 ZCode v3.6.4 及以上版本」 | 删除该版本门槛 | 版本号属上游发布信息，本说明书不据此判断可用性 |
| 套餐与非任务内容 | 涉及套餐、额度、社群的表述 | 已删除 | 与内网隔离部署无关 |
