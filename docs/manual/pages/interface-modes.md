# 界面模式（编程 / 办公 / 审查）

Reactor 用「界面模式」表达**你这次想怎么用 Agent**：编程档面向代码与工程操作，办公档面向文档与办公产物，审查档面向「把文件交给我来审」。这一页说明三档的取值与默认值、改档位的入口、每个入口的显示规则，以及每一档会**收起哪些编程向界面**。

依据：`docs/已完成/已完成-interface-mode.md`（三档契约）。界面模式是本仓特有功能，上游 ZCode 官方文档没有对应写法。

> **相关页面**：审查档的具体能力见[文件审查板块](review-panel.md)；改档位会用到的键位见[快捷键表](keyboard-shortcuts.md)。

## 三档取值与默认值

| 档位 | 取值 | 面向的场景 | 界面上收起的编程向内容 |
| --- | --- | --- | --- |
| 编程模式 | `coding`（**默认**） | 写代码、跑命令、看 diff 与终端 | 不收起 |
| 办公模式 | `office` | 写文档、做表格、产出办公产物 | 终端、Git 变更面板、命令详情、代码 diff 等 |
| 审查模式 | `review` | 审文件：校对、一致性、以文审文、合同风险、标准引用自检 | 同办公模式；草稿首页另换成审查类型卡片 |

「办公」与「审查」都不等于「编程」，且**两者都要求收纳编程向界面**。这条判断是后面所有「该不该隐藏某块界面」的分界线。

## 状态所有者与持久化

界面模式只有**一份状态**，由 UI 层的 `interfaceMode` 字段拥有（`packages/ui/src/store/index.ts`），别无第二处定义，也没有服务端事实。

| 关注点 | 值 |
| --- | --- |
| 唯一写入口 | `setInterfaceMode(mode)`：内部先归一化，再写状态 |
| 持久化 | 浏览器 localStorage，键 `zcode-interface-mode` |
| 取值 | `"coding"` / `"office"` / `"review"` |
| 默认值 | `"coding"` |
| 旧值迁移 | 旧值 `"general"` / `"concise"` 归一为 `"office"`；其余未知值一律归一为 `"coding"` |
| 多窗口同步 | 该字段在跨窗口广播白名单内，一个窗口改档，另一个窗口跟随 |

**旧值迁移为什么要保留**：改名前的存量为 `"general"` / `"concise"`，如果直接按「未知值 → 编程档」处理，这些用户升级后会被静默改成编程模式、以为自己的选择丢了。因此归一化函数把这两个旧值映射到办公档。

所有入口都只读同一字段、只调同一个 setter；不存在「主面板这份是临时预览」之类的局部副本。

## 入口

| 入口 | 位置 | 形态 | 说明 |
| --- | --- | --- | --- |
| **主面板胶囊（唯一可用入口）** | 会话草稿首页 | 三档胶囊分段切换 | 见「主面板入口的显示规则」 |
| 首次引导 | 首次引导问卷 | 单选，**只有两档** | 只问「编程 / 办公」；不选就沿用当前值 |
| 快捷键（遗留） | 快捷键表 | `CmdOrCtrl+Shift+U` | **已注册但无执行侧**，按下不生效，不作为可用入口 |

**设置页的「界面模式」行与账户菜单的「界面模式」子菜单已经删除**：主面板已有显式入口，这两处设置入口与它重复，只会让你以为存在两份状态。新增相关设置项时不要再引回第二个交互入口。

> **提示**：快捷键 `CmdOrCtrl+Shift+U` 在命令表里仍然登记（用于保留注册与冲突检测），但没有任何执行侧；它在用户可见的快捷键列表里也被过滤掉。当前**只有主面板胶囊能改界面模式**。

## 主面板入口的显示规则

- **只在草稿态空态显示**：与问候语同属会话空态节点，排在问候语之后、输入卡之前。
- **一旦会话产生消息就随之消失**，不与工具输出、终端争注意力；切回空草稿首页时重新出现。
- 桌面端与手机远控共用同一个会话面板组件，因此两端显示同一控件，不按平台分叉。
- 三档图标与首次引导的模式选项**同源**（`coding` / `office` / `review` 各一个图标），保证同一模式在全应用只有一套视觉标识。
- 文案复用同一组 i18n 键（`settings.interfaceMode.coding` / `.office` / `.review`），不新增同义词。
- 用大号胶囊（`lg`），与设置页里的密集分段（`sm`）区分：主面板是入口，不是密集设置项。
- 三个档位同宽/等宽分布，不得因新增一档让胶囊在窄窗口里溢出。

## 收敛判据：三个派生判断

展示层不从「是不是办公档」这一个布尔值推导所有行为，而是拆成三条只读判断：

| 判断 | 语义 | 用途 |
| --- | --- | --- |
| `useIsFocusedMode()` | `office \|\| review` | **收敛判据**：隐藏终端、Git 变更面板、命令详情、代码 diff |
| `useIsOfficeMode()` | `office` | **仅**办公档独有行为（插件推荐排序、主动推荐开关、办公问候语） |
| `useIsReviewMode()` | `review` | 审查档独有行为（审查类型卡片、审查问候语） |

**改动纪律**：原来按「办公档」判断的分支必须**逐个归类**，不许整批换成收敛判据。整批替换会把「办公档独有的推荐排序」错误地套到审查档上；反过来只改一半，审查档就会漏掉每一处隐藏逻辑。

## 首次引导为什么刻意只有两档

首次引导是**产品定位问卷**（「你希望怎么用」），不是档位选择器。把「审查」塞进引导，会让一次性问卷承担功能导航的职责。因此：

- 引导里只出现「编程 / 办公」两项；不选则落在编程档。
- 审查档**只能从主面板胶囊进入**。
- 引导记录的档位类型固定为两值，写入时把已停留的审查档按最近语义收窄为办公档，**不为此扩宽引导记录的字段定义**。
- 停在审查档时打开引导：引导内不出现第三档；引导保存后也不会把审查档改写成办公档。

## 验收场景

1. 主面板点「办公模式」：胶囊高亮切换；刷新或重启后选择保持。
2. 设置页与账户菜单里都**不再出现**界面模式选项，只有主面板胶囊能改它。
3. 会话进行中主面板不出现该胶囊；切回空草稿首页时重新出现。
4. 从旧版本升级（localStorage 存 `"general"` / `"concise"`）仍落在办公模式，不被重置为编程模式。
5. 胶囊出现三档；点「审查」后高亮第三档，刷新后仍停在审查档。
6. 审查档下草稿空态显示**审查类型卡片**，不显示编程/办公的推荐语料；切回办公档恢复推荐语料。
7. 审查档下 Git 面板、终端、命令详情、代码 diff 均不出现；切回编程档全部恢复。
8. 首次引导仍只出现「编程 / 办公」两项；在引导里选完后若再切到审查档，重启后落在审查档。
9. 办公档现有行为零回归：插件推荐排序、主动推荐开关、办公问候语均不受影响。
10. 审查档问候语为「把文件交给我来审」，句首同样带登录用户名。
11. 审查类型卡片固定显示全部 5 类，**不受办公档「主动推荐」开关影响，也没有「换一批」**（它是菜单，不是推荐池）。
12. 点任一审查类型卡片 → 提示词填入输入框（不自动发送），你可以再补一句或直接发送。
13. 快捷键 `CmdOrCtrl+Shift+U` 当前无执行侧，不作为验收项。

## 与上游 ZCode 的差异

| 项 | 上游 ZCode | 本说明书 / 本仓 |
| --- | --- | --- |
| 界面模式 | **上游无此能力** | 三档 `coding` / `office` / `review`，主面板胶囊切换，localStorage 键 `zcode-interface-mode` |
| 改档位入口 | — | 仅主面板胶囊；设置页与账户菜单入口已删除 |
| 首次引导 | — | 刻意只记「编程 / 办公」两档，审查档只能从主面板进入 |
| 键盘切换 | — | `CmdOrCtrl+Shift+U` 已注册但无执行侧，当前不可用 |

**本仓为什么需要它**：内网部署的用户不只是写代码的人，还有大量「把 Agent 当文档助手」的办公与审查场景。上游的单一界面把终端、Git、命令详情、代码 diff 全部铺在同一屏，对审查/办公用户是噪音；界面模式把「这次要做什么」显式化，并让收敛逻辑有唯一判据可依。

> **待核实**：首次引导在两档与审查档之间的交互细节（例如引导记录返回后是否需要额外刷新界面）以 `docs/已完成/已完成-interface-mode.md` 第 7 节验收场景为准，本页只转述结论，未逐条复现。
