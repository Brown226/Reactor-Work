# 数据目录与背景主题契约

这一页讲两件与「你的机器上到底发生了什么」直接相关的事：

1. **数据目录**：Reactor 把用户级数据放在哪、工作区级配置放在哪、两者边界怎么判、有哪些显式覆盖项，以及遇到旧目录时的失败语义。
2. **背景主题**：整个工作区窗口的背景怎么配置、参数范围与默认值、持久化在哪、自定义图片的边界。

依据：`docs/已完成/已完成-data-directory-contract.md`、`docs/已完成/已完成-appearance-background-theme.md`。

> **相关页面**：安装与数据目录覆盖项见[安装与部署](install.md)；本仓与上游的路径差异汇总见[与上游 ZCode 的差异](upstream-diff.md)。

## 数据目录：两族目录，边界明确

Reactor 使用**两族**目录，判定方法只有一个——**看基目录是谁**。

| 族 | 用途 | 写法 | 例子 |
| --- | --- | --- | --- |
| **用户级** | 会话、凭据、模型配置、主题偏好、知识缓存、CLI 日志等 | `~/.reactor` | `~/.reactor/v2/setting.json`、`~/.reactor/cli/config.json`、`~/.reactor/skills/` |
| **工作区级** | 项目配置的产品语义 | `<repo>/.zcode`（**保持不变**） | `<repo>/.zcode/config.json`、`.zcode/skills/`、`.zcode/agents/`、`.zcode/workflows/`、`.zcode/plans/` |

判定方法：

- 基目录是「用户主目录 / 数据基目录 / 存储根」→ **用户级**，用 `~/.reactor`。
- 基目录是「工作目录 / 工作区根 / 当前目录」→ **工作区级**，保持 `.zcode`。

> **提示**：这是一条最容易搞混的约定。**用户级目录名已改，现在是 `~/.reactor`；工作区级仍然叫 `.zcode`，没有改。** 如果你的项目目录里看到 `.zcode/`，那是正常的项目配置目录。

### 唯一所有者

用户级目录名由**一个常量**拥有，全仓没有第二处字面量定义（少数刻意不依赖共享包的内部包各有一份**同值**副本，改名时必须同步）。因此改目录名只需改这几处常量值，全仓用户级路径自动跟随。

### 允许的显式覆盖项（优先级高于默认）

以下环境变量/配置是**你显式指定**的，必须优先于默认目录；只在它们缺席时才回落到默认值：

| 覆盖项 | 语义 |
| --- | --- |
| `ZCODE_DATA_BASE_DIR` | 指定数据基目录；用户数据根 = `{数据基目录}/.reactor` |
| `ZCODE_HOME` | 直接指定用户数据根（不再拼接目录名） |
| `ZCODE_STORAGE_DIR` | 同上，等价写法 |
| CLI 用户配置里的 `storage.dir` | 同上，配置形态 |

覆盖项优先级的顺序是：**运行时显式设置 > 环境变量 > 用户主目录**。

> **注意**：CLI 的默认配置里的存储路径与「读不到配置时的兜底值」**必须是同一个值**——一处是默认配置，一处是兜底，两者分叉会导致「配置说一个目录、实际写另一个目录」。这是内部一致性约束，排查「数据写到别处」时先看它。

### 跨工具约定目录（保持原样）

以下位置**不是** Reactor 的数据目录，而是跨工具约定或第三方位置，不受上面那条约定管辖：

- `~/.agents/` 与 `<repo>/.agents/`（AGENTS.md 生态的兼容目录）
- `~/.claude/`（Hooks 的兼容来源）
- `.zcodeignore`、`.zcode-plugin/`、`.zcode-share/`、`.zcode/workflow-drafts/`（文件名或工作区目录，不是用户数据根）
- 官方版应用自身的 Electron 数据目录——只作为**导入来源**被读取，**不写入**

### 知识缓存目录

文件审查板块的知识缓存（标准清单 / 术语白名单 / 规范库）落在用户级目录下的知识子目录：

```text
~/.reactor/knowledge/
  ├─ standards.json        标准规范清单索引
  ├─ terminology.json      术语白名单
  ├─ rule-libraries.json   规范库条目
  └─ review-text/          审查时落盘的正文快照
```

`REACTOR_KNOWLEDGE_DIR` 可覆盖该目录（测试与多环境隔离用）。写入方是端侧同步服务，读取方是 Agent 的知识自检工具——**两边必须解析出同一个目录**，否则会表现为「同步下来了但工具说缓存为空」。

## 失败语义

- **目录不存在 = 合理空状态，不是错误**。用「文件不存在」错误判定，不做存在性预检（预检会引入竞态，也会阻塞服务线程）。
- **不迁移旧数据目录**：本产品**不做数据迁移**，官方版留下的数据目录保持原样、不被写入。两个产品在同一台机器上并存互不干扰，这是**目标**而不是副作用。
- 同步失败时**保留上一份可用缓存**：网络抖动不该让审查失去依据。

### 有意保留（不要当漏改处理）

| 位置 | 为什么保留 |
| --- | --- |
| 工作区内所有 `.zcode` | 项目配置语义，不是用户数据 |
| 从官方版导入旧 MCP 配置的来源目录 | 改掉等于废掉该功能 |
| 安装脚本里的安装树目录 | 是**安装树**而非用户数据；迁移需要先决定目录名并处理已安装脚本的指向，属独立决策 |
| `~/.agents/**` | 跨工具约定目录 |

## 背景主题

「背景主题」给**整个工作区窗口**铺一层背景（左侧栏与主区域共享同一层垫底），并可调两个参数。

| 参数 | 取值 | 默认 | 语义 |
| --- | --- | --- | --- |
| 预置 | 不使用 / 薄雾 / 天空 / 黄昏 / 沙丘 / 玄武（6 项） | **不使用**（即关闭本特性） | 选择一项即启用背景 |
| 自定义图片 | 桌面端自选一张图片 | 无 | 非空时**优先于预置**；与预置互斥 |
| 模糊 | 0–32px | 10px | 背景层的高斯模糊半径 |
| 覆盖色 | 40–100% | 60% | 用当前主题底色压在图上的比例；越高文字越清晰、背景越淡 |

### 有意的边界

- **侧栏与主区域都在背景之上**：两者各自用同一档半透明底板把背景透出来，因此侧栏不是一块纯色面板，而是「泡」在背景里的半透明面。
- **卡片与输入框保持不透明**：正文对比度由它们兜底；设置页与弹窗本身不在半透明作用域内。
- **覆盖色下限 40%**：背景是图片/渐变，无法逐像素校验正文对比度，用下限兜底；上限 100% 等价于「看不见背景」。
- **空状态水印在背景开启时隐藏**：避免水印叠在背景上。
- **预置是「图」不是「淡色底」**：色彩饱和度按「图」的标准给足。
- **不做自动配色**：本特性只改背景，**不派生品牌色/主题色**（颜色主题是独立议题）。

### 自定义图片（仅桌面端）

- **入口**：外观页背景卡片网格里的「上传图片」/「更换图片」卡片，卡片右上角可移除。**仅当平台支持选择文件路径时**才渲染该入口（Web / 手机远控不出现）。
- **选文件**：走系统原生选择对话框 → 按扩展名校验（PNG / JPG / JPEG / WebP / GIF / BMP / AVIF），不支持的格式就地提示，**不写入状态**。
- **读取**：按路径读取媒体预览，转成内联数据写入背景变量。
- **持久化的是路径，不是图片数据**：路径落本地存储，每次启动重新读一次；读取结果是一份内存运行态。
- **失败语义**：文件被移动/删除、超过体积上限（8MB）、格式不支持时，背景**回落为预置**，外观页显示一行本地化提示；日志留有原因。**不弹窗、不阻塞**。
- **互斥规则**：点任一预置卡片 = 放弃自定义图片；点「不使用背景」同理。

### 单一事实源与状态所有者

| 关注点 | 角色 |
| --- | --- |
| 取值定义、预置渐变、归一化、CSS 变量 | 一份库模块 |
| 状态切片（载入 / 落盘 / 应用 / 广播还原） | 一份 store 切片 |
| 渲染层 | 样式表 + 工作区外壳的层标记 |
| 设置界面 | 外观页的背景主题区 |

- **唯一所有者**是这一份背景主题状态。
- **持久化只有一条路径**：合并 → 归一化 → 写本地存储 → 应用到文档根。设置页与跨窗口广播都走它，不存在第二条写入通道。
- **存储键**为 `zcode-background-theme`；该字段也在跨窗口广播白名单内，多窗口通过广播同步（收到广播时缺字段保留当前值）。

### 渲染契约

```text
文档根 html
  ├─ data-app-background            ← 开关
  ├─ --app-background-image         ← 背景图取值，关闭时为 none
  ├─ --app-background-blur / -scrim ← 两个参数
  └─ --app-background-base          ← 主题底色字面值（各主题各一份）
```

- 背景画在**窗口根容器**上：整窗铺底，侧栏与主区域都在它上面。
- 工作区外壳把底色覆盖成「主题底色按覆盖色比例混出的半透明色」；外壳内的各面板继续用同一档混合色画自己，因此**自动**获得同一层半透明，不需要逐组件改样式。
- **模糊只作用在背景层上**，不影响任何界面内容。

### 未做（后续）

- **视频背景**：性能、动效规范与移动端都另有成本。
- **从背景图派生配色**：属「颜色主题」议题，本次明确不做。
- **预置换成真实照片**：需要可商用授权的图片素材；当前预置是跟随主题的渐变合成。

## 验收场景

1. `~/.reactor/` 下出现用户级数据（会话、配置、凭据等），且**官方版自己的数据目录不被写入**。
2. 工作区内的 `.zcode/` 配置仍按项目语义生效，未被改名。
3. 设置 `ZCODE_DATA_BASE_DIR`（或 `ZCODE_HOME` / `ZCODE_STORAGE_DIR`）后，用户级数据落到指定位置。
4. 外观页出现「背景主题」区：不使用背景 + 5 个预置卡片 + 模糊/覆盖色两个滑块。
5. 选任一预置：整个工作区（含左侧栏）透出背景，设置页/弹窗/卡片底色不变，正文可读。
6. 拖动模糊滑块背景实时变柔和；拖动覆盖色背景实时变淡/变浓。
7. 选「不使用背景」：背景层消失，主区域回到纯色，界面无其它差异。
8. 重启应用：选择被记住，背景按上次的预置与参数恢复。
9. 开两个窗口：在一个窗口切换背景，另一个窗口同步跟随。
10. 背景开启时，空状态水印不显示。
11. 桌面端点「上传图片」→ 选一张 PNG/JPG：整窗换成该图；重启后仍然生效。
12. 把已选图片改名/删除后重启：背景回落为预置，外观页显示读取失败提示；卡片仍可重新选图；可清除自定义图片。
13. 选一张非图片（如 .txt）或超过 8MB 的图片：分别提示格式不支持 / 读取失败，**状态不被写入**。
14. Web 端不出现「上传图片」卡片。

## 与上游 ZCode 的差异

| 项 | 上游 ZCode | 本说明书 / 本仓 |
| --- | --- | --- |
| 用户级数据目录 | `~/.zcode` | **`~/.reactor`**（工作区级 `.zcode` 不变） |
| 与官方版共存 | — | 不删、不迁官方版数据，两者并存互不干扰 |
| 覆盖项 | — | `ZCODE_DATA_BASE_DIR` / `ZCODE_HOME` / `ZCODE_STORAGE_DIR` / `storage.dir` 优先于默认 |
| 背景主题 | **上游无此能力** | 整窗背景层 + 预置/自定义图片 + 模糊/覆盖色两个参数 |
| 主题派生配色 | — | 明确**不做**：只改背景，不派生品牌色 |

**本仓为什么需要它**：内网机器上往往**同时装着官方版与本仓版本**，用户级目录必须分开，否则两份产品互相覆盖会话与凭据；同时「不迁移、不删除官方数据」让切换产品不需要备份动作。背景主题则是内网长时办公场景下的可用性偏好，且被刻意收窄为「只改背景」以免与颜色主题、设计规范冲突。

> **待核实**：`~/.reactor/knowledge/review-text/` 正文快照的生命周期（无清理策略与容量上限）在流程问题清单里登记为待决项，当前尚未定 TTL 与容量策略。
