# 手机远控

手机远控用来把当前 Reactor 桌面窗口临时开放给手机访问。扫码之后，你可以在手机上查看和切换这个窗口里已经打开的工作区、任务和会话，继续给 Agent 发指令。

手机端是一层控制界面：它不同步代码，也不新建运行环境。你在上面发出的每一条指令，都由桌面端那个工作区原本连着的机器去执行。

## 适合什么场景

- 任务已经在桌面端跑起来，需要离开电脑后继续看进度。
- 临时收到问题反馈，需要用手机快速追加一条指令。
- 长任务执行中，需要随时检查 Agent 当前状态。

## 手机扫码连接

在 Reactor 左下角侧栏点击手机图标，打开 **移动端远程控制**。

弹窗左侧生成二维码和连接地址，用手机扫码，或者复制链接在手机浏览器里打开。

连接成功后，手机端接入的是**整个桌面窗口**，而不只是扫码时停留的那个工作区。

## 手机端能做什么

### 任务首页

进来先看到的是这个窗口里的工作区和任务。你可以：

- 按 工作区 或 时间线 两种方式组织任务。
- 按 创建时间 或 更新时间 排序。
- 刷新列表，拿到桌面端的最新状态。
- 在已有工作区里新建任务。
- 对显示为「未连接」的远程工作区发起 **重新连接**。

每个工作区会标出它的类型——本地、远程或对话，任务右侧则是运行状态。

### 会话页

点进任务就是会话界面。Agent 的回复、执行过程和进度都在这里，你可以直接在底部输入框补充需求让它继续。会话满足条件时还可以分叉。

> 同一时间只支持一个手机页面连接。如果已经在别的页面打开过，需要先关掉旧页面。

## 命令在哪台机器上执行

手机端只是控制界面，本身不创建任何运行环境。实际执行的位置，取决于桌面端那个工作区当初是怎么连的：

| 工作区类型 | 代码和命令在哪执行 |
| --- | --- |
| 本地 | 你的桌面电脑 |
| SSH | 对应的远程主机 |
| WSL | 对应的 WSL 发行版 |
| Docker | 对应的容器 |

换句话说，手机不会另外建立远程连接，它只是把指令转交给桌面端已经建好的那条通路。

## 它与桌面端的实时链路并不相同

这是本仓的一条架构约束，值得单独说明：**桌面端与手机端看到同一份会话事实，但交付方式不同。**

| 端 | 链路语义 | 交付方式 |
| --- | --- | --- |
| 桌面端 | `desktop-continuous` | 直连实时流，逐帧连续推进 |
| 手机 / Web 远端 | `web-remote-replayable` | 快照 + 断档修复（gap repair） |

两条链路**共用同一状态所有者与同一事件序列**，区别只在交付语义：桌面端消费连续流，手机端以快照为基线、出现断档时按序列补齐。因此在修改流、快照、队列或重连逻辑时，两种语义必须同时验证——只按其中一条路径判断会破坏另一条。

另外，手机端**不另起 Agent、Local Host 或远程会话**：它接入的是桌面端已经存在的 Host attachment，复用同一份会话运行时。手机上的操作因此不会与桌面端产生第二套运行环境。

## 停止与安全

连接地址本身就带远控授权，拿到它就能操作你的窗口，所以有几点需要留意。

**关闭弹窗不会停止远控。** 用完之后要点 **停止** 才真正结束这次连接。

**怀疑地址外泄就刷新二维码。** 刷新会让之前复制或扫过的地址立即失效，已连上的手机需要重新扫码。

**不要公开发布或转发连接地址。** 它等同于一把临时钥匙。

另外，远控期间桌面端需要保持运行和联网，桌面端一旦断开或窗口关闭，手机端就无法继续。

## 常见问题

### 手机能新建或连接远程工作区吗？

不能创建全新的 SSH、WSL 或 Docker 连接——填写连接参数这一步必须在桌面端完成。但如果某个远程工作区已经登记在当前窗口里、只是暂时断开了，手机端可以对它发起重新连接，实际的连接过程仍然由桌面端执行。

### 手机能打开桌面端没开过的项目吗？

不能。手机端只能访问当前桌面窗口里已经打开或登记过的工作区，不能浏览这台机器上的任意目录，也不能连到窗口之外的环境。

### 手机端能触发浏览器自动化或电脑控制吗？

不能。这两项能力依赖桌面端的本机环境与内置浏览器面板，手机端不提供入口。

> **待核实**：手机端与桌面端在**同一任务上的并发写入**如何仲裁（例如两端同时追加指令时的顺序保证），本说明书未在源码中确认，请在部署与培训时以实际行为为准。
