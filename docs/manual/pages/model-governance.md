# 模型治理与开发者模式

内网部署下，Agent 能用哪些模型由**企业服务端的模型目录**决定；而本地的模型配置界面是一条会绕过这套治理的旁路，因此默认被**藏起来**，只有显式进入「开发者模式」才解锁。

这一页说明两条策略的规则与边界：**本地模型配置界面默认隐藏**（连点版本号 7 下解锁），以及**企业目录即白名单**。另外说明「一键拉取模型」这一添加模型入口的语义边界。

依据：`docs/已完成/已完成-model-governance-and-dev-mode.md`、`docs/已完成/已完成-model-provider-catalog-pull.md`。

> **相关页面**：模型接入的整体方式见[接入模型](model-access.md)；内网服务端与策略下发见[服务端总览与接线](server-overview.md)。

## 两条策略一句话说清

| 策略 | 规则 |
| --- | --- |
| 本地模型配置界面 | **默认隐藏**；任意一处版本号连续点击 7 下解锁（相邻两次间隔超过 1.5 秒即归零重数） |
| 模型目录即白名单 | 企业会话激活时，聊天里可选的模型 = **该会话从服务端目录同步到的企业模型**；本地其它 provider 的模型不参与选择 |

两条策略的关系：**后者是治理，前者之所以要藏，正是因为它绕过前者。** 两条均已落地。

## 开发者模式

### 默认状态与解锁方式

- **默认隐藏**：设置导航里的「模型设置」在未解锁时不出现。
- **「企业服务端」始终可见**：它是被认可的模型来源（登录 / 状态 / 刷新模型 / 退出）。
- **解锁方式**：任意一处版本号**连续点击 7 下**；相邻两次点击间隔超过 1.5 秒即归零重数。

### 两个入口，各数各的

当前版本号落在两处：

1. **设置 → 外观**的「应用信息」行（版本号）。
2. **侧栏底部**的版本号。

**每个入口有自己的计数器，混点不解锁**：「在一处连续点 7 下」是唯一能自我验证的操作，在 A 处点 4 下、B 处点 3 下不会解锁。

> **提示**：为什么不做「设置 → 关于」入口——该版本的「关于」是原生对话框，无法挂手势；帮助菜单项也不可用（选中即关菜单，1.5 秒窗口内点不满 7 下）。

### 交互细节

- **途中不给进度**：连点过程中**不显示**「再点 N 下」的进度提示；只有真正解锁/反锁那一刻给一行结果提示（隐藏入口的进度条等于把后门画在门上）。
- **反锁要收尾**：再次连点 7 下即反锁；如果当时正停在「模型设置」页，会自动退回「常规」页，不留空白内容区。
- **只藏界面不删配置**：反锁后本地 provider 配置**仍然留在磁盘上**，只是界面不再显示。
- **不跨窗口广播**：开发者模式是纯本地的调试开关，窗口之间不同步；不写入用户配置、不上报。

## 企业目录即白名单

- **企业会话激活**（已登录企业服务端）时，聊天里可选的模型 = 该会话从网关目录同步到的**企业模型**；本地其它 provider 的模型不参与选择。
- **未登录 / 未配置企业服务端**时**不做限制**：本地 provider 正常可用（个人版 / 离线场景）。
- **开发者模式解锁 = 旁路**：解锁后本地 provider 重新可用。这是一条**绕过治理的旁路**——不经网关的模型调用没有白名单校验，也没有相应的审计与用量上报。
- **企业模型的鉴权仍走网关**：每次请求现场签发令牌，因此审计与用量在网关侧依然成立。本策略约束的是「**能选到哪些模型**」，不是「调用能否被审计」。

### 判定输入只有两个

模型过滤只在**一处**实现，输入只有：

1. 是否解锁开发者模式；
2. 企业会话是否激活且目录非空。

不读其它状态，避免出现第二套「当前是否企业模式」的判断。

### 失败语义

| 情况 | 行为 |
| --- | --- |
| 未登录企业服务端 | 不限制模型（本地 provider 全量）；「模型设置」仍按开发者模式隐藏策略处理 |
| 已登录但目录为空（同步中/失败） | **不限制**，并在企业服务端面板显示原有状态；不因目录为空把可选模型清空 |
| 目录同步后被裁掉的模型 | 由既有的模型协调逻辑处理；聊天里选不到即视为不可用 |
| 反锁时正停在「模型设置」 | 退回「常规」页 |
| 过滤后一个模型都不剩 | **回退为不过滤**——不把选择器清空，否则你会看到一个空菜单却不知道发生了什么 |

## 一键拉取模型目录

设置 → 模型配置里，每个供应商卡片上有「一键拉取模型」按钮（在「添加模型」左侧）。它从供应商的 `/models` 目录一次拉取、多选批量添加。

### 语义边界（重要）

- **拉取是只读操作**：不写个人配置、不进模型注册表、不改模型顺序。
- **「添加」永远走已有的单模型添加路径**：因此不会出现第二套写入语义或版本竞争处理。
- **默认勾选 = 目录中尚未添加的全部模型**；已存在的行禁用勾选并标「已存在」。
- **确认后逐个等待添加**：每次添加都会触发一次配置保存与视图刷新，所以**不并发提交**（并发会互相覆盖个人配置版本）。
- **中途失败**：已成功的保留，弹窗停留在错误态，不再自动关闭；**失败的项保持勾选**，可直接重试。
- 拉取与批量添加共用一把忙碌锁，重复点击不会并发拉取或重复提交同一批 ID。

### 请求契约

| 项 | 值 |
| --- | --- |
| 参数 | 请求地址（与聊天请求同一份表单值）、API 密钥（表单中正在编辑的值，回落已保存的凭据）、接口类型 |
| 请求发起方 | **由持有该供应商配置的那台机器发出**；远程工作区走同一条通道 |
| 候选地址 | 按接口类型有两条候选，**只在 404 时**降级到下一条；鉴权失败直接报错（换地址同样失败） |
| 鉴权头 | 按接口类型选择（`x-api-key` 或 `Authorization: Bearer`）；密钥为空时都不带（部分网关允许匿名读目录） |
| 超时 | 15 秒，避免上游挂起把设置页永久卡在加载态 |
| 响应解析 | 兼容顶层数组、`data[]`、`models[]` 三种形态；取模型 id/名称，去重排序后返回，保证弹窗顺序稳定 |

> **提示**：拉取请求放在**宿主进程**执行，而不是界面层直接请求。打包后界面层的来源是本地文件协议，受浏览器来源策略限制，供应商是否放行统一；放在宿主侧不受该限制。

### 失败语义

| 情况 | 表现 |
| --- | --- |
| 未填请求地址 | 直接报「未配置地址，无法拉取模型目录」 |
| 401 / 403 | 透出 HTTP 状态码 + 响应片段，不换候选地址 |
| 404（第一条候选） | 自动换第二条候选；两条都 404 才报错 |
| 超时 / 网络错误 | 抛出中止原因，弹窗显示在错误槽 |
| 目录为空 | 「该供应商返回的模型目录为空」 |
| 目录全部已添加 | 「目录里的模型都已添加，无需重复添加」，确认按钮禁用 |

## 验收场景

1. 全新安装（未解锁）：设置导航无「模型设置」；「企业服务端」可见。
2. 在外观页版本号连点 7 下：出现解锁提示，「模型设置」出现在导航里；重启后仍解锁。
3. 在侧栏底部版本号连点 7 下同理；但「外观点 4 下 + 侧栏点 3 下」**不解锁**。
4. 已解锁时再连点 7 下：反锁并提示；此时若正停在「模型设置」页 → 自动回到「常规」。
5. 连点间隔超过 1.5 秒重新计数；连点途中没有任何进度提示。
6. 登录企业服务端且目录同步成功：聊天模型选择器只列企业模型；本地 provider 模型不出现。
7. 同一状态下解锁开发者模式：本地 provider 模型重新出现在选择器里。
8. 退出企业登录：选择器恢复列出本地 provider 模型。
9. 反锁后本地 provider 配置仍在磁盘上（只是界面不再显示）。
10. 对自建网关点「一键拉取模型」：弹窗列出目录且顺序稳定；全选未添加项 → 添加后与逐个「添加模型」写入同一份配置。
11. 再次打开弹窗：刚添加的行标「已存在」并被排除在勾选之外。
12. 用错误密钥触发 401：弹窗显示可读错误，不弹第二个候选地址的 404 干扰信息。
13. 断网或上游超时 15 秒：按钮回到可点状态，弹窗给出错误而不是永久加载。
14. 连续快速点击「一键拉取模型」只发出一次拉取。

## 与上游 ZCode 的差异

| 项 | 上游 ZCode | 本说明书 / 本仓 |
| --- | --- | --- |
| 模型来源 | 官方套餐 / 官方端点 | 内网自建服务端与模型网关，**企业目录即白名单** |
| 本地模型配置 | 普通设置项，随时可改 | **默认隐藏**，连点版本号 7 下解锁；解锁即旁路治理 |
| 一键拉取模型目录 | — | 从供应商 `/models` 一次拉取、多选批量添加，只读拉取 + 复用既有写入路径 |
| 审计口径 | 套餐侧计量 | 企业模型鉴权走网关，审计与用量在网关侧成立；旁路调用不经网关 |

**本仓为什么需要它**：内网要保证「用户只能用企业认可的模型」，但调试和离线场景又确实需要本地 provider。把本地配置藏到一个需要显式动作才能进入的状态里，既保住了白名单的默认效力，也留了一条**可解释、可追溯**的旁路（解锁是显式行为，旁路调用不带网关令牌、在网关侧天然留痕）。

> **待核实**：本页描述的界面文案与入口位置以 `docs/已完成/已完成-model-governance-and-dev-mode.md` 为准；「帮助菜单版本号入口」在该文档的验收场景中被提及，但同一文档也说明帮助菜单项因交互限制不可用，具体以实际界面为准。
