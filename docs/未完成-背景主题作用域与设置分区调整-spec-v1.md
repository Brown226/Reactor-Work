# 背景主题作用域收窄 + 设置页分区顺序 + 侧栏远程入口隐藏

## 背景

大王对照 NewMax 1.1.20 的个性化主题后提出三点：

1. **背景主题的作用区不对**。NewMax 的背景只铺在中间的主内容区
   （`[data-workspace-primary-content]`），侧栏和右侧面板保持各自原底色；
   Reactor 现在是整窗铺底（`[data-desktop-window-frame]::before`），
   并且把 `--color-background` 整体改成半透明（`[data-app-background-surface]`
   挂在 workspace shell 根上），连侧栏一起透了出来。
2. **设置页分区顺序要调换**：背景主题放到代码设置前面。
3. 侧边栏「项目」区块的加号菜单里，仍有一个未隐藏的「远程连接」入口
   （`ChatEmptyState` 空态菜单里的那个上一轮已隐藏）。

## 产品规则

### 1. 背景主题只作用于主内容区

- 唯一作用域是右侧主工作区容器（`#content`，标记 `data-app-background-primary`）。
- 侧栏、右侧 side pane、设置页、弹窗保持各自不透明底色，**不参与背景**。
- 主内容区内的各个 `bg-background` 表面通过 `--color-background` 的半透明混色
  透出背景；该变量只在主内容区子树内被改写。
- 背景层沿用现有的 `::before`（当前图）/`::after`（交叉淡入旧图）双图层机制，
  宿主从窗口根换成主内容区容器；`blurPx`、`scrimPercent`、`motion` 语义不变。
- 宿主需要 `overflow: hidden`：背景层有 `transform: scale(1.06)` 防模糊露边，
  不裁剪会画到侧栏上去。

### 2. 设置页分区顺序

外观设置页的区块顺序改为：字体 → **背景主题（内嵌主题色）** → **代码设置** → 预览 → **应用信息（最末）**。
（此前是 字体 → 代码设置 → 背景主题 → 主题色 → 应用信息 → 预览。）

**主题色并入背景主题**：两者都只影响界面观感、同一屏调参，原本分成两个一级区反而割裂。
合并后顺序为：预置卡片 → 上传图片 → 动态壁纸 / 模糊 / 覆盖色 → **强调色**。
- 合并是**视觉分区**上的收口，状态仍分别由 `backgroundTheme` 与 `accentColor` 两个切片持有，
  不合并 store、不改持久化键。
- `AccentColorSection` 保留为独立组件（可独立测试与复用），只是不再由设置页直接渲染，
  改由 `BackgroundThemeSection` 在结尾嵌入。

**应用信息放到最末**：版本/构建时间属于"看一眼就走"的信息，排在所有可调项之后。


### 3. 侧栏远程入口隐藏

`WorkspaceSidebar` 的项目区块加号菜单里，「远程连接」项不再渲染。
与 `ChatEmptyState` 上一轮的处理保持一致：只收窄渲染条件，
**不动** `useRemoteConnectionEntryVisibility`（它还控制已有远程工作区的恢复），
**不动** `SSHDialog` 本体和远程能力。

## 状态所有者

- 背景设置：`packages/ui/src/lib/backgroundTheme.ts`（单一事实源，未改）
- 背景应用：`applyBackgroundTheme()` 写到 documentElement 的属性与变量（未改）
- 作用域：纯 CSS 选择器 + 两个容器标记属性，无新增状态

## 验收场景

1. 开启任一背景预置后，**只有主内容区**出现背景；侧栏仍是纯色不透明。
2. 切换预置时主内容区仍有 240ms 交叉淡入。
3. 内置浏览器沉浸预览激活时，主内容区背景仍额外模糊一档。
4. 关闭背景后主内容区恢复纯色，侧栏视觉不变。
5. 设置 → 外观：背景主题区块在代码设置区块之前。
6. 侧栏项目区块加号菜单只剩「打开文件夹」。
7. 已有远程工作区 tab 的恢复与重连不受影响。

## 已知边界

- 右侧 side pane 打开时，主内容区与它之间有分隔边框；背景在两列中的左列内裁剪，
  不跨越到 side pane。
- Web 与手机远控复用同一份 CSS，作用域同步收窄。
