# 用户数据隔离：按企业用户分命名空间

> 适用范围：任何「会话/任务历史落盘路径」的改动之前，先读本文件。
> 相关实现：`packages/shared/src/userDataScope.ts`、`packages/services/src/userDataScope.ts`、
> `packages/services/src/paths.ts`、`apps/zcode-cli/packages/adapters/src/storage/session-store/paths.ts`、
> `packages/desktop/src/main/desktopDataScope.ts`、`packages/ui/src/hooks/useReactorServer.ts`。

## 1. 问题

同一台机器（同一个 OS 账户）上用不同企业账号登录，任务列表与会话历史完全相同：
换登录只换了凭据、企业 provider 与策略，本机数据一个字节都没换。

根因：本机数据全部按「机器 + 工作区」落盘，企业登录身份（`uid`）不参与任何存储键。
- 任务索引 `~/.reactor/v2/tasks-index.sqlite`，行键 `workspace_key`（`resolveWorkspaceKey`）；
- 会话语料 `~/.reactor/cli/db/db.sqlite`，表按 `workspace_id` 组织；
- 派生数据（legacy 快照、Git 检查点、memory）挂在同一份 `workspaceHash` 下；
- `uid` 只出现在 `reactorServerService` 的登录态里，下游只喂策略/用量/审计。

## 2. 决策

**会话/任务数据按企业用户分命名空间，配置与凭据保持全局。**

| 数据 | 位置 | 命名空间 |
| --- | --- | --- |
| tasks-index、legacy 会话快照、会话 workspace 目录 | `~/.reactor/users/{scope}/v2/...` | 按 scope |
| CLI 会话库（消息正文真正所在） | `~/.reactor/users/{scope}/cli/db/db.sqlite` | 按 scope |
| Git 检查点索引、memory、审查知识导入、审计 outbox | `~/.reactor/users/{scope}/...` | 按 scope |
| 凭据、provider/模型配置、UI 设置、设备标识、日志、策略缓存 | `~/.reactor/v2/...`（原路径不变） | 全局 |

凭据**不能**进命名空间：切 scope 要重启进程，若凭据也跟着搬，重启后读不到令牌，
「登录成功 → 重启 → 回到未登录」会变成死循环。因此凭据、provider 配置、策略缓存留在全局根。

**本地态零迁移**：未登录/本地模式的 scope 是 `local`，解析结果就是历史路径本身
（`~/.reactor/v2`、`~/.reactor/cli/db`）。老数据原样可见，不搬、不改、不删。

## 3. scope 的取值与通道

`scope = "local" | 企业 uid`（sanitize 后只保留 `[A-Za-z0-9._-]`，最多 64 字符，其余字符折叠成 `_`）。

| 角色 | 事实源 |
| --- | --- |
| Host 进程内路径 | `process.env.ZCODE_DATA_SCOPE`（fork 时注入，惰性读一次） |
| Agent/CLI 子进程 | 继承 Host 的同一变量（`sanitizeZCodeRuntimeEnv` 不剔除它） |
| Main 进程下一次 fork 的依据 | 磁盘 marker `~/.reactor/data-scope.json` |

**切换时序**（登录/登出是唯一的切换点）：

```
Renderer                Host(services)                    Main                     CLI
   |  login(账号密码)  -->|                                 |                      |
   |                      |-- 登录成功，令牌+user 落盘       |                      |
   |                      |-- 同步写 marker {scope: uid}     |                      |
   |  <-- status(loggedIn)|                                 |                      |
   |  executeDesktopCommand(RelaunchApp) ------------------> |                      |
   |                      |                                 |-- app.relaunch()     |
   |                      |                                 |   重启后 fork Host   |
   |                      |                                 |   读 marker=uid      |
   |                      |                                 |   env ZCODE_DATA_SCOPE=uid
   |                      |<-------------------------------- fork env ------------|
   |                      |-- 路径解析命中 users/{uid}       |                      |
   |                      |-- spawn agent 时 env 带 scope --> | -------------------> | db.sqlite 命中 users/{uid}
```

marker 写在**登录 RPC 返回之前**（同步、原子写 tmp + rename），因此 Renderer 收到成功响应时
磁盘上一定已经是新 scope，不存在「重启用了旧 marker」的竞态。

登出：`clearSession()` 之后写 `{scope: "local"}`，然后同样 `RelaunchApp`。

## 4. 边界

- 手机远控复用桌面 Host 的会话运行时，看到的就是桌面当前登录用户的数据——隔离落在桌面侧，
  远控侧不另建隔离，也不另起存储。
- 远程 workspace（SSH/WSL/Docker）的 agent 跑在远端机器上，env 由远端自己决定；
  本机命名空间只覆盖本机 Host 与本地 agent。
- Web 入口（`window.zcode` 缺席）不触发切换：远端没有本地数据根可切。
- 换机器 / 换 OS 账户 = 新的数据根，天然隔离，不在本方案范围。

## 5. 验收口径

1. 未登录启动：数据路径 = 历史路径（`~/.reactor/v2`、`~/.reactor/cli/db`），老任务原样可见。
2. 账号 A 登录 → 重启后 `~/.reactor/users/{uidA}/v2/tasks-index.sqlite` 新建且为空；
   新建任务只落在这里。
3. 退出登录 → 重启后回到 `local`，A 的任务不可见。
4. 账号 B 登录 → 重启后 `~/.reactor/users/{uidB}/...` 为空且与 A 互不可见。
5. 已登录（同一账号）重启：不切 scope，任务列表原样恢复。
6. 单元测试覆盖 scope sanitize、marker 解析/写入、paths 与 CLI db 的命名空间解析。

### 实际验收结果（2026-10-08，dev 桌面真机）

| 口径 | 结果 | 证据 |
| --- | --- | --- |
| 1 本地态零迁移 | 通过 | marker=`local` 启动，UI 仍显示原有 9 个任务（`请执行这条命令…`、`请求一句话自我介绍` 等） |
| 2 A 登录即新命名空间 | 通过 | marker=`tiankd` 后启动：UI 显示「暂无任务」；`~/.reactor/users/tiankd/{v2,cli/db}` 新建 |
| 3/4 B 与 A 互不可见 | 通过 | marker=`admin` 启动：admin 命名空间为空，看不到 tiankd 的「隔离验证：请用一句话自我介绍」 |
| 2 写入只落本命名空间 | 通过 | tiankd scope 下新建任务后：`users/tiankd/v2/tasks-index.sqlite` tasks=1、`users/tiankd/cli/db/db.sqlite` 会话=1；本地库 tasks=9、会话=11 均未增长 |
| 5 同账号重启不切 scope | 通过 | marker 持久化，重启后仍在该用户命名空间内 |

静态门禁：root `pnpm typecheck` 0；`pnpm lint` 仅余 1 个既有错误（`portal/manual/build.mjs` max-lines，
属用户自己的 docs→portal 迁移文件）；`pnpm architecture:check --changed` 0；
services 78/78、ui 86/86、adapters 4/4；CLI `turbo run typecheck` 30/30。

**遗留口径（需用户拍板）**：老数据留在 `local`，不在首登时自动搬运。单用户机器上表现为
「登录企业账号后看不到登录前的历史任务」，需要时再做一次性迁移。
