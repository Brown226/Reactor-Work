# 产品文档入口（服务端可配置地址）

帮助菜单与 quickpick 的「产品文档」入口原先硬编码官方站 `https://zcode.z.ai/docs`。
本改动把地址改为**服务端下发**：未配置时不再跳官方站，只占位提示。

## 1. 产品规则

- 入口不变：帮助菜单「产品文档」、quickpick `产品文档` 命令，共用同一个收口模块
  `packages/ui/src/lib/productDocs.ts`（避免不同菜单跳到不一致的地址）。
- 地址优先级：服务端组织策略 `productDocsUrl`（已登录企业服务端）→ 无。
  **没有第二级兜底 URL**：未配置（未登录 / 无企业服务端 / 字段为空 / 值非法）时，
  点击入口弹提示「产品文档地址尚未在服务端配置」，不打开任何网页，更不打开官方站。
- 协议：复用既有 `GET /desktop/policy`（任意已登录用户可读）通道，**不新增端点**；
  写入口仍是 `PUT /desktop/policy`（仅平台管理员）。
- 服务端维护路径（两种，任选）：
  1. 环境变量 `REACTOR_PRODUCT_DOCS_URL`：库内没有该字段时的缺省值，改完重启服务端生效；
  2. 平台管理员 `PUT /desktop/policy` 写 `productDocsUrl`：库内值优先，立即生效。
- 端侧生效时机：跟随既有策略同步（登录成功 / 应用启动 / 打开设置页三个触发点），
  不为此新增轮询；未同步到就按未配置处理。

## 2. 单一事实源与状态所有者

| 关注点 | 位置 |
| --- | --- |
| 服务端字段 | `server/packages/shared/src/audit.ts` 的 `DesktopPolicy.productDocsUrl` |
| 服务端缺省 / 存储 | `server/packages/server/src/audit/repo.ts`（env 兜底 + DB 覆盖） |
| 服务端写入口 | `server/packages/server/src/audit/routes.ts` 的 `PUT /desktop/policy` 校验 |
| 端侧契约 | `packages/shared/src/desktopPolicy.ts` 的 `ReactorDesktopPolicy.productDocsUrl` + 归一化 |
| 端侧出口 | `packages/services/src/reactor-server/reactorPolicySync.ts` → `ReactorServerUsageOverview.productDocsUrl` |
| UI 消费 | `packages/ui/src/lib/productDocs.ts`（解析）+ 帮助菜单 / App / quickpick 三个调用点 |

**唯一所有者**是服务端 `desktop_policy`（env 只是它的缺省值）。端侧只读：策略经
PolicyCache 落盘、`normalizeReactorDesktopPolicy` 归一化后进入 `getUsageOverview()`，
UI 不另存一份、不写回。

归一化口径（端侧与服务端一致）：非字符串 / 空串 / 非 `http(s)` 协议 / 超过 500 字符
→ 视为未配置（`null`）。非法值不抛错、不打开，按未配置走提示分支。

## 3. 与既有边界的关系

- **策略语义**：`productDocsUrl` 只是随策略下发的配置位，不参与模式天花板、黑名单、
  出网白名单、额度任何强制判定（见 `docs/未完成-服务端接线-P4-用量上报与策略.md` §4.3）。
- **CLI**：CLI 读同一份策略缓存文件，但不消费该字段；归一化后多带一个键不影响其判定。
- **分享 / 只读视图**：与文档入口无关，不涉及。

## 4. 验收场景

1. 未登录或无企业服务端：点「产品文档」弹「尚未配置」提示，不打开任何网页。
2. 已登录且策略配置了合法 URL：点入口打开该 URL（帮助菜单与 quickpick 一致）。
3. 平台管理员 `PUT /desktop/policy` 改 URL 后，端侧下次策略同步即用新地址，无需改客户端。
4. 服务端值是非法值（`ftp://`、空串、超长）：端侧按未配置处理，不崩溃、不打开。
5. 服务端只设 env、没写库：下发值即 env 值；写库后库值覆盖 env。
6. en-US 下入口名与「尚未配置」提示随语言切换。
