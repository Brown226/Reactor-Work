# 已完成：标准自检点击问题不再退回提取正文，改开原件定位

- 状态：已完成（2026-10-13）
- 范围：`KnowledgeCheck`（action=standards）输出契约与 display 构造、前端审查结果面板的数据读取；不改定位算法、不改渲染结构

## 背景

大王反馈：审查模式里「标准自检」出结果后，点击问题条，原文展示成了提取出来的纯文本，
没有在原有格式（docx/pdf 版面）上定位展示。同轮的「自述型审查」却是正常的——会打开原件。

## 根因（代码级确认，全链路逐点核实）

`ReviewResultPanel.openItem`（`packages/ui/src/review/ReviewResultPanel.tsx:168`）本就写好了
两条分支：`hasOriginal` 为真且是 docx/pdf 时**只开原件**并按片段高亮；否则开「原件 + 提取正文」
两标签。问题在于标准自检这条链路上 `sourcePath` 从来没到过前端：

| 环节 | 状态 |
| --- | --- |
| skill 调用（`review-standard-check/SKILL.md:32`） | 传了 `sourcePath` |
| `KnowledgeCheckInputSchema` | 有 `sourcePath` 入参 |
| handler（`knowledge-check.ts:605`） | 只把它拼进 notice 文案，**输出不回显** |
| `KnowledgeCheckOutputSchema`（strict） | **无 `sourcePath` 字段** |
| `review-result-display.ts:98` `createKnowledgeCheckDisplay` | **写死 `sourcePath: null`** |
| 前端 `readKnowledgeResult` standards 分支 | 不读 `sourcePath`（也没得读） |
| `reviewResultGroups.ts:259` | `result.kind === "issues" ? result.sourcePath : null`，只对自述型生效 |

对照：`ReportReviewIssues` 的输出契约与 display 都带 `sourcePath`，所以只有它走得通原件分支。
`REVIEW_DISPLAY` 的 zod schema 里 `sourcePath` 本就是 nullable 字段，无需改契约形状。

另核实一处排除项：提取正文快照的后缀是 `.md` 不是 `.txt`
（`persistReviewText`，内容寻址落盘 `review-text/<sha1-16>.md`），预览区按 markdown 渲染。
用户观感上的「成了 txt」是纯文本丢失原版面，不是后缀问题。

## 修复口径

1. `KnowledgeCheckOutput` 接口与 zod schema 补 `sourcePath: string | null`（strict schema 必须同步，
   否则 handler 输出 safeParse 失败、display 直接变 undefined）。
2. handler 四个 return 点（notice 工厂 / standards / terminology / rules）补该字段；
   standards 用入参原值，其余为 null。
3. `createKnowledgeCheckDisplay` 改为透传 `bound(data.sourcePath, REVIEW_DISPLAY_MAX_PATH_CHARS)`，
   与 `createReportIssuesDisplay` 同口径。
4. 前端 `ReviewResultView` 加 `sourcePath` 并在 standards 分支读取；
   `collectReviewResults` 两种 kind 都取 `result.sourcePath`。
5. 不改 `openItem` 的既有分支逻辑——原件高亮能力早已具备，本次只补数据。

## 验收场景

- 标准自检结果里点击一条问题：docx/pdf 原件被打开并高亮命中片段；xlsx（canvas 无文本层）
  与扫描件 PDF 退回「原件 + 提取正文」两标签，高亮落在正文上。
- `sourcePath` 缺失（老载荷 / 未传）时行为与本修复前一致：只开提取正文，不报错。
- 自述型审查（issues）行为不变。

## 验证

- CLI：standards 输出带 `sourcePath`、display 透传、老载荷无该字段时不报错。
- 前端：standards 分支读到的 `sourcePath` 进入分组与 `ReviewResultItem`。
- 全量 `pnpm typecheck` + `pnpm lint` + `pnpm --dir apps/zcode-cli typecheck` / `lint`
  + `pnpm architecture:check --changed`。

## 未决 / 边界
