# 已完成：设置页插件图标绕过本地打包资产修复

- 状态：已完成（2026-10-12）
- 范围：`packages/ui/src/settings` 下技能列表与子智能体列表的插件图标解析；不动数据来源、不动渲染结构

## 背景

大王反馈「Reactor 使用指南」技能在设置页技能列表里仍显示 ZCode 旧图标（黑底白 Z）。
本地打包资产 `packages/ui/src/assets/plugin-icons/zcode-guide.png` 自 `e6fd30c`
（2026-09-29 内置内容与图标）起就是 Reactor 立方体，从未变更过。

## 根因（代码级确认）

插件图标统一经 `PluginIcon` → `resolvePluginIconSource(pluginId, listing.icon)`：

- 传入完整插件身份（`zcode-guide@zcode-plugins-official`）时命中
  `OFFICIAL_PLUGIN_ICON_BY_ID`，返回本地打包资产；
- 身份缺失时回退 `listing.icon`，即官方 CDN 地址
  `https://cdn-zcode.z.ai/zcode/official-plugin/assets/...`（本机实测可达，
  HTTP 200 / image/png），于是直接渲染 CDN 上的上游旧标。

`CommandsSection.tsx` 早已有注释固定这个口径（「id 必须带 marketplace 后缀……
否则会直接渲染 listing.icon 指向的旧 CDN 资产」），但两处同构调用漏传 id：

| 位置 | 问题 |
| --- | --- |
| `SkillsSection.tsx` `pluginIconItemById` | Map value 只构造 `{ name, listing }`，未带 `id` |
| `SkillsSection.tsx` `renderSkillRow` 回退分支 | 按裸名解析 listing，无 id |
| `SubagentsSection.tsx` `pluginIconItemById` | 同上，Map value 未带 `id` |
| `SubagentsSection.tsx` `renderAgentList` 回退分支 | 同上，无 id |

服务端 catalog（`skills` 表 28 条）`icon` 字段全部为空，市场页不参与本问题。

## 修复口径

1. 两处 `pluginIconItemById` 的 Map value 补 `id: plugin.id`，与 `McpSettingsSection`
   既有写法对齐（该处注释同样记录了本地命中优先）。
2. 回退分支新增 `resolveUniquePluginItemByName`（`pluginStoreListing.ts`）：与既有
   `resolveUniquePluginListingByName` 同一「同名唯一才解析」的安全约束，但返回完整
   条目以携带 id；同名多个时仍返回 undefined，不把第三方品牌误挂到别的 marketplace。
3. 不改 `resolvePluginIconSource` 的判定，不改任何数据来源与请求路径。

## 验证

- 新增 `packages/ui/test/pluginIconItem.test.ts`：id 命中本地资产、同名唯一返回完整条目、
  同名多个降级、CDN 回退仅发生在无 id 时。
- 定向 oxlint + 全量 `pnpm typecheck` + `pnpm lint` + `pnpm architecture:check --changed`。

## 未决 / 边界

- `HooksSection.tsx` 的 `resolveUniquePluginListingByName` 只用于显示名解析，不渲染图标，不动。
- 市场页（`MarketPage.tsx`）卡片图标走服务端 catalog `item.icon`（当前全空，回落首字母），
  与插件图标是两条链路，本次不并轨。
