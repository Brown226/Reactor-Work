# 输入区涉密与 AI 免责提示

覆盖新建任务首页与会话对话页底部固定展示的一行合规提示。改动只涉及 `packages/ui`
（文案 + 一个纯展示组件 + `SessionPane` 的一处挂点），不跨包、不动协议、不引入状态。

## 1. 产品规则

两个入口共用同一份文案、同一个组件，按所在页面各自定位：

| 入口 | 位置 | 对齐 |
| --- | --- | --- |
| 新建任务（草稿）首页 | 面板右下角（绝对定位，不随 composer 居中组排布） | 右对齐 |
| 会话对话页 | 输入卡与面板底边之间的空隙（dock 内、输入卡下方） | 居中 |

- 中文文案：`本工具严禁上传和处理涉密文件，AI生成内容仅供参考！`；en-US 有对应翻译，
  两处都走 i18n key `chat.securityDisclaimer`，不在组件里硬编码。
- 只展示、不交互：不占点击（草稿态那份带 `pointer-events-none`）、不带链接、
  不随会话状态变化；草稿态发出首条消息后，页面从"新建任务首页"切换为"会话对话页"，
  提示从面板右下角改挂到输入卡下方，不出现两份也不消失。
- 草稿态为什么不放 chips 下方：草稿首页的 composer 随空态整体居中、不吸底
  （`centerEmptyStateWithDock`），挂在 dock 里只会贴在推荐 chips 下方，
  与"界面右下角"的产品要求不符，因此改为绝对定位于面板右下角。
- 分享中（分享 dock 替换 composer 的非分享分支）不显示：提示属于 composer 所在分支，
  随 composer 一起被分享 dock 替换，不悬浮在分享界面之上。
- 只读视图（`readOnly`，如 subagent 观察视图）不显示 composer，也不显示本提示。
- 桌面、Web、手机远控复用同一组件与同一份文案；手机远控的草稿空态同样展示。

## 2. 单一事实源与状态所有者

| 关注点 | 位置 |
| --- | --- |
| 文案 | `packages/ui/src/i18n/locales/{zh-CN,en-US}.ts` 的 `chat.securityDisclaimer` |
| 展示组件 | `packages/ui/src/v4/ConversationSecurityDisclaimer.tsx`（纯展示：无 state、无服务依赖） |
| 渲染挂点 | `packages/ui/src/v4/SessionPane.tsx`，按 `isDraft` 二选一 |

**同一时刻只有一份实例**：`conversationBottomDockContent` 非分享分支里，`!isDraft` 时渲染在
composer 之后（会话态，输入卡下方）；`isDraft && !readOnly` 时渲染在 SessionPane 根节点，
绝对定位于面板右下角（草稿态）。两个分支互斥，不存在同屏两份，也不在 composer 组件内部另挂。

组件自身无状态、无副作用，不需要 owner；它只消费 i18n 文案。

## 3. 与既有边界的关系

- **背景主题**：提示位于 composer dock 内。背景开启时 dock 与输入卡仍保持不透明底板
  （见 `docs/已完成/已完成-appearance-background-theme.md`），提示文字可读性由该底板兜底；
  提示本身不参与背景图渲染，也没有单独的背景层。
- **自适应字号**：问候语标题的 20–30px 自适应逻辑只测量问候语容器（见
  `docs/已完成/已完成-interface-mode.md` 第 6 节），提示是独立段落，不参与测量。

## 4. 验收场景

1. 新建任务首页：面板右下角显示该行提示，右对齐、贴近窗口右下角，不与推荐 chips 相邻
   （composer 随空态居中，提示不随它排布）。
2. 会话对话页：输入卡与面板底边之间显示同一行提示，居中；发送消息、滚动历史、
   切换界面模式均不使其消失。
3. 中英文切换：文案随语言变化，en-US 不是中文直译占位。
4. 进入分享流程：提示随 composer 一起被分享 dock 替换，分享界面不出现该提示。
5. 三种界面模式（编程 / 办公 / 审查）下都显示；推荐 chips 因开关隐藏时（办公档关闭主动推荐）
   草稿态右下角的提示仍显示。
6. 开启背景主题后提示仍可读（面板底板兜底），背景开启隐藏的只有草稿空态水印，不含本提示。
7. 同一时刻只有一份提示：草稿态只在右下角，发出首条消息后只在输入卡下方，不同屏出现两份。
