# 聊天模型选择器精简（单来源平铺 + 移除「管理模型」入口）

> 面向聊天输入框右下角的模型选择器（`V4ComposerToolbar` → `ModelConfigSelect`）。
> 只收敛**展示层**，不改模型来源、治理或选择语义——那些仍归
> `已完成-model-governance-and-dev-mode.md` 管。

## 1. 产品规则

### 1.1 单来源平铺，多来源才分组

- 模型选择器共有多少「来源」由 `modelGroups.length` 决定（企业会话下通常只有一个
  source：`Reactor 企业服务端`，见 model-governance 的 provider 物化）。
- **仅一个来源时**：不再渲染该来源的分组标题行，直接把模型平铺为一级列表——
  省掉一层「点开标题 → 才看到模型」的多余层级。
- **两个及以上来源时**：保持原有分组层级（标题 + 二级子菜单），不改变语义。
- 判定收口在 `ModelConfigSelect` 的 `shouldShowModelProviderLevel`，判定尺度由
  `length > 0` 改为 `length > 1`。调用方显式传 `showProviderLevel` 时优先用调用方值。

### 1.2 聊天输入框移除「管理模型」入口

- 聊天输入框的模型选择器**不再**在菜单底部提供「管理模型」项（原 `showManageModelsAction`
  触发的 footer action，跳「设置·模型供应商」区）。
- 该入口的职责由**设置页**承担；聊天输入框只负责选择当前会话要用的模型。
- **仅限聊天输入框**：子智能体表单 / 自动化编辑 / 工作流 / 闲时任务这些调用点自带的
  「管理模型」入口是各自场景的显式入口，**本次不动**。

## 2. 状态所有者与接口

| 关注点 | 所有者 | 位置 |
| --- | --- | --- |
| 是否展示 provider 分组层 | 单一函数（默认判定） | `packages/ui/src/ModelConfigSelect.tsx` 的 `shouldShowModelProviderLevel` |
| 聊天选择器的分组构造 | 既有函数（不改） | `packages/ui/src/lib/modelSelectionGroups.ts` 的 `buildRegistryModelSelectGroups` |
| 触发器显示兜底文案 | 单一函数 | `packages/ui/src/chat-input-toolbar/modelSelection.ts` 的 `resolveModelSelectTriggerDisplay` |

- `showManageModelsAction` 由 `ModelConfigSelect` 的**必填** props 改为**可选**（缺省 `false`），
  使聊天输入框可以直接不传；其它调用点照常显式传值，行为不变。
- 删除孤儿函数 `shouldShowManageModelsAction`：它此前只有聊天输入框一个调用点，
  入口移除后无任何引用。
- `resolveModelSelectTriggerDisplay` 移除 `showManageModelsAction` / `manageModelsLabel`
  两个参数与「无分组但可管理模型时把占位文案写成『管理模型』」的分支；无分组时回落到
  默认「选择模型」占位。

## 3. 失败语义 / 边界

| 情况 | 行为 |
| --- | --- |
| 分组数为 0（同步中 / 目录为空） | 不渲染菜单（`modelMenuVisible` 只看 `modelGroups.length > 0`）；不再有「管理模型」兜底入口 |
| 分组数为 1 | 平铺该来源的模型，无标题行 |
| 分组数 ≥ 2 | 保留分组标题与二级子菜单 |
| 调用方显式传 `showProviderLevel={false}` | 沿用调用方值（如闲时任务），不受默认判定影响 |
| 子智能体 / 自动化调用点的「管理模型」 | 不受影响，仍按其自身 `onManageModels` 渲染 |

## 4. 验收场景

1. 企业会话（单一来源 `Reactor 企业服务端`）：打开模型选择器，**没有**「Reactor 企业服务端」
   标题行，模型直接平铺列出。
2. 同上场景：菜单底部**没有**「管理模型」项。
3. 开发者模式解锁后出现多个来源：分组标题与二级子菜单恢复显示。
4. 子智能体表单里的模型选择器：「管理模型」入口**仍在**（不在本次移除范围）。
5. 触发器在无分组时不显示「管理模型」占位，回落到「选择模型」。

## 5. 不做 / 边界

- 不改模型来源、治理白名单、选择与落库语义（仍在 model-governance 范畴）。
- 不新增聚合项、倍率徽标、分组小标题等新元素——本次只做收敛与简化。
- 不删除 `ModelConfigSelect` 对外的 `showManageModelsAction` / `manageModelsLabel` /
  `onManageModels` 能力，其它调用点仍在使用。
