# 移除首次引导页

覆盖首次引导页（职业问卷 + Claude 迁移向导）的整体删除。改相关代码前先读本文。
界面模式契约不受影响，仍见 [已完成-interface-mode.md](./已完成-interface-mode.md)。

## 1. 决策背景

- 引导页的职业答案在全仓无功能消费，`onboarding-record.json` 的上传链路（`uploadState`）
  从未接线，记录只是本地账本。
- 迁移向导的首启自动打开路径已空转（三方 agent 迁移移除后 discovery 为空，只标记
  handled 后静默关闭）；从 Claude 迁移的能力在设置页「迁移」分区独立存在，不随引导删除。

## 2. 移除范围

### 2.1 引导页（整块删除）

| 层 | 内容 |
| --- | --- |
| UI | `packages/ui/src/onboarding/` 目录下问卷 `OccupationOnboarding`、迁移向导 `OnboardingDialog` 及全部 parts / hooks / 可视化（`occupationOptions.ts` 的 `modeOptionIcons` 保留，供主面板模式胶囊使用） |
| UI hooks | `hooks/useSettingsSync.ts`（唯一消费者是迁移向导）、`hooks/useOnboardingRecordService.ts` 及其 `hooks/index.ts` 导出 |
| UI store | `newUserOnboardingOpen` / `setNewUserOnboardingOpen` / `onboardingDialogRequested` / `requestOnboardingDialog` / `clearOnboardingDialogRequest` |
| UI 入口 | `Root.tsx` 两处挂载、`SettingsPage.tsx` 侧栏「引导」按钮、`settingsPageHelpers.tsx` 的 `onOpenOnboardingDialog` 卡片、`userActionTraceCatalog.ts` 的 `open_onboarding` action |
| 快捷键 | `openOnboarding`（`shared/src/shortcutCommands.ts`）及 i18n 标签、`ShortcutSettingsSection` 的过滤项 |
| services | `packages/services/src/onboarding/` 整个目录、`index.ts` 导出、`node.ts` 注册、`accessor.ts` 字段 |
| client | `remoteServiceAccess.ts` 的 `onboardingRecordService` 代理 |
| shared | `onboardingRecord.ts` 及 `index.ts` 导出、`channels.ts` 的 `OnboardingRecord` channel、`validationAppSettings.ts` / `protocol.ts` 的 `onboardingOccupation` 字段 |
| settings-sync | 服务侧首启提示两方法 `getFirstRunPromptState` / `markFirstRunPromptHandled` 及 settings 字段 `settingsSyncFirstRunPromptHandled` |
| i18n | `onboarding.*`、`occupationOnboarding.*`、`settings.onboarding*` 全部 key |

### 2.2 保留清单（不随引导删除）

- 设置页「迁移」分区及 `useClaudeSessionMigration`、`ExternalAgentImportDialog`、
  Skills / MCP / Commands 分区：从 Claude 迁移的能力入口仍在设置页。
- `settingsSyncService`（services/settings-sync）的 discover / import 能力本身。
- 界面模式三档（编程 / 办公 / 审查）及其全部门控：状态、hook、主面板胶囊、快捷键均不变。
- `memoryEnabled`、`proactiveSuggestionsEnabled` 两个 settings 字段与设置页开关：
  只是不再由引导播种，改由用户自助设置；`proactiveSuggestionsEnabled` 仍按办公档门控。

## 3. 变更后的产品规则

1. 新装启动直接进入工作区，无任何全屏引导覆盖层或首启弹窗；设置页无「引导」入口。
2. 快捷键 `CmdOrCtrl+Shift+O` 无绑定，设置页快捷键列表不出现该条。
3. 界面模式维持原有三档语义与门控，首次进入落在 `coding` 默认档，由主面板胶囊切换。
4. `memoryEnabled` / `proactiveSuggestionsEnabled` 取 AppSettings 默认值，不再被引导预置。
5. 升级兼容：旧 settings 里的 `onboardingOccupation` / `settingsSyncFirstRunPromptHandled`
   字段停止读取，不做迁移、不清库（schema 收窄后旧值被忽略）。

## 4. 状态所有者

| 项 | 变更 |
| --- | --- |
| `interfaceMode` | **不变**（仍归 `store/index.ts`，localStorage + 广播，见 interface-mode 契约） |
| `onboarding-record.json` | 文件与服务整体移除；不再有"是否答过引导"判定，不再按 userId 回填偏好 |
| settings | 移除 `onboardingOccupation`、`settingsSyncFirstRunPromptHandled`；`memoryEnabled` / `proactiveSuggestionsEnabled` 保留 |

## 5. 验收场景

1. 新装启动直接进入工作区，无任何全屏引导覆盖层或首启弹窗；设置页无「引导」入口。
2. 快捷键 `CmdOrCtrl+Shift+O` 无绑定，设置页快捷键列表不出现该条。
3. 新建任务页仍显示问候语 + 编程/办公/审查三档胶囊；切档后问候语、推荐语料、
   终端/git 面板等门控行为与移除前一致。
4. 办公档下主动任务推荐开关可编辑并生效；关闭推荐后重启不复活。
5. 从旧版本升级：旧 settings 多余字段被忽略，不影响启动；localStorage 里的
   interfaceMode 值继续生效。
6. 从 Claude 迁移仍可在设置页「迁移」分区完成（会话 / skills / MCP / commands）。
7. 多窗口广播：theme / locale / 字号 / 界面模式 / 背景主题仍同步。
