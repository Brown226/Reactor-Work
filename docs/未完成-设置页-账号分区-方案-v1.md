# 设置页「账号」分区（原「企业服务端」）方案 v1

> **状态**：已实现并通过门禁（typecheck / architecture:check / 定向 lint / 13 项单测；实测见 7.1）
> **决策**：①额度区保留但修口径 ②只做客户端可拿到的数据 ③不接 `GET /me`
> **日期**：2026-10-09
> **背景**：用户反馈「企业服务端」这个分区名与信息结构不符合预期——它应该是**账号**：
> 展示当前用户的登录信息、所在组织的可用权限与可用额度。同时质疑「本月用量」是否与
> 「使用统计」重复。

## 1. 问题与决策

### 1.1 为什么改名

「企业服务端」描述的是**技术设施**（一台内网服务器），而用户在这个页面里想回答的是
「我是谁、我在哪个组织、我能做什么、我还有多少额度」。模型来源（企业 provider）只是
账号权益的一个投影，不该占据页面标题。

**决策**：分区 id 由 `reactorServer` 改为 `account`，标题「账号」，留在 `basics` 组。
位置在 2026-10-10 调整为**基础设置第一项**（原「紧跟模型设置」）：「账号」回答
「我是谁、组织给了我什么」，是进入设置页后最优先的身份入口；模型设置（开发者模式下
才可见）退到其后。调整只改 `settingsPageConfig.ts` 里 `BASE_SETTINGS_SECTIONS` 的顺序，
初始落点回退仍是「常规」（`consumeInitialSettingsSection("general")`），不受顺序影响。

id 改名必须带**迁移**：`zcode-settings-last-section` 里存着旧值 `reactorServer`，
不迁移会让老用户的上次停留分区被判非法并清空（`packages/ui/src/lib/settingsNavigation.ts`
的 `readLastSettingsSectionPreference`）。迁移写法与既有的 `plugins → plugin` 一致。

### 1.2 「本月用量」能不能删？——不能，但口径必须修

用户问「用量的那个下面使用统计不是有了吗」。核对结论：**使用统计里没有等价信息**。

| | 使用统计（`settings.usage`） | 账号页额度区 |
| --- | --- | --- |
| 数据源 | 本机 agent 库 `model_usage`（`apps/zcode-cli/packages/adapters/src/storage/session-store/repositories/usage.ts` 的 `queryAppUsage`） | 服务端 `GET /desktop/usage/summary`（`server/packages/server/src/audit/routes.ts`） |
| 范围 | 仅本机；`USAGE_RETENTION_DAYS = 30` 会 prune | 按调用者 scope 收敛，跨机器汇总 |
| 语义 | 我用掉了多少 token | 组织给我多少 / 我还能用多少 |
| 组织额度上限、告警线 | **没有** | 有 |

且使用统计的 App Usage 路径**不按 provider 过滤**（`AppUsageRequest` 只有
`{range, timeZone}`，CLI SQL 只 `group by model_id`），所以企业网关的调用被混算进去
但无法单独归属——「本月企业网关 token」的唯一权威来源就是服务端的
`GET /desktop/usage/summary`。

**决策**：保留额度区，但**修掉一个真实口径缺陷**：

`packages/services/src/reactor-server/reactorPolicySync.ts` 里
`percent = monthTokens / quotaLimit`，其中 `monthTokens` 是**调用者 scope 内**的合计
（普通用户只有自己，部门负责人是本部门子树），而 `quotaLimit` 是**全组织**上限
（服务端 `evaluateQuotaAlerts` 的 `monthTokens` 无 uid/dept 过滤）。两者相除对
非管理员是错的。

**修法（客户端，不改服务端契约）**：按角色区分口径，不合成单一百分比。

| 角色 | 用量标签 | 百分比 |
| --- | --- | --- |
| `platform_admin` | 组织本月已用 | 有（分子分母同口径） |
| `dept_head` | 本部门本月已用 | 不显示（分子是本部门、分母是全组织） |
| `user` | 我的本月已用 | 不显示 |

管理员仍看到进度条与告警线；非管理员看到「组织上限 X · 我的用量 Y」两个独立事实，
如实说明口径不同，不假装是一个百分比。

### 1.3 边界（本期不做）

用户决策：只做客户端能拿到的数据，不改服务端。因此以下**不做**：

- 不消费 `GET /me`（邮箱、`scope.kind` 走不到客户端；登录时落盘的 `reactor-server`
  资料仍是唯一来源）。
- 不新增「我的权限」接口（`/admin/permissions`、`/admin/roles` 被
  `requireAdmin` 拦死，仅 `platform_admin` 可用）。
- 不新增「我的额度」接口（服务端无 `/me/quota`、无 `/desktop/quota`）。
- **不显示组织名**：服务端**没有组织实体**（`server/packages/server/src` 内 grep
  `orgName|tenant` 零命中），顶层部门是唯一近似且 `/depts/tree` 对普通用户 403。

## 2. 信息架构

分区 `account`，页内两个分段（`SegmentedTabs`，全应用唯一分段控件原语）：

```
账号  ┌──────────────────────────────────────────────┐
      │ [ 账号 | 组织 ]                               │
      ├──────────────────────────────────────────────┤
      │ 身份卡：头像 · 姓名 · 角色徽标 · 账号 uid · 部门  │
      │ 连接卡：服务端地址 · 网关地址 · 登录状态          │
      │ 企业模型卡：模型 chip 云 + 刷新模型              │
      │ 退出登录                                       │
      └──────────────────────────────────────────────┘

组织  ┌──────────────────────────────────────────────┐
      │ 数据范围卡：角色 · 数据范围 · 部门路径           │
      │ 可用权限卡：按角色列出的能力清单                 │
      │ 可用能力卡：企业模型 N · 企业技能 N · 企业专家 N  │
      │ 可用额度卡：组织上限 · 用量 · 进度 · 告警线       │
      └──────────────────────────────────────────────┘
```

未登录时两个 tab 都不渲染，直接复用 `ReactorServerLoginForm variant="settings"`
（登录页与设置页共用同一份实现的既有约定不变）。

## 3. 状态所有者（不新增任何状态）

| 事实 | 所有者 | UI 只读来源 |
| --- | --- | --- |
| 登录态、令牌、企业 provider | host 侧 `IReactorServerService` | `useReactorServer()` |
| 额度上限、告警线、策略 | 服务端 `/desktop/policy` → host `ReactorPolicyCache` | `useReactorServer().overview` |
| 月度用量 | 服务端 `/desktop/usage/summary` | 同上（`monthTokens`） |
| 技能目录投影 | host 侧 `IServerSkillSyncService` 内存投影 | `useServerSkillMarket().catalog`（`getCatalog()`，不联网） |
| 专家目录投影 | host 侧 `IServerAgentSyncService` 内存投影 | `useServerAgentSync().getCatalog()` |
| 页内 tab 选择 | 组件局部 `useState` | 不持久化（与 usage 分区 tab 同口径） |

UI 不读凭据、不写 provider、不碰文件；能力清单的文案映射是**纯展示派生**。

## 4. 角色 → 数据范围 / 能力清单映射

服务端事实源：`server/packages/server/src/identity/permissions.ts` 的 `ROLE_META`
与 `permissionAllowed`，以及管理台 `server/packages/admin/src/pages/Roles.tsx` 的
`ROLE_POINTS`。客户端只做**同一套三角色的只读镜像**（角色集合固定、不开放自由角色），
不新增权限判定路径。

| 角色 | 数据范围 | 能力清单 |
| --- | --- | --- |
| `platform_admin` | 全公司 | 用户 / 组织 / 角色全量管理；模型、供应商、技能、Agent 等全部模块；AD 同步触发与权限点扫描；审计与报表全量 |
| `dept_head` | 本部门及以下 | 本部门成员管理（调岗 / 停用 / 资料）；本部门报表与用量；不可改角色、不可越部门边界 |
| `user` | 仅本人 | 个人中心（本人账号）；桌面端会话与工具能力（受组织策略约束）；个人用量查看；不可进入管理面 |
| 未知值 | 不显示 | 只显示原始 role 字符串，不猜 |

未知角色（服务端将来扩角色）**不猜语义**，如实显示原值。

## 5. 验收场景

1. 已登录 + `platform_admin`：账号页显示姓名、角色「平台管理员」、uid、部门；
   组织页数据范围显示「全公司」，额度区显示「组织本月已用 X / 上限 Y（Z%）」+ 进度条。
2. 已登录 + `user`：组织页数据范围「仅本人」，额度区显示「组织上限 Y · 我的本月已用 X」，
   **不出现百分比与进度条**；能力清单不含管理面条目。
3. 组织未设额度上限（`quotaLimit === null`）：额度区显示用量 + 「组织未设置额度上限」，
   不渲染进度条。
4. 服务端不可达（`monthTokens === null`）：额度区如实显示「暂不可用」，**不拿本地队列冒充**。
5. 未登录：整个分区只有登录表单，两个 tab 不出现。
6. 老用户从旧版本升级：上次停留在「企业服务端」的用户，升级后仍落在「账号」分区
   （`zcode-settings-last-section` 迁移）。
7. 窄屏（<1024px）：分段控件与卡片行不溢出，主操作（刷新模型 / 刷新用量 / 退出登录）仍在。

### 7.3 「企业技能」永远显示「—」（2026-10-09，同一轮反馈的第二条）

**现象**：账号分区「可用能力」卡里，企业模型有数、企业专家有数，唯独**企业技能恒为「—」**——用户看到的就是"组织什么都没给我"，而服务端实际下发了 **24 个**技能。

**根因**：计数读的是 `useServerSkillMarket` 的**内存投影**（`catalog`），而该投影只在「专家 · 技能」市场页调 `load()` 时才填充。账号页自己从不拉目录 ⇒ 只要没逛过市场页，投影就是空数组 ⇒ `length > 0` 判定不成立 ⇒ 显示「—」。桌面端有 host 同步兜底，web 端没有，所以 web 上必然复现；桌面端在市场页打开前同样是「—」。

**修法**：账号页在投影为空时**显式拉一次目录**（`load()`），失败仍回落「—」而不拿 0 冒充；桌面端首帧已被 host 同步填好，`catalog.length > 0` 时跳过，不会重复请求。同时保留原注释口径：装了几个是市场页的事，账号页回答"组织下发了多少"。

**验证**：web 客户端 + 企业账号登录，账号页「可用能力」现为 `4 企业模型 / 24 企业技能 / 2 企业专家`；`pnpm typecheck` 与改动文件定向 `oxlint` 均 0 error。
