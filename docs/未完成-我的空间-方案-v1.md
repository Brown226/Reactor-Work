# 我的空间（My Space）方案 v1

> 目标：把每用户 1GB 空间做成**可用功能**——容量可见、文件可管、产出自动归集、可交付分享。
> 决策（用户已拍板）：**分享要做**；**回收站占额度**；**产物自动归集**。
>
> **实施状态（2026-10-31）**：§2 磁盘布局、§3 容量口径、§4 全部 16 条接口、§5 安全不变量、
> §6 前端面板均已落地并实测。产物归集通过「登录后默认工作区 = 用户空间根」实现。
> 已知限制见 §8。

## 1. 与工作区的关系（先定这条，否则做出来是网盘翻版）

- **工作区**：agent 干活的地方。登录后默认工作区 = 该用户的空间根目录，因此
  agent 的产出天然落在用户空间里 —— 这就是「产物自动归集」的实现方式，
  不引入额外的搬运逻辑。
- **我的空间页**：面向人的资产管理视图（容量、批量操作、回收站、分享）。
- 两者指向同一份磁盘数据，不复制、不同步。

## 2. 磁盘布局

```
/data/users/<uid>/            ← 空间根（= 默认工作区）
├── <用户文件与目录>
└── .trash/                   ← 回收站（占额度）
    └── <id>/
        ├── meta.json         ← {name, deletedAt, fromPath, size}
        └── <payload>
```

`.trash` 对空间页可见（单独的回收站视图），对工作区文件树隐藏（点开也没有意义）。

## 3. 容量口径

- `usedBytes` = 空间根下全部文件（**含 .trash**）+ 目录项开销忽略。
- `quotaBytes` = `REACTOR_WEB_USER_QUOTA_BYTES`（默认 1GB）。
- 上传前校验：`usedBytes + 本次大小 > quotaBytes` → 413 且不落盘。
- `byCategory`：`document`(doc/docx/xls/xlsx/ppt/pptx/pdf/txt/md)、`image`、
  `drawing`(dwg/dxf)、`other`。

## 4. 接口契约（全部挂在 `@zcode/server`，前缀 `/api/space`）

身份：沿用 user-workspace 的约定 —— 优先用服务端登录记录的 uid；
显式 `?uid=` 仅阶段一调试用，注释标注可伪造。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/space/entries?path=<rel>` | 列目录：`{path, entries:[{name,kind,size,mtime}], usage}` |
| POST | `/api/space/mkdir` | body `{path}`，目录相对空间根 |
| POST | `/api/space/upload?path=<dirRel>` | 原始字节流，文件名走 `x-file-name`（encodeURIComponent） |
| GET | `/api/space/download?path=<rel>` | 文件流（`Content-Disposition: attachment`） |
| GET | `/api/space/preview?path=<rel>` | 文件流（inline，供预览器取） |
| POST | `/api/space/rename` | `{path, name}` |
| POST | `/api/space/move` | `{paths:[], toDir}` |
| POST | `/api/space/delete` | `{paths:[]}` → 进回收站 |
| GET | `/api/space/trash` | `{items:[{id,name,size,deletedAt,fromPath}]}` |
| POST | `/api/space/trash/restore` | `{ids:[]}` |
| POST | `/api/space/trash/purge` | `{ids:[]}`，空数组 = 清空 |
| GET | `/api/space/usage` | `{usedBytes,quotaBytes,trashBytes,byCategory}` |
| POST | `/api/space/share` | `{path, ttlHours, password?}` → `{token, expiresAt, url}` |
| GET | `/api/space/shares` | 我创建的分享 |
| POST | `/api/space/share/revoke` | `{token}` |
| GET | `/api/space/shared/:token?pwd=` | **公开**下载（不校验登录，校验 token/过期/口令） |
| POST | `/api/space/upload/begin` `chunk` `commit` `status` | 分片上传与断点续传（status 返回已收分片） |
| GET | `/api/space/search?q=` | 递归按文件名搜索，跳过内部目录，上限 500 |
| POST | `/api/space/archive` | `{paths:[]}` → zip 流（仅文件） |
| POST | `/api/space/upload/versioned` | 覆盖同名文件，旧内容归档到 `.versions` |
| GET | `/api/space/versions?path=` / POST `/versions/restore` | 历史版本列表与还原 |
| GET | `/api/space/dwg?path=` | DWG/DXF 解析：调用容器内 `dwg-sidecar graph`，返回 `{version, symbols[], segments[], ms}`；按「路径+mtime+size」缓存 |

### 4.1 DWG 在线预览的实现与边界

- 服务端 spawn `dwg-sidecar`（ACadSharp，linux-x64 已内置镜像），命令 `graph`，
  取 `INSERT` 符号插入点与 `LINE`/多段线线段坐标；前端投影成 SVG（Y 轴翻转、按图层分色）。
- **sidecar 的 graph 不输出圆、圆弧、椭圆与块属性**，因此预览图会缺这些图元；
  界面必须同时给出「图元统计 + 图层图例 + 下载原件」并明确提示，不能假装完整渲染。
- 单屏最多渲染 8000 条线段（2 万条 polyline 会卡主线程），超出提示下载原件。
- 解析失败按语义分码：501 未安装组件、422 图纸本身解析不了、504 超时，
  前端据此显示不同文案而不是统一的「失败」。


分享存储：`/data/shares.json`（进程内加锁写入；量为几十条规模足够，不引入数据库）。

## 5. 安全不变量

1. 所有 `path` 必须是相对路径，resolve 后必须仍在空间根内（含 .trash）。
2. 拒绝 `..`、绝对路径、盘符、控制字符；文件名校验不含 `/` `\`。
3. 符号链接不跟随（用 `lstat` 判断）。
4. 上传文件名做长度与字符清洗；同名自动加 ` (1)` 后缀，不覆盖。
5. 分享 token 32 字节随机；校验过期与口令（口令存 sha256）。
6. 公开下载只允许**文件**，不允许目录；不允许越出分享创建时的路径。

## 6. 前端结构（`packages/ui/src/my-space/`）

- `MySpacePanel.tsx`：整屏 Dialog，入口是**左侧栏「我的空间」按钮**（搜索项下方，
  `data-testid="my-space-trigger"`）。侧栏是桌面端共享组件，入口由 `onOpenMySpace`
  是否传入决定：只有 Web 宿主传入，桌面端不渲染，布局零变化。
  - 左：容量卡（进度条、分类占比、回收站占用）+ 视图切换（文件 / 回收站 / 分享）
  - 中：文件列表（名称/大小/时间，多选、拖拽上传、面包屑）
  - 右：预览（复用现有 previewPane）+ 详情 + 操作（下载/加入对话/分享）
- `spaceClient.ts`：所有 fetch 封装，统一错误文案
- 与 agent 联动：`onAddToChat(paths)` 回调，由宿主接到 composer 的附件注入

## 7. 验收场景

1. 首次登录：容量卡显示 0 / 1GB，可建目录、上传、下载、预览。
2. 上传超配额：413，界面显示「空间不足，请清理」，文件不落盘。
3. 删除 → 回收站可见、容量**不释放**；还原后回到原路径；彻底删除后容量释放。
4. 分享：创建得到链接，无痕窗口打开可下载；过期/错误口令拒绝。
5. 产物归集：在对话里让 agent 写文件，文件出现在空间页列表。
6. 路径穿越（`../`、绝对路径、符号链接）全部 400。

## 8. 已知限制（实施后记录）

- 无 Range/断点续传：下载与预览一次性返回完整流，大视频拖动不支持。
- 用量不做缓存：`entries`/`usage`/上传前配额都会递归扫描，文件多时 O(n)/请求（准确性优先）。
- 上传整包进内存：单文件接近 1GB 会有内存峰值，后续应改流式落盘。
- 过期分享不自动清理，只在列表里标 `expired`，需手动撤销。
- `?uid=` 显式参数仍是阶段一后门（与 `/ws` 无鉴权同级），接入会话身份后必须收紧。
- move/rename 的「查空位再 rename」存在理论竞态窗口；上传用 `wx` 原子创建，无覆盖风险。
- 分享下载放行服务端 lite token（否则无痕/匿名打不开），访问控制完全由 token+过期+口令承担。
