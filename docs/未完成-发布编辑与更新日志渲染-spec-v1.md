# 发布编辑 + 更新日志 Markdown 渲染 · spec v1

日期：2026-10-29
范围：管理台「系统 · 软件更新」、门户「更新日志」页、服务端下载页

## 一、问题

1. **发布后无法编辑。** 列表只有「上传产物 / 上线 / 下线 / 删除」，更新说明写错、发布名写错、灰度要调整时只能删除重建。
2. **更新说明的 Markdown 没有被渲染。** 管理台填写框标着「Markdown」，但展示端把原文当纯文本输出：
   - 门户 `changelog.html` 的 `renderNotes()` 只剥掉 `- ` / `* ` 前缀，`## 标题`、`**加粗**`、行内代码原样显示；
   - 服务端 `/download` 页 `renderCard()` 用 `textContent` 直接塞原文。

## 二、后端现状（已具备，不改）

`PATCH /admin/updates/releases/:id` 已存在，`patchRelease()` 只接受：

| 字段 | 可改 | 说明 |
| --- | --- | --- |
| `releaseName` | ✅ | null / 空串 = 清空 |
| `releaseNotesZh` | ✅ | |
| `releaseNotesEn` | ✅ | |
| `rolloutPercent` | ✅ | 1..100 |
| `published` | ✅ | 上线需已有产物（409） |
| `version` / `platform` / `channel` / 产物文件 | ❌ | **不在支持范围** |

`version` / `platform` / `channel` 是 manifest 的定位键，产物文件在上线后不可换（客户端按 sha512 校验，换文件会让已下载用户校验失败）。因此编辑弹窗**只开放后端确实支持的字段**，并在界面上明确写出哪些不可改，而不是给一个点了会 400 的输入框。

## 三、设计

### 3.1 编辑入口

- 列表行操作区新增「编辑」（`PencilSimple`），位置在「上传产物」之后、「上线/下线」之前。
- 点击打开「编辑发布」弹窗，与「新建发布」共用同一套视觉，但字段不同。

### 3.2 编辑弹窗字段

| 项 | 形态 | 说明 |
| --- | --- | --- |
| 版本号 / 平台 / 通道 | **只读文本** | 顶部一行摘要，并附一句「不可修改」的说明 |
| 产物 | 只读 | 有产物时显示文件名与大小；缺失时提示可走列表里的「上传产物」 |
| 发布名 | 可编辑 | 留空 = 清空（传 null） |
| 更新说明（中文） | 可编辑 | Textarea，Markdown |
| 更新说明（英文） | 可编辑 | Textarea，可空 |
| 灰度比例 | 可编辑 | 1..100 |

- 保存走 `updatesApi.patch(id, {...})`，成功后 `load()` 刷新列表并 toast。
- 失败时如实展示服务端错误，不做静默兜底。

### 3.3 Markdown 渲染范围

| 展示位 | 处理 |
| --- | --- |
| 门户 `portal/changelog.html` | 重写 `renderNotes()`：支持标题、有序/无序列表、粗体、斜体、行内代码、代码块、链接、引用、分割线 |
| 服务端 `/download` 页（`updates/download-page.ts`） | 同一套渲染，替换 `textContent` |
| 客户端更新提示（`UpdateReleaseNotesTooltip`） | **不改**：已由 `MessageResponse`（Streamdown）渲染，且渲染异常时会降级为纯文本 |

**安全约束**：渲染一律用 DOM API 构建节点（`createElement` + `textContent`），**不拼 HTML 字符串、不使用 `innerHTML`**，从结构上排除注入。链接只放行 `http/https`，其余协议降级为纯文本。

**依赖纪律**：门户与下载页都是零依赖内联脚本，不引入 marked / markdown-it；渲染器只覆盖发布说明实际会用的子集。

## 四、验收场景

1. 在列表点「编辑」→ 改中文说明与灰度 → 保存 → 列表灰度列更新；重新打开弹窗显示新值。
2. 编辑时清空发布名 → 保存 → 列表发布名列显示 `—`。
3. 编辑弹窗里版本号/平台/通道不可输入（DOM 上无对应 input）。
4. 门户「更新日志」页：`## 标题` 渲染为标题、`- 项` 渲染为列表项、`**粗体**` 渲染为粗体、`` `code` `` 渲染为行内代码；页面无原始 `##` / `**` 残留。
5. `/download` 页卡片中的更新说明同样渲染为富文本。
6. 含 `<script>` 或 `javascript:` 链接的说明不会被执行 / 不会生成可点击链接。
