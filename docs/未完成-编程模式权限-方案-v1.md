## 1. 背景与现状

桌面端有三档界面模式：`office`（办公）/ `coding`（编程）/ `review`（审查）。

现状（代码实况）：

| 项         | 位置                                                    | 说明                                  |
| ---------- | ------------------------------------------------------- | ------------------------------------- |
| 枚举       | `packages/ui/src/lib/interfaceMode.ts:1`                | `"office" \| "coding" \| "review"`    |
| 状态所有者 | `packages/ui/src/store/index.ts:109` 的 `interfaceMode` | **默认 `coding`**                     |
| 持久化     | `localStorage["zcode-interface-mode"]`                  | 全局 key，不分账号                    |
| 切换入口   | `packages/ui/src/v4/DraftInterfaceModeToggle.tsx`       | 硬编码三档，无过滤                    |
| 权限语义   | store 注释自述                                          | 「仅展示详情偏好，不改变 Agent 权限」 |
| 服务端参与 | 无                                                      | 服务端完全不知道该字段                |

**已有可复用的机制**（不造新轮子）：

1. 服务端**可见性引擎** `server/packages/server/src/common/scope.ts` —— `all/role/dept/user` 四级并集，`skills`/`agents` 已在用。
2. 服务端**策略下发通道** `GET /desktop/policy`（`server/packages/server/src/audit/routes.ts:263`）+ 客户端缓存/同步（`packages/services/src/reactor-server/reactorPolicyCache.ts`、`reactorPolicySync.ts`）。
3. 管理台**授权范围选择器** `server/packages/admin/src/components/ScopePicker.tsx`。

## 2. 产品规则（已与用户对齐）

1. **默认关闭（白名单）**：未配置受众时，编程模式**只对 `platform_admin` 开放**。
2. **仅隐藏入口 + 最小兜底**：未授权用户在切换器里看不到「编程」档；**若本地已存/默认为 `coding`，登录后自动落到 `office`**（否则白名单形同虚设——默认档就是 coding）。
3. **`platform_admin` 恒全档可用**：否则管理员一旦把受众配错就永久看不到编程模式，无法自救。

## 3. 状态所有者与数据流

```
管理台「界面模式权限」页（仅 platform_admin）
    │  PUT /admin/interface-mode-policy   { kind, roles, deptIds, uids }
    ▼
服务端表 interface_mode_policy（单行，编码编程模式受众）
    │  GET /desktop/policy  按 viewer 计算 allowedInterfaceModes
    ▼
DesktopPolicy.allowedInterfaceModes: string[]   （随既有策略一起下发）
    │  复用 reactorPolicyCache / reactorPolicySync（登录/启动/设置页三触发点）
    ▼
客户端 store.availableInterfaceModes
    ├─ DraftInterfaceModeToggle 过滤档位（只渲染已授权档）
    └─ 初始化/归一化兜底：当前档不在允许集合 → 回落到 office
```

**唯一所有者**：

- 服务端：`interface_mode_policy` 表由「界面模式权限」页独占写入（走 `PUT /admin/interface-mode-policy`）。
- 客户端：`allowedInterfaceModes` 的唯一写入者是策略缓存（`reactorPolicyCache`），UI 只读投影。

## 4. 接口契约

### 4.1 服务端新增表

```sql
CREATE TABLE IF NOT EXISTS interface_mode_policy (
  id INT PRIMARY KEY DEFAULT 1 CHECK (id = 1),
  feature TEXT NOT NULL,          -- 目前仅 'coding'（编程模式）
  scope_kind TEXT NOT NULL CHECK (scope_kind IN ('off','all','role','dept','user')),
  scope_roles TEXT[] NOT NULL DEFAULT '{}',
  scope_dept_ids INT[] NOT NULL DEFAULT '{}',
  scope_uids TEXT[] NOT NULL DEFAULT '{}',
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_by TEXT
);
```

复用 `common/scope.ts` 的 `parseScope` / `deptsExist`；可见性谓词复用 `visibilitySql`（`off` 等价于「谁都不可见」，由判定层短路，不入谓词）。

### 4.2 管理面（仅 platform_admin）

| 方法  | 路径                           | 说明                                   |
| ----- | ------------------------------ | -------------------------------------- |
| `GET` | `/admin/interface-mode-policy` | 读取当前受众（含 `kind` 与三列）       |
| `PUT` | `/admin/interface-mode-policy` | 写入受众（`off` = 关闭，仅管理员可用） |

### 4.3 下发面（任意登录用户）

`GET /desktop/policy` 的响应体 `DesktopPolicy` 新增字段：

```ts
allowedInterfaceModes: string[];   // 形如 ["office","review"]；缺省不含 "coding"
```

该字段**按 viewer 计算**（其余字段仍组织级）：

| viewer                            | `allowedInterfaceModes`                  |
| --------------------------------- | ---------------------------------------- |
| `platform_admin`                  | `["office","coding","review"]`（恒全档） |
| 命中 `scope` 的部门/角色/账号用户 | 含 `"coding"`                            |
| 未命中 / `kind='off'` / 未配置    | `["office","review"]`（**不含 coding**） |

### 4.4 客户端契约

`packages/shared/src/desktopPolicy.ts` 的 `ReactorDesktopPolicy` 新增 `allowedInterfaceModes`：

- `DEFAULT_REACTOR_DESKTOP_POLICY.allowedInterfaceModes = ["office","review"]`（**默认关闭**，与产品规则 1 一致）。
- `normalizeReactorDesktopPolicy` 归一化：只保留 `office/coding/review` 交集。
- 纯判定函数 `isInterfaceModeAllowed(mode, policy)`。

> ⚠ 两个 workspace 不共享运行时，服务端 `server/packages/shared/src/audit.ts` 与客户端 `packages/shared/src/desktopPolicy.ts` 需**同步改**（同 `normalizeProductDocsUrl` 的既有约定）。

## 5. 验收场景

1. **未配置受众**：非管理员登录 → 切换器只有「办公/审查」；本地若存着 `coding` → 自动落 `office`。
2. **配置 `dept` 受众**：授权部门成员登录 → 三档齐全，可正常切到编程模式；其他部门成员 → 只有办公/审查。
3. **配置 `user` 受众**：仅名单内账号见到编程模式。
4. **配置为 `off`**：除管理员外全部隐藏编程模式。
5. **管理员**：无论怎么配，自己始终三档齐全。
6. **未登录 / 拉取失败**：沿用「缺字段按默认合并」，即不含 `coding`；**有缓存则用上一份**（不因一次网络抖动把已授权用户锁出去）。

## 6. 不做（本轮边界）

- **不在 Agent 运行时层拦截**：本次为「隐藏入口 + 客户端兜底」，未授权用户即使通过 devtools 改 localStorage 强制切到 coding，其会话也不会被服务端拒绝执行——因为编程模式仅是展示偏好，不改变 Agent 权限。若要真正强制，需另立「会话类型准入」方案。
- **不改 `DesktopPolicy` 其余字段的组织级语义**（审批模式/黑名单/配额仍全组织单值）。
