## 1. 洞①：管理操作审计中间件（服务端）

### 1.1 形态决策

**复用 `audit_event` + Hono 中间件统一兜底**，不建第二张表：

- 中间件只记「通用骨架」：方法 + 路由模式 + 实际路径 + 结果状态。**不读 body**（请求体是流，中间件读走会破坏下游 handler；且 body 里可能有密钥/口令，读了就有泄漏面）。改前/改后快照这类富信息继续由既有手写埋点提供。
- 既有 7 处手写埋点**保留**，通过标记去重：`markAdminAudited(c)` 在手写 `audit()` 闭包第一行打标，中间件在 `next()` 之后看到标记就跳过，**一个请求只落一条**。标记用模块级 `WeakSet<Context>`（Hono 每请求一个 Context 实例，贯穿整条中间件/处理器链），不改各路由文件本地的 `Ctx` 类型，避免 6 个文件的类型扩散。

### 1.2 挂载位置与顺序

`identity/routes.ts` 的 `createIdentityApp` 内，紧跟 authed 组 Bearer 中间件之后：

```
authed.use("*", bearer…)        // 现有
authed.use("*", adminAuditMiddleware(db))   // 新增：claims 已就绪
…authed 自有路由…
app.route("/", authed)           // 复制到根（含中间件）
```

`identity/server.ts` 在 `createIdentityApp` 之后逐个 `app.route("/", createXxxRoutes(db))` 挂管理面——Hono 按注册顺序组合，Bearer 中间件先跑、管理面路由后跑，审计中间件插在 Bearer 之后即天然覆盖全部后挂路由（与 Bearer 覆盖管理面的既有机制同一原理）。

### 1.3 记录范围（方法 + 路径白名单）

只记**写方法**（POST/PATCH/PUT/DELETE），路径按白名单包含、黑名单排除：

| 包含 | 说明 |
| --- | --- |
| `/admin/*` | skills、agents、updates、feedback 管理面、standards、terminology、rule-libraries、gateway（secrets/providers/models）、permissions、agent/bundle 管理 |
| `/users`、`/users/*`、`/depts`、`/depts/*` | 组织与用户管理（现状零留痕） |
| `/auth/sync` | LDAP 同步触发（管理操作） |
| `PUT /desktop/policy` | 组织策略下发（现状零留痕） |
| `/v1/kb/*` 写 | KB 数据集/文档/审核（`datasets/routes.ts` 头注早已挂待办；`/v1/kb/search` 是查询，按黑名单排除） |

| 排除 | 理由 |
| --- | --- |
| GET/HEAD/OPTIONS | 读操作不进兜底（敏感读如 `secrets.list` 由手写埋点自己记） |
| `/me/*` | 终端用户个人动作（收藏/安装/启用），量大且非管理操作 |
| `/desktop/audit/batch` | 审计上报自身的入口，记了就是自刷噪音 |
| `/auth/logout`、`/auth/gateway-token` | 登录生命周期，非管理操作 |
| `/v1/kb/search` | POST 形态的查询 |

### 1.4 落库形状

- `action='admin_action'`（复用 `recordAdminAction`，写失败仅告警不阻断请求——沿用其内建 catch）。
- `op = "{METHOD} {routePath}"`（如 `POST /admin/skills`；`routePath` 是路由模式，id 不进 op 防高基数）。
- `target = 实际 path`（截 128，含 `/skills/42` 这类对象 id）。
- `outcome`：`status < 400 → ok`；`401/403 → denied`；其余 `error`；`errorCode = String(status)`（非 ok 时）。
- `summary`/`details` 不填（无 body）。

### 2.3 映射与过滤（纯函数 `buildBehaviorAuditEvent`）

| 输入事实 | 输出 | 条件 |
| --- | --- | --- |
| `permission.lifecycle` phase=resolved | `approval`，`approvalDecision`: allow/modify→`allow`、deny→`deny`、escalate→`ask` | 必报（用户审批结论） |
| `permission.lifecycle` phase=denied + `ruleId` 以 `policy.` 开头 | `policy_block`，outcome=denied，`errorCode=ruleId` | 必报（命令黑名单等组织策略拦截） |
| `permission.lifecycle` phase=denied（其它 ruleId） | `approval`，`approvalDecision=forbidden`，outcome=denied | 规则拒绝，不是用户审批 |
| `permission.lifecycle` phase=requested | 不报 | 问了还没答，不是结论 |
| `tool.lifecycle` 终态 + `errorCode` 含 `egress_blocked` | `policy_block`，outcome=denied | 出网白名单拦截（`egress_blocked` / `webfetch_egress_blocked` 同时覆盖） |
| `tool.lifecycle` 终态 + `errorCode=permission_denied` | 不报 | 已由同 toolCallId 的 permission 事实记为 approval/policy_block，避免一案两行 |
| `tool.lifecycle` 终态 + `sideEffect===true` | `tool_call`，outcome: completed→`ok` / failed→`error` | 副作用工具全报；`sideEffect!==true`（只读或缺字段）不报 |
| 其它 phase（scheduled/started/progress） | 不报 | 只记终态 |

公共字段：`eventId = "{sessionId}:{fact.eventId}"`（与用量映射同构；超 128 字节退化为 `h:` + djb2 十六进制，保持幂等）；`ts = occurredAt`；`target = toolCallId`（截 128）；`toolName`（截 128）；`summary = toolName`（policy_block 为 ruleId，均截 200）；`durationMs` 透传。**红线**：`errorMessage`/`reason`/输入摘要一律不进任何字段——reason 是中文自由文本，可能回显命令内容。

### 2.4 上报门禁

- `model_call`：企业登录 ∩ 企业 provider（现状不动）。
- `tool_call`/`approval`/`policy_block`：**只判企业登录态**，不判 provider。理由：这三类是受管设备的行为/治理审计，不计费；组织策略（黑名单/白名单）在本地模型会话同样生效，只留痕企业 provider 会漏掉旁路会话里的拦截记录。
- 未登录不入队（与 model_call 同口径：事件丢弃而不是挂着等登录——登录后 CLI 已重启，旧会话事实不再产生）。
