# ZCode 3.19.1 内置办公工具资产迁移

> 范围：把 LibreOffice、Python、Poppler、qpdf、pandoc 按上游 3.19.1 的方式接入 Reactor。
>
> 依据：官方 3.19.1 Windows 安装包、官方 4.0.0 Windows/Linux 安装包与 AppImage/deb 的静态检查。上游源码未公开，本文描述的是**可观察行为与资产契约**，不是逐行源码复刻。

## 0. 结论先行

1. 上游 3.19.1 的“内置”**不是把工具放进安装包**，而是新增 `preinstalled-tools` 运行时子系统：按平台从 CDN 下载到用户数据目录，安装后把 `bin` 前置到 `PATH`。
2. 官方 3.19.1 Windows 安装包内**没有** `soffice`、`python.exe`、`pdftoppm.exe`；只有工具清单、`preinstalled-tools` 子进程和 156 KB 的 Windows 入口 shim。
3. 官方 3.19.1 清单包含 **5 个工具、15 个平台资源**：Python、qpdf、pandoc、Poppler、LibreOffice。3.19.1 与 4.0.0 的版本、大小、SHA-256 完全一致。
4. **只覆盖 macOS 与 Windows**：清单没有 `linux` 资源；4.0.0 Linux AppImage 不含这些二进制，`.deb` 也没有相关依赖。Linux 仍然依赖系统安装或 `PATH`。
5. 默认 `preinstalledToolsAutoInstall=true`，主进程以 `autoPrepare=true` 初始化，随后 `prepareAll()`。首次启动会后台准备全部工具：Windows 约 **737 MB 下载 / 2.22 GB 磁盘**，macOS ARM 约 **576 MB / 1.66 GB**。
6. 本仓库现在的 `office-engines` 是**构建期打包**的旧方案，且没有接入 `electron-builder`；要完全对齐上游，应替换为 `preinstalled-tools`，而不是在旧方案上补一个 Poppler。

## 1. 上游实测证据

### 1.1 Windows 安装包

以 `ZCode-3.19.1-win-x64.exe` 为例：

- 解包 `app-64.7z` 后，`resources/` 下没有 LibreOffice/Python/Poppler 二进制。
- 存在 `out/preinstalled-tools/process.js`，负责下载、校验、解压、安装、入口生成、升级与清理。
- 存在 `resources/preinstalled-entry-shim/zcode-preinstalled-entry-shim.exe`，156 KB，用于 Windows 入口转发。
- 主进程 `out/main/index.js` 内嵌工具清单（3.19.1 变量名为 `Vy`，4.0.0 为 `jy`）。
- `resources/tools/` 只有 `ripgrep`、`ugrep`、`cua-helper`、`runtime-host`，与办公工具无关。

### 1.2 Linux 制品

- 4.0.0 Linux AppImage 解包后没有 `soffice`、`pdftoppm`、`pdfinfo`、预装工具目录。
- 4.0.0 Linux `.deb` 的 `Depends` 不包含 LibreOffice、Poppler、Python。
- 3.19.1 清单本身也没有 `linux` 平台资源。

结论：上游的“内置”在 Linux 上**不成立**，至少不是随包或预装工具目录的形式。

### 1.3 清单一致性

3.19.1 与 4.0.0 的 15 条资源在版本、归档大小、安装大小、SHA-256、路径上一致；4.0.0 的 `process.js` 有修订，并新增 `binaryArch` 字段。本文以 3.19.1 清单为基线，4.0.0 的行为修正可作为后续同步项。

### 1.4 实测制品

- Windows 3.19.1：`https://cdn-zcode.z.ai/zcode/electron/releases/3.19.1/windows-x64/ZCode-3.19.1-win-x64.exe`
- Linux 4.0.0 AppImage：`https://cdn-zcode.z.ai/zcode/electron/releases/4.0.0/linux-x64/ZCode-4.0.0-linux-x64.AppImage`
- Linux 4.0.0 deb：`https://cdn-zcode.z.ai/zcode/electron/releases/4.0.0/linux-x64/ZCode-4.0.0-linux-x64.deb`
- 预装工具 CDN：`https://cdn-zcode.z.ai/zcode/preinstalled-tools`

## 2. 上游运行时结构

### 2.1 目录

```text
<dataRoot>/preinstalled-tools/<release>/
  bin/                         # 入口 shim，前置到 PATH
  tools/
    python/
      installation.json
      versions/<resourceId>/
      staging/
    qpdf/
    pandoc/
    poppler/
    libreoffice/
```

- `<release>` 为 `development` 或产品渠道标识，用于隔离 dev/stable/preview。
- `versions/` 保留已安装版本，安装新版本成功后再切换入口，因此“工具升级期间旧版本继续可用”。
- `staging/` 用于下载与解压的临时目录，成功后原子发布。
- `installation.json` 记录 `schemaVersion`、`toolId`、`resourceId`、`version`、`platform`、`arch`、`installationDir`、`installedSizeBytes`、`requiredFiles`、`entries`、`installedAt`。

### 2.2 CDN 与覆盖

- 默认 base URL：`https://cdn-zcode.z.ai/zcode/preinstalled-tools`
- 环境变量：`ZCODE_PREINSTALLED_TOOLS_CDN_BASE_URL`
- 支持逗号分隔的多个候选地址，按失败类型排序重试：`network=1`、`interrupted=2`、`checksum=3`。
- 归档 URL = `baseUrl + "/" + archive.path`。

### 2.3 环境契约

本地 Host 启动子进程时：

- `PATH` 前置 `<dataRoot>/preinstalled-tools/<release>/bin`。
- 设置 `ZCODE_PREINSTALLED_TOOLS_AVAILABLE=1`。
- 远程 Host 不注入以上 PATH 和标记，避免把本机工具路径带到远端。

因此：

- `qpdf`、`pandoc`、`pdftoppm`、`pdftotext`、`pdfimages`、`pdfinfo` 直接按同名命令解析。
- Python 使用 `zcode-python`，LibreOffice 使用 `zcode-soffice`，避免与系统同名命令冲突。
- Git Bash 中由于 `bin` 在 `PATH` 最前，内置工具优先于系统同名命令。

### 2.4 入口与 shim

| 工具 | 入口 | Windows 目标 | macOS 目标 |
|---|---|---|---|
| Python | `zcode-python` | `overlay/Scripts/python.exe` | `overlay/bin/python` |
| qpdf | `qpdf` | `Library/bin/qpdf.exe` | `bin/qpdf` |
| pandoc | `pandoc` | `pandoc.exe` | `bin/pandoc` |
| Poppler | `pdftoppm` / `pdftotext` / `pdfimages` / `pdfinfo` | `Library/bin/*.exe` | `bin/*` |
| LibreOffice | `zcode-soffice` | `LibreOffice/program/soffice.com` | `LibreOffice.app/Contents/MacOS/soffice` |

Windows 入口：

- 复制 `zcode-preinstalled-entry-shim.exe` 为 `bin/<name>.exe`。
- 写入 `bin/<name>.shim`：

```json
{
  "schemaVersion": 1,
  "target": "<installationDir>/<target>",
  "args": [],
  "env": [
    { "name": "PYTHONNOUSERSITE", "action": "set", "value": "1" },
    { "name": "PYTHONHOME", "action": "unset" }
  ]
}
```

- shim 读取同名 `.shim`，转发 stdio 与退出码。
- 旧 exe 不能直接覆盖时，先移动到 `bin/.retired/`，再写入新 shim，避免 Windows 文件锁失败。

macOS/Linux 入口：

```sh
#!/bin/sh
export PYTHONNOUSERSITE='1'
unset PYTHONHOME
exec '<installationDir>/<target>' "$@"
```

### 2.5 安装流水线

1. 解析平台资源，生成候选下载地址。
2. 校验磁盘空间：至少 `archive.sizeBytes + installedSizeBytes`。
3. 流式下载，`accept-encoding: identity`，边下边算 SHA-256。
4. 校验大小与 SHA-256；超限立即失败。
5. 在 `staging/` 解压 `tar.gz`，拒绝路径穿越、绝对路径、越界符号链接。
6. 执行 `rewrite`：
   - `text`：替换 Python `pyvenv.cfg` 中的安装前缀占位符。
   - `binary` / `binary-dir-prefix`：替换 macOS dylib 的构建前缀。
7. 校验 `requiredFiles`。
8. 执行 `runtimeChecks`，带超时与期望输出。
9. macOS 对重写后的 Mach-O 执行 `codesign`。
10. 写 `installation.json`，原子发布到 `versions/<resourceId>`。
11. 生成/更新入口 shim，清理已退役入口。
12. 旧版本在确认无进程占用后清理；失败不阻塞新版本使用。

### 2.6 运行时检查

| 工具 | 检查 |
|---|---|
| Python | 导入 `openpyxl, xlsxwriter, defusedxml, docx, lxml, reportlab, pypdf, pikepdf, pdfplumber, pypdfium2, pdf2image, PIL, pptx, matplotlib, pandas, numpy`，输出 `zcode-python-ok`；再执行 `python -m pip --version` |
| qpdf | `qpdf --version` 输出 `qpdf version 12.4.2` |
| pandoc | `pandoc --version` 输出对应版本 |
| Poppler | `pdftoppm -v`、`pdftotext -v` 输出 `26.10.0` |
| LibreOffice | `zcode-soffice -env:UserInstallation=${CHECK_TEMP_URL}/profile --headless --norestore --version` 输出 `LibreOffice 26.8.1` |

### 2.7 默认策略

- `preinstalledToolsAutoInstall` 默认 `true`。
- 主进程启动时 `autoPrepare=true`，初始化后调用 `prepareAll()`。
- `preinstalledToolsAgentDisabled` 可按工具 ID 禁止 Agent 使用。
- 状态通过 IPC 暴露：`GetPreinstalledToolsState`、`ExecutePreinstalledToolsCommand`。
- 仅主窗口可访问预装工具 IPC。

## 6. 迁移设计

### 6.1 原则

1. **替换旧管线**：以 `preinstalled-tools` 为主路径，不再把办公工具打进安装包。
2. **清单与上游一致**：工具 ID、版本、平台、SHA-256、入口名、参数、环境变量按第 3、2.4 节复刻。
3. **只改接入层**：文档插件、PDF 读取、技能仍按现有接口工作；通过 PATH 与 `zcode-*` 入口完成切换。
4. **保留系统回退**：预装工具不可用时，仍允许系统 `soffice`、`python3`、`pdftoppm`，但优先级低于预装工具。
5. **不复制上游代码**：按契约重新实现，避免把闭源实现直接搬进仓库。

### 6.2 目标架构

```text
Desktop Main
  ├─ PreinstalledToolsManager（新）
  │    ├─ catalog.ts            内嵌 5 工具清单
  │    ├─ installer.ts          下载/校验/解压/rewrite/检查/发布
  │    ├─ shims.ts              Windows .exe+.shim / Unix shell
  │    └─ paths.ts              dataRoot/release/versions
  ├─ preinstalledToolsProcess   子进程，隔离 IO 与解压
  └─ host env
       ├─ PATH = <binDir> + 原 PATH
       └─ ZCODE_PREINSTALLED_TOOLS_AVAILABLE=1

Agent / CLI
  ├─ zcode-python / zcode-soffice
  ├─ qpdf / pandoc / pdftoppm / pdftotext / pdfimages / pdfinfo
  └─ 系统命令 fallback
```

### 6.3 新增模块

建议放在 `packages/services/src/preinstalled-tools/`：

| 文件 | 职责 |
|---|---|
| `catalog.ts` | 内嵌第 3 节清单；按 `process.platform`/`arch` 过滤；生成下载 URL |
| `paths.ts` | 解析 `<dataRoot>/preinstalled-tools/<release>/bin|tools` |
| `installer.ts` | 磁盘检查、下载、SHA-256、解压、rewrite、requiredFiles、runtimeChecks、原子发布 |
| `shims.ts` | Windows `.shim` JSON 与 shim exe；Unix shell 入口 |
| `state.ts` | `installation.json`、当前版本、进行中操作、错误分类 |
| `manager.ts` | `prepare`、`prepareAll`、`remove`、`syncEntries`、`getState` |
| `types.ts` | 清单、入口、检查、状态的严格类型 |

桌面侧：

| 文件 | 职责 |
|---|---|
| `packages/desktop/src/main/preinstalledToolsProcess.ts` | fork 子进程、IPC、状态广播、退出清理 |
| `packages/desktop/src/main/desktopRuntimeEnv.ts` | 构造本地 Host 环境：PATH 前置、可用标记 |
| `packages/desktop/electron-builder.config.js` | 打包 `preinstalled-entry-shim/`；不再打包 `office-engines` |
| `packages/desktop/scripts/prepare-runtime-assets.mjs` | 准备 shim；移除 office-engines 挂接 |

服务侧：

| 文件 | 改动 |
|---|---|
| `runtimeCommandEnv.ts` | 本地 Host 的 `PATH` 前置 `preinstalledToolsBinDir`；远程不注入 |
| `officeEnginesEnv.ts` | 优先解析 `zcode-soffice` / `zcode-python`，再回退旧 `office-engines` 与系统路径 |
| `runtimeToolResolver.ts` | 增加预装工具根目录解析；保留 `resources/tools` 作为非办公工具回退 |

### 6.4 入口解析顺序

```text
LibreOffice:
  ZCODE_LIBREOFFICE_PATH
  > preinstalled-tools/bin/zcode-soffice
  > 旧 office-engines/soffice
  > PATH soffice / libreoffice

Python:
  ZCODE_PYTHON_PATH
  > preinstalled-tools/bin/zcode-python
  > 旧 office-engines/python
  > PATH python3 / python

Poppler:
  preinstalled-tools/bin/pdftoppm / pdftotext / pdfimages / pdfinfo
  > PATH 同名命令
```

技能侧需要同步：

- `env_check.sh`：先检查 `zcode-soffice`、`zcode-python`，再回退 `soffice`、`python3`。
- `recalc.py`、`verify.py`：调用 `zcode-soffice` 优先。
- 文档技能说明中不再要求用户预装 LibreOffice/Python/Poppler。

### 6.5 旧管线处置

1. `scripts/prepare-office-engines-assets.mjs` 与 `office-engines-assets.json` 标记为 legacy，默认不参与构建。
2. `electron-builder.config.js` 不新增 `office-engines` 的 `extraResources`。
3. 内网离线场景可保留旧管线作为回退包，但必须与预装工具二选一，避免两套版本同时写入 PATH。
4. 迁移完成后删除旧脚本与文档中“LibreOffice 不打包”“Poppler 不内置”的旧策略，避免后续 Agent 按旧决策实现。

### 6.6 Linux 决策

上游没有 Linux 预装资源。完全对齐上游时：

- Linux 不下载、不安装预装办公工具。
- 继续使用系统 LibreOffice/Python/Poppler，或由 Linux 包管理器提供。
- 不要为 Linux 复用 macOS/Windows 的办公工具 PATH 前缀；Linux 没有可命中的预装入口。

如果产品必须让 Linux 也开箱即用，需要单独 ADR 扩展清单（新增 linux 资源、构建、签名、镜像），这不属于“完全按照上游”的范围。

### 6.7 设置与 UI

建议保留上游两个设置：

- `preinstalledToolsAutoInstall`：默认 `true`；关闭后不自动准备，仍可按工具手动触发。
- `preinstalledToolsAgentDisabled`：按工具 ID 禁止 Agent 使用。

状态至少包含：

```ts
type PreinstalledToolState = {
  toolId: string;
  status: "not-installed" | "downloading" | "verifying" | "installing" | "checking" | "ready" | "failed";
  phase?: string;
  downloadedBytes?: number;
  installedVersion?: string;
  error?: { kind: "network" | "interrupted" | "checksum" | "disk-space" | "runtime"; message: string };
};
```

## 8. 验收矩阵

| 场景 | 预期 |
|---|---|
| Windows 干净机器首次启动 | 后台下载并安装；`zcode-python`、`zcode-soffice`、`pdftoppm` 可用 |
| macOS ARM 干净机器 | 同上，Mach-O 重写后可执行 |
| macOS Intel | 使用 x64 资源 |
| Windows ARM64 | Python/LibreOffice 使用 x64 资源可运行 |
| Linux | 不下载预装工具；系统命令可用；标记不设置 |
| 升级时旧版本被占用 | 新版本安装成功，入口切换；旧版本空闲后清理 |
| 下载中断 | 分类为 `interrupted`，可重试 |
| SHA-256 不匹配 | 分类为 `checksum`，不发布 |
| 磁盘不足 | 分类为 `disk-space`，不下载/不解压 |
| 路径穿越归档 | 拒绝解压 |
| Git Bash | `command -v` 命中预装 `bin` |
| Agent 禁用某工具 | 该工具不可被 Agent 调用，但状态可查看 |
| 远程 Host | 不注入本机预装 PATH |
| 关闭自动安装 | 启动不下载；手动安装仍可用 |
| 旧 office-engines 存在 | 预装入口优先；不出现双版本冲突 |

## 9. 风险与待确认

1. **体积与流量**：Windows 全量 737 MB 下载、2.22 GB 磁盘；需要镜像、按需安装或明确提示。
2. **CDN 可达性**：内网需配置 `ZCODE_PREINSTALLED_TOOLS_CDN_BASE_URL` 镜像，否则首次使用失败。
3. **许可证**：LibreOffice（MPL/LGPL）、Poppler（GPL）、qpdf（Apache-2.0）、pandoc（GPL）、Python 及依赖各自许可证；归档内已带 `LICENSES/`、`THIRD_PARTY_NOTICES.md`，产品需同步展示。
4. **Windows shim**：需要自行构建/签名 156 KB 级 shim；杀毒软件可能拦截未签名 exe。
5. **macOS 签名**：dylib 重写后需要 `codesign`，否则可能被 Gatekeeper 拦截。
6. **Linux 不对齐**：上游无 Linux 预装资源；如果产品要求 Linux 开箱即用，需要额外 ADR。
7. **3.19.1 与 4.0.0 差异**：清单一致，`process.js` 有修订；升级到 4.0.0 时应重新对比安装器逻辑。
8. **4.0.0 行为变化**：4.0.0 取消 Office 插件额外视觉验收；本迁移不包含该项，升级时需单独处理。
