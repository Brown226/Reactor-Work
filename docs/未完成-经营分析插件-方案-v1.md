# 经营分析插件 · 方案 v1

状态：待实施｜适用范围：内网/公网部署｜维护者：桌面工具组

## 1. 背景与目标

`accounting-and-reporting` 覆盖财务域（科目映射、底稿审计、台账对账、月结复核、
报表渲染）。**产品/经营侧的量化工作**——数据质量核查、KPI 框架设计、指标波动诊断、
看板搭建——没有对应技能，用户提出这类需求时只有通用 agent 行为。本方案从 mimocode
内置包 `data-analytics` 技能中拆出四个 workflow，成立独立内置插件 `analytics`，
与财务插件域边界清晰、无重复写入路径。

## 2. 目标形态

纯内容型插件（无 package.json、不进 pnpm workspace），对齐四件套/research fork 形态：

```
apps/zcode-cli/packages/analytics-plugin/
  .zcode-plugin/plugin.json        插件清单（version 0.1.0）
  LICENSE.txt                      来源与授权说明（书面许可）
  README.md                        插件说明
  skills/
    analyze-data-quality/          数据质量：口径/粒度/新鲜度/冲突核查
    design-kpis/                   KPI 框架：主指标/驱动指标/护栏/目标值
    metric-diagnostics/             指标诊断：波动归因、双向排除
    build-dashboard/               看板：BI 平台 / HTML / Streamlit 三种规格
```

## 3. 产品规则（边界）

| 规则 | 内容 |
| --- | --- |
| 与 accounting-and-reporting 的分工 | 财务核算与报告归 accounting；产品/经营分析（数据质量、KPI、指标诊断、看板）归 analytics。`audit-xls` 与 `analyze-data-quality` 都涉及"审计"但对象不同：前者审财务底稿，后者审数据资产 |
| 与四件套的分工 | 分析结论的**成品交付**（docx/xlsx/pptx/pdf 报告）归四件套创作层；analytics 只生产分析本身，图表规格内嵌于 build-dashboard |
| 上游裁剪口径 | 只取四个 workflow 的 SKILL.md 与 build-dashboard 的 specifications；**不取**上游其余 workflow（gather-business-context / build-report / visualize-data / product-business-analysis 等）及其 scripts（report-to-google-doc 等 17 个 py） |
| 裁剪后的引用处理 | 四个 SKILL.md 中对未入选兄弟技能的 `$name` 引用，以文件头 "Modified by ZCode:" 边界说明收口：上下文收集改为内联进行，成品产出指向四件套；不在正文逐条改写 |

## 4. 授权与许可登记

上游作者书面许可（2026-10-09，件由项目所有者持有）覆盖 mimocode 内置包全部内容，
本插件与 research 插件**共用同一条 copied-components 记录**（roots 扩展至
analytics-plugin/skills）；四个打了边界补丁的 SKILL.md 登记进 `modifiedFiles`
（Apache 4(b) 文件内修改声明，标记串 `Modified by ZCode:`）。上游 workflow 自带的
`agents/openai.yaml` 不随包复制：本仓技能加载器无 skill 级 agent 概念（四件套的
agent 在插件层），复制只会留下死文件。
