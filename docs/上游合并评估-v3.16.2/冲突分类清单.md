## 执行顺序建议

1. **先冻结 5 个品牌/数据落点改动**（A 类前 5 条），特别是 `settingService.ts` 的数据目录常量。
2. **处理 G 类 13 个**，保持删除并清理引用；同时处理 C1 机械项。
3. **处理 A 类 17 个**：取上游后逐条补回上表列出的本地行。
4. **按依赖方向重写 C3**：`shared` → `services` → `desktop/host` → `desktop/main` → `ui`。
5. **C2 按子域推进**：先 `app-shell`/侧栏（含 E 类迁移），再 settings，再 v4 对话，再桌面端，再 CLI。
6. **F 类插件双实现最后定**，需要产品决策。
7. **收尾**：`pnpm install` 重生成 lock → 重生成 third-party 清单 → `pnpm typecheck` + `pnpm lint` + `pnpm architecture:check --changed`。

## 风险提示

- **静默回退三类**：数据目录（`.zcode`）、品牌文案、i18n 键值。这三类不会报错，只会在运行期表现为「写错目录」或「界面变回 ZCode」。
- **198 处只是文本冲突**：上游删除模块后本地仍 import 的语义冲突不在此列，只能靠 `pnpm typecheck` 兜底。
- **F 类不做决策就合**：会出现同名插件双份技能，运行时行为不确定。
- **不建议为了跟进而上游侧栏迁移**：本地侧栏改动 +54/-67，上游是 2388 行重写，迁移成本远低于逐行适配。
