# 办公公式与字体管线 · 从 LeAgent 借入方案

状态：方案待评审｜适用范围：四件套创作层 + office-engines｜维护者：桌面工具组
设计来源：LeAgent `docgen/omml.py`、`docgen/fonts.py`、`docgen/mathtext.py`、
`utils/cjk_font_discovery.py`（Apache-2.0）。本方案只取「纯函数、可测、无服务依赖」
的文档引擎零件，不引入 LeAgent 的工具目录、docgen 渲染器与 Python Agent 运行时。

## 1. 背景与缺口

四件套（docx / pdf / pptx / xlsx）Phase 2 最小依赖已实测通过，但两条排版质量短板
在真稿上会直接丢分：

| 缺口 | 现状 | 后果 |
| --- | --- | --- |
| 公式 | docx 走 docx-js Math 或 matplotlib **渲 PNG 贴图**；pdf 线靠字符近似 | 公式不可编辑、缩放糊、与正文字体不一致 |
| CJK 字体 | 各 skill 各写一份按 OS 硬编码路径；`cover_render.py` 撞 CFF 直接跳过 | PDF 封面/正文在缺字重机器上掉字或换脸；TTC 子字体探测缺失 |

更严重的一条：`scripts/prepare-office-engines-assets.mjs` 的 `FONT_URLS` 目前下的是
**NotoSansCJKsc-*.otf（CFF/PostScript outlines）**。ReportLab `TTFont` 明确拒绝
CFF——`cover_render.py` 注释里已经踩过这个坑。也就是说 office-engines 的 `fonts/`
目录对 PDF 线**当前不可用**，只能靠系统字体碰运气。

LeAgent 的 `docgen` 把这两个问题都解过，且解法与四件套兼容：不推翻 skill 路线，
只补「公式插入」和「字体解析/注册」两个纯函数层。

## 2. 借入范围（明确二分）

### 2.1 借

| LeAgent 源 | 落点 | 为什么 |
| --- | --- | --- |
| `docgen/omml.py` | 共享 Python 模块 `omml.py` | LaTeX→OMML，产出 Word/PPT **原生可编辑公式**；未知结构降级返回 `None`，不抛 |
| `docgen/fonts.py`（FontManager / FONT_MANIFEST / register_pdf_fonts / office_east_asia_font） | 共享 Python 模块 `skill_fonts.py` | 解析顺序、TTC 子字体探测、ReportLab 注册、docx/pptx ascii+eastAsia 双名 |
| `utils/cjk_font_discovery.py` | 并入 `skill_fonts.py` | 系统 CJK 字体扫描，去掉 structlog/LeAgent 配置依赖 |
| 字体资产钉版策略（gstatic **TTF** + sha256） | 改写 `prepare-office-engines-assets.mjs` 的 `FONT_URLS` | 修 OTF/CFF 不可嵌；与 manifest hash 机制对齐 |

### 2.2 不借

| 源 | 原因 |
| --- | --- |
| `docgen/renderers/*`、`themes`、`gen/document_tool` | 与四件套 skill **双写路径**；创作仍归 skill |
| `docgen/mathtext.py` 全量 | 仅保留「OMML 失败时的 PNG 回退」接口约定，实现继续用现有 matplotlib 路径 |
| LeAgent 工具目录（web/data/oa/…） | 与本仓核心工具、技能重叠或产品域不同 |
| 自动下载到用户 home | 内网定稿：字体只走受管目录 / 系统字体，禁运行时联网 |

## 3. 产品规则与分层

沿用四件套三层能力（见 `内网办公四件套-fork-spec.md` §2）：

1. **创作层唯一 owner 仍是 skill**：公式以 LaTeX 为输入语法（模型友好），
   skill 决定插到哪一段；本借入只提供「LaTeX → OMML 元素 / XML」这一步。
2. **操作层不新增工具**：不做 `formula_*` MCP；公式插入发生在 docx/pptx skill
   脚本内，与 `docx_patch`（确定性小修）无交集。
3. **字体解析唯一 owner 为 `skill_fonts`**：skill 不再各自硬编码路径；env 契约
   仍是 `ZCODE_SKILL_ENGINE_ROOT` / `ZCODE_FONT_DIR`（见 fork-spec §7）。
4. **失败语义**：`latex_to_omml_*` 返回 `None` 时，调用方必须降级到现有 PNG
   路径或纯文本，并在 postcheck 记一条可读告警——不得静默丢公式。
5. **字体解析失败**：`FontManager.resolve()` 返回 `available() == false` +
   结构化 warning；ReportLab 线不得回退到 CFF 字体假装成功。

## 4. 接口契约

### 4.1 `omml.py`（纯函数）

```python
def latex_to_omml_xml(latex: str, *, display: bool = False) -> str | None:
    """LaTeX → OMML XML 字符串。失败/不支持返回 None，不抛。"""

def latex_to_omml_element(latex: str, *, display: bool = False):
    """LaTeX → lxml 元素（供 OOXML 注入）。失败返回 None。"""

def omml_pptx_alternate(latex: str, fallback_text: str, *, display: bool = False):
    """PPTX 的 mc:AlternateContent 包装（m:oMath + 可读回退文本）。失败返回 None。"""
```

- 管线：`LaTeX --latex2mathml--> MathML --本模块--> OMML`。
- 覆盖：分式、根式、上下标、n 元运算符（∑∏∫…）与极限、定界符、矩阵、重音、纯文本 run。
- 命名空间：`m` / `mc` / `a` / `a14`（与 LeAgent 一致，PowerPoint 兼容）。
- **依赖**：`latex2mathml`（纯 Python，新增）、`lxml`（已在 19 包闭包内）。

### 4.2 `skill_fonts.py`（进程内单例）

```python
class FontManager:
    def resolve(self, *, allow_download: bool = False, refresh: bool = False) -> ResolvedFonts: ...
    def register_pdf_fonts(self, *, allow_download: bool = False) -> dict: ...
    @staticmethod
    def office_east_asia_font() -> str: ...  # python-docx / python-pptx 用

def get_font_manager() -> FontManager: ...
```

解析顺序（`allow_download=False` 为内网默认，对应 LeAgent
`LEAGENT_FONT_AUTO_DOWNLOAD=0`）：

1. `ZCODE_SKILL_ENGINE_ROOT/fonts/` 受管目录（安装器/IT 预置）
2. `ZCODE_FONT_DIR` 显式指定
3. 系统 CJK 字体扫描（Windows Fonts、`/usr/share/fonts`、`~/Library/Fonts`）
4. 结构化 warning + `available() == false`（**不**回退 CFF、**不**静默 Helvetica）

| 输出 | 语义 |
| --- | --- |
| `ResolvedFonts.regular/bold` | 绝对路径；TrueType outlines（ReportLab 可嵌） |
| `register_pdf_faces` | ReportLab `TTFont` 注册表（含 TTC `subfontIndex`） |
| `office_east_asia_font()` | 供 docx/pptx 的 eastAsia 字体名（如 `SimHei` / `Noto Sans SC`） |

**CFF 黑名单**（照 LeAgent + 现有 `cover_render.py` 教训）：PingFang、Hiragino、
Noto CJK OTC/OTF、Source Han OTF 一律跳过，不得注册进 ReportLab。

### 4.3 env 契约（不变）

`ZCODE_SKILL_ENGINE_ROOT` / `ZCODE_FONT_DIR` 语义与 `officeEnginesEnv.ts` 已注入
链路一致；本借入只增加消费方（skill 脚本），不新增 env 名。

## 7. 验收场景

1. **OMML 主路径**：干净环境 + 内置 Python，对含分式/根式/上下标/求和的 LaTeX
   串调用 `latex_to_omml_xml`，得到非空 OMML；用 python-docx 写入 test.docx 后
   Word/WPS 打开，公式为**可编辑原生对象**，`postcheck` 无降级告警。
2. **OMML 降级路径**：输入 LeAgent 覆盖不到的结构（或直接断言 `latex2mathml`
   失败），返回 `None`，调用方产出 PNG/文本，`postcheck.math-omml` 报降级条数
   ≥ 1 且流程不崩。
3. **字体解析**：仅系统宋体/黑体的 Windows 上，`skill_fonts.resolve()` 命中
   TrueType；`register_pdf_fonts()` 后 reportlab 能 `TTFont` 注册成功。
   构造只有 PingFang/Noto-OTF 的环境：解析失败并给 warning，**不**注册 CFF。
4. **受管字体**：`ZCODE_FONT_DIR` 指向含 Noto Sans SC TTF 的目录时，优先于系统
   字体；`allow_download=False` 时全程无网络请求。
5. **资产脚本**：`prepare-office-engines-assets.mjs --stage fonts` 拉到 TTF，
   manifest 记录 sha256；故意换 OTF URL 时校验失败。
6. **回归**：`pnpm typecheck`、`pnpm lint`、`architecture:check --changed` 无新增
   违规；docx/pdf 两条线「造真文件 → 真脚本处理」冒烟仍通过。

## 9. 明确不做

- 不做公式相关 MCP 工具；不把 OMML 暴露给 review 一键修改（`docx_patch` 只改字）。
- 不借 LeAgent docgen 渲染器 / 主题系统；不引入 Jinja 模板引擎。
- 内网构建禁止字体自动下载；`FONT_URLS` 仅供 CI/发布机 `--stage fonts` 使用。
- 不处理 PPT 动画、Word 公式编号/交叉引用（超出 LeAgent 覆盖，另案）。
